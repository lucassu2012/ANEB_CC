## 🔴 读这份文档之前必须先读的三句

**这三句不是脚注，是这份数据的使用条件。**

### 一、**这条规则不会上线。本回放不改变任何现行判据。**

被回放的 (b) 规则（`lowConfidence = sampleCount < expected_n`）**已被 D-740 否决**，其逐字裁定是：

> 「`expected_n` **只作完备性信号、不替换门限**；`threshold_source` **不设**。」

D-751 再次确认（「显名排除 S1／C1／C2 ＋ **不设 `threshold_source`**」）。
⇒ **本文件是反事实回放**：它算的是「**若**采用那条已被否决的规则会怎样」，
**不是**任何已上线或拟上线行为的描述。

### 二、**两个比例不可作差。**

**重叠只有 90 / 1378 ＝ 6.5%。**
⇒ 「17.8% → 12.4%」**不是同一批样本少标了 5.4 个百分点**，
而是**两批几乎不相交的标**：旧规则打的 866 个标里 **776 个被摘掉**，同时新规则打上 **512 个完全不同的**。
**把它读成「水位下降」是错的。**

### 三、**它真正证明的是 D-740，而不是「该不该换规则」。**

被摘掉的 776 条**全部**是 `T1`／`U1`／`D1` 上 `sample_count ∈ {1, 2}` 的实例
——即 **profile 本来就只安排 1–2 个样本，却被固定门限 3 判为低置信**。
⇒ 本回放的产出是「**当前的低置信里有多少是结构造的**」，**不是**「换不换规则」。

## 5. 途中订正的一条推导规则（`a82e716`）

回放暴露 `EXPECTED_N_RULES["N1"/"N2"]` 写错：原 `sum:samples` 推出 **40**，
而语料实测 **388 个带 `kpi_quality` 的 scenario 里 384 个为 17、另 4 个为 0**。

**正确规则 ＝（首个 `clock_sync`）.samples − `ECHO_WARMUP` ＝ 20 − 3 ＝ 17**，依据：

- `ScenarioKpi.kt:123-124`：「N1/N2 输入＝**首次 clock_sync** 的 echo 样本；尾部 clock_sync 只用于 skew 插值，**不进 N 组**」
- `ScenarioRunner.kt:232/235/481`：`val warmup = i < ECHO_WARMUP`；仅非 warmup 进 `valid`；`const val ECHO_WARMUP = 3`

**错在两处、方向都是放大**：①求和全部 `clock_sync` 而消费方只吃首个；②没剔预热。

⚠ **`T2` 经同样方法独立确认，不是同族问题**：`KpiCalculator.kt:227/323` 明写
「T2 主口径…**剔除 `sameReadBatch` 伪 0 间隔**」，且 `:445` 的计数发生在剔除**之后**
⇒ 剔除量取决于**多少 token 落在同一次 socket read 里**，**数据相关、每次不同**
（实测短缺 s1 **0**／s2 −63／s3 −1，不成比例）。
**与 N1 的恒定 40→17 结构不同。** `sum:tokens-1` 是正确的**名义上界**，`actual ≤ expected` 是正确的关系（D-746）。

## 6. 为此新增的守卫（`a82e716`）

| 守卫 | 它防什么 |
|---|---|
| `test_echo_warmup_matches_the_kotlin_constant` | `ECHO_WARMUP` 是 Kotlin 常量的**第二份副本**；直接读 `ScenarioRunner.kt` 比对（承 D-264／D-508） |
| `test_derived_expected_n_matches_what_the_corpus_actually_recorded` | 🔴 **推导值 ≟ 语料实测值** |

**第二条为什么非有不可**：既有的 `check_expected_n` 核的是「profile **声明的** ≟ 我**推导的**」，
**两侧出自同一个假设** ⇒ 那条错规则**完美通过了它**。
新守卫的输入来自**语料**，**与推导规则不共享任何假设**。

判据分两档：**非 ITL 族要求「最大正实测 == 推导值」**（容忍单次丢样本，但**上界必须恰好够得着**）；
**ITL 族（T2/T3）只要求 `<=`**（合并信号，D-746）。
⚠ **`T1`/`U1`/`U2`/`D1` 四族推导与实测精确相等，本身就是这道检查的阳性对照**
——它证明该检查**有区分能力，不是恒真的**。

**突变审计 2/2 CAUGHT**（进程内突变，不落盘）：
把 `N1/N2` 改回旧写法 ⇒ 逐条报「最大实测 17 != 推导 40」，六个 `(profile, version)` 组合全中；
把 `ECHO_WARMUP` 改 0（只改一侧）⇒ 两条守卫**都**咬住。
