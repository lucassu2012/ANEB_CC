## 2. 大脑点名的四处重点

### ① 出口行 / `MIXED_EGRESS` 在「批内全同出口」形状下的呈现

**前提本身不成立，如实记录**：这 16 run 并非单一出口——pounce gen-2（9 场景）落在
`106.85.27.201`，15-run 批（135 场景）落在 `106.83.173.55`（与 D-437/D-439 已确认的
两个观测吻合）。`radio_rollup.py` **正确识别并标注** `MIXED_EGRESS:2` /
`MIXED_SERVING_CELL:2`，`campaign_report_radio.csv` 的 `egress_ips` 列逐出口逐场景数
精确印出 `106.83.173.55×135; 106.85.27.201×9`——出口呈现本身**没有问题**。

**真缺口**：`publish_check.py` 全文 grep `MIXED_EGRESS` **零命中**——它的"出口 IP"检查
（D-431）只核对"每格至少读出一个非空出口"，本轮该项 PASS（"1 个格均至少读出一个出口
IP"），**完全看不到同一格内混了两个出口**这个信号。只看发布门的读者会得到一个干净的
PASS，永远不知道这个格其实混了两个出口——这正是本项目反复咬中的"一个信号只活在一个
面"形状（同族：D-303/D-304/D-305）。**建议**（超出本次彩排授权，未动手）：publish_check
增加一项"MIXED_EGRESS/MIXED_SERVING_CELL 存在即 WARN，须由人解释"。

### ② radio 段在 100% 覆盖 + 全 NR 语料下的呈现

制式列正确印出单值 `NR`（此前语料均以 LTE 为主，这是第一次看到纯 NR 的呈现，无异常）；
`serving_cells` 列印出 `672-10119936-627264/672-10119936-633984`——**同 PCI（672）同
TAC（10119936）、仅 ARFCN 不同**，即同一物理小区站点的两个频点（载波聚合/频点切换），
**不是换了两个基站**。`MIXED_SERVING_CELL:2` 这个名字字面上容易被读成"漫游到了别的
基站"，本次实测数据恰好是"同站不同频"这一更温和的子情形——**命名本身没有错**（两个
serving_cell 元组确实不同），但读者需要下钻到 CSV 才能看出"差在哪一位"，值得在正文提醒。

pounce gen-2 那 9 场景里 7 个 stale（T35/D-445 已知机制），15-run 批 135 场景零 stale——
两者汇入同一个 (点位,运营商,忙闲) 格后，`publish_check` 只报"1/1 个格的无线证据 stale 或
过薄"这一句WARN，**读者无法从这一句判断是谁的问题**：批本身是干净的，脏的只是 pounce 那
9 个场景。细粒度需要下钻 `campaign_report_radio.csv` 的 `stale_samples=7` 列才能看到。

### ③ §10 新框架的三元组标注在报告面的落点

**确认为真缺口**：全仓 `scripts/` grep "三元组"/"triplet" **零命中**；`MIXED_EGRESS`
仅存在于 `radio_rollup.py` 一处，且它做的是"同格内出口是否一致"这一个具体判断，**不是**
"(RAT,出口,时段) 三元组是否完整"这个更高层的通用概念。`radio_rollup` 的表格行确实同时
印了 制式/出口/时段/点位/运营商 五个维度，**三元组的三个分量客观上都在同一行里出现**，
但没有任何代码把它们捆成"三元组"、也没有任何逐行检查"这一行的三元组是否与另一行可比"。
**§10 目前只活在 ADDENDUM 文档里，报告面没有接线**——这与大脑的预判一致。

### ④ 发布门在这个形状下的判定与理由

**结论：可发布**（FAIL 0 / WARN 6 / N/A 4）。六条 WARN 各自理由具体、可操作（层级对账/
同一客户端/无线上下文/标签来源/序位效应/预热效应），四条 N/A 如实标注"未核算不代表没
问题"，无一条含糊。**唯一的呈现缺口就是①**：出口 IP 那条 PASS 的判据边界过窄，让
MIXED_EGRESS 这个真实存在的情况在发布门这一面完全隐身。
