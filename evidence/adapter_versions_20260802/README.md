# 四个适配目标 App 的装机版本快照（2026-08-02 13:17 +08:00）

`spec/adapters/*.json` 四份规格的 `package_note` 都写着「**2026-07-18** P40 装机核实」。
本快照回答的唯一问题是：**那句话所核实的 App，和今天机上这个，是不是同一个。**

## 1. 结论：四份规格的验证记录今天都不可依赖，但理由分两种

| 规格 | package | versionName（versionCode） | firstInstallTime | lastUpdateTime | 相对 07-18 |
|---|---|---|---|---|---|
| deepseek | `com.deepseek.chat` | 2.2.2 (233) | 2026-07-19 15:02:06 | 2026-07-19 15:02:06 | **从未更新，但首装晚一天** |
| doubao | `com.larus.nova` | 14.4.0 (14040001) | 2026-07-17 23:49:18 | 2026-07-30 09:42:59 | 更新晚 12 天 |
| tongyi | `com.aliyun.tongyi` | 6.14.6.2959 (61406) | 2026-07-17 23:49:49 | 2026-07-29 05:09:24 | 更新晚 11 天 |
| kimi | `com.moonshot.kimichat` | 3.0.5 (361) | 2026-07-17 23:50:08 | 2026-08-01 22:57:13 | 更新晚 14 天 |

**三份是「装完之后又更新了」**（doubao / tongyi / kimi）——07-18 核对过的界面，之后被至少一次
版本更新覆盖过。

**deepseek 那格不一样，而且容易被读漏**：它 `firstInstallTime == lastUpdateTime`，
**一次都没更新过**——单看「更新过没有」这一列，它看起来是四个里唯一干净的。但它的
**首装时间是 07-19 15:02**，比规格自称的核实日**晚一天**：07-18 在机上被核对的那个
DeepSeek，**不是**现在这个（中间有过一次卸载重装或换包）。⇒ 它的验证记录同样不可依赖，
只是原因不是「更新」而是「不是同一次安装」。

> 这也是本次量化的价值所在：**动手前那句凭印象的「四个 App 都在规格之后更新过」是错的**，
> 四个里有一个从没更新过。若照那句话去写标注，deepseek 那份会挂一条它经不起查的理由，
> 而**一条经不起查的理由，比没有理由更糟**——下一个人核对时会先推翻它、再连带怀疑另外三条。

## 2. 据此**没有**做的事

- **没有回填 `validated_against_version`。** 本快照回答的是「现在装的是哪个版本」，
  **不是**「规格是对着哪个版本验的」。拿前者填后者会凭空造出一份从来不存在的验证记录，
  而那个字段的全部用途就是让人判断规格能不能信。缺席的语义是「不知道对哪个版本验过」，
  这是**合法且诚实**的状态（`AdapterSpec.AdapterDto` 该字段 `= null` 默认的 KDoc 已写明）。
- **没有新造 status 词**（大脑裁定）。四份规格的 `status` / 各节点规则的 `status` 一字未动；
  标注只落在 `package_note` 这段本就承载带日期溯源叙述的自由文本里——它紧挨着
  「2026-07-18 装机核实」那句话，读者看到原句就看到限定条件。放在别处等于削弱它。

## 3. 待办：再验证并入 E1 设备窗

四份规格的节点规则本来就全是 `PENDING-VALIDATION`（三个正则全 `null`，宿主走 generic 兜底，
规则不作打点闸门），所以**今天没有任何一条打点依赖于这些过期的界面特征**——
这也是本条只标注、不停用的原因。

再验证动作（`uiautomator dump` + `ADAPTER_EVT` 诊断回填 + 填 `validated_against_version`）
按裁定并入 **E1 真机设备窗**，与该窗的其它设备动作一次做完。

## 4. 复现

```
adb -s <serial> shell "dumpsys package <pkg> | grep -E 'versionName|versionCode|firstInstallTime|lastUpdateTime'"
```

原始输出见同目录 `dumpsys_package_versions.txt`（机器产出，未手抄）。
时间为**设备本地时**（+08:00）；`captured_at` 记在该文件首部。

**边界**：本快照只说 App 版本，**不说界面变没变**。版本号变了不必然意味着适配节点特征变了，
版本号没变也不保证界面一致（服务端下发的 UI 配置不会改 versionName）。
⇒ 它给的是「**该重新核一遍**」的理由，不是「**规格已失效**」的结论。
