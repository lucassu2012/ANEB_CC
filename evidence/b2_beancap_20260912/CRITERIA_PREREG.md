# 限速档判据（跑前写死，2026-09-12；此文件在任何一个字节流量之前落盘）

载荷 P = 4 MiB = 4194304 B/次；三阶段 × 3 次 = 9 次 ⇒ 上行合计 37.75 MB ≪ 200 MB 闸②。
量法：POST https://120.79.148.0:8443/api/v1/upload（既有端点，服务端读完 body 才回响应
⇒ 客户端以「收到响应头」为终点，测不到本机 socket buffer 假吞吐）。两个独立读数：
 - 客户端 goodput = P / (time_starttransfer - time_pretransfer)
 - 服务端 goodput = P / (recv_end_us - recv_start_us)   ← 服务端自报，不经我的时钟

## 判据① 闸（先跑；不达即停）
基线中位 goodput **< 3 Mbps ⇒ 判「不可判」**，不是通过也不是失败：帽为 1 Mbit/s，
基线没有 3 倍余量时「限住了」与「本来就这么慢」不可分。此时停下报大脑改帽（如 --up 25）。

## 判据② 主判据（整形中）
帽 = --up 125 (KB/s，包层) + --buffer 1000 (ms ⇒ 桶容量约 125000 B 突发)。
突发使整份平均被抬高：预测 measured = P*R/(P-B) = 4194304*125000/4069304 = **128.8 KB/s = 1.031 Mbps**。
**预登记带 = [0.85, 1.20] Mbps**（带不对称，两个方向各有理由）：
 - 下界 < 1.00：帽计的是**包字节**（IP/TCP/TLS 头约 3–5%）⇒ 应用层 goodput 稳态必**低于** 1.00 Mbps；
 - 上界 > 1.031：突发桶效应 + 「KB 取 1000 还是 1024」未定（若 1024 则线速 1.024 Mbps ⇒ 测得约 1.056）。
**分离判据**：整形中位必 < 基线中位的 1/2。否则无论落不落带都不算「限住了」。
落带即认；落不进按 D-843 **改 125 这个常数，不改档名**。

## 判据③ 对照（防「帽是全局的」这个替代解释）
整形上行**跑满期间**并行 ping 近对照 223.6.6.6（不在 --dst-ip 内）。
🔴 这条有区分力的原因写在前面：**若帽是全局的**，1000 ms 的桶在被打满时会把对照的 ICMP
排在桶后 ⇒ RTT 应**暴涨到接近 +1000 ms**。RTT 仍约 11 ms ⇒ 作用域确实只收在目标 IP。
（不用「同目标下行」当唯一对照：--filter out 只管出站，下行若掉是 **ACK 饿死**而非作用域外溢
——这条解释我**跑前**就写在这里，免得事后现编。下行仍测，作为方向性旁证。）

## 判据④ 驱动
三个时刻各查一次 sc query WinDivert：整形前应 1060、整形中应 STATE 4 RUNNING、收尾后回 1060。

## 阶段三（收尾后）存在的理由
它是**时间漂移**的对照：若阶段三回不到基线，阶段二的低速就不能归因于整形器。
