## 1. 🔴 对我原 H1–H4 的结构性批评（四个视角独立提出，内容一致）

1. **四条全是「划分」，没有一条是「干预」。** 收窄 filter 能说出第二次目击**是什么**
   （源地址、类型），**永远说不出为什么栈会走两遍**；更要紧的是
   **它分不开「一个包被呈现两次」与「两个不同的包」**——每条候选 filter 在这两个世界里
   读数完全相同。⇒ 必须各加一条：**改变机器的实验**、**确立包身份的实验**。
2. **「四条互斥」是假的，而这个假是承重的。** H1（NAT 前后）是「clone＋reinject」的**特例**：
   按源地址得到 20/20 会**同时**确认特例与通例，然后被读成「H1 已证，收工」。
3. **H2 早已死在我手上的数据里。** `B=0` 证明 NETWORK 层对转发包**什么都不呈现**；
   若真「每接口一次」，B 会是 20 或 40。**我把 B=0 只用来支撑「第 2 行」，从没反过来用在 H2 上。**
   且 H2 对 A 格根本不成立（A 只有一个接口承载该路由）。
4. **H4 不是假设**：无机制、无预测、如所写不可证伪；而它挂的测法测的是**方向**不是「不同因」。
   **它真正的判决性实验是「把移动热点关掉，再跑一次 A 格」**——A 掉到 20 则两格同因、H4 为假；
   仍是 40 则确为不同因。**一次运行、一个比特，而我的设计里没有它。**
5. **filter 是纯地址的** ⇒ 能抬高计数的是**任何进程发往 223.5.5.5 的任何包**。
   H3 问「是 request 还是 reply」**问窄了**：该问的是「**它到底是不是 ICMP**」。
6. **`2.00×` 这个精确比例是个没被用上的结构约束**：它一举排除所有**一次性**机制
   （ARP 预热、首包邻居排队、单次重试、路由抖动）——那些抬高 1，不是抬高 20。
   存活的只能是**每包一致**的机制，或**两个不同群体的 20+20 分解**。

## 3. 🔴 采纳的新工具：三个我原设计里完全没有的

1. **`impostor` 字段**：文档义为「由**其他驱动**注入、而非来自网络或 Windows TCP/IP 栈」的包，
   **两层都可编译**。⇒ **它就是为这个问题造的**：一次运行、零风险地回答
   「第二次目击是不是重注入」。
   🔴 **而且它比任何去碰 360 的测法都好**：它检测**任何**驱动的重注入而**不必关掉防护**——
   关掉安全软件是不可逆且扩大攻击面的动作，**在一个只读测试能回答同一问题时不该伸手去碰**。
   （本树历史上正是把异常错怪给 360 过。）
2. **`ifIdx` 字段**：视角侧**今日实测** `ifIdx == 9` 与 `ifIdx == 13` **在 `NETWORK_FORWARD` 都能编译**
   ⇒ **H2 在转发层可由 filter 单独判定**。我先前说「C 格无法用方向分解、只能靠 SrcAddr」
   ——**对 `outbound` 是对的，但我漏了 `ifIdx`**：又一次把「一个字段不行」写成「这一类都不行」。
3. **包身份**：循环**从不读 `pRecvLen`、从不碰包缓冲** ⇒ 「20 个包被看见 40 次」与
   「40 个不同的包」**是同一个读数**。⇒ **前置条件本身还有前置条件**：先确立身份
   （读长度 ＋ 取 IP ID／ICMP seq 的多重集），再谈分解。

## 4. 🔴 我自己仪器的三个缺陷（视角侧指出，我复核认账）

1. **循环一遇 `Recv` 失败即退出，且从不读 `GetLastError`** ⇒ **每个计数都是「首次出错前的成功数」**
   ⇒ **`B=0` 在「无匹配流量」与「第一次 Recv 就失败」之间是歧义的**。
   B=0 是本组最强的单一读数，而它的另一种成因我从未排除。
2. **`t.join(timeout=5)` 的返回值从不检查** ⇒ 读线程没退出的那一格照样印出一个正常模样的数字。
3. **`SNIFF` 是「复制并转发」而非「摘走并转发」** ⇒ **只因原包继续下行才存在的那个副本，
   在 divert 模式下可能根本不存在** ⇒ 本测量**会高估**；而 divert 模式引入的**自我再捕获**
   是 `SNIFF` 永远看不到的。**⇒ 这个前置条件按现设计无法完全回答它所前置的那个问题。**

## 5. 判据文档的一处订正

`c_forward_layer_probe_20260912/CRITERIA_PREREG.md` §0 写「WinDivert 2.x 的地址结构是 **64 字节**」
——**64 是尾部 union 的大小**，整个结构是 `Timestamp`(8) ＋ 打包的标志字 ＋ union。
128 字节缓冲两种算法下都安全，**故已测的一切不受影响**；但**一旦开始读那个结构（§3-3 要求读），
这个数就变成承重的，必须取自随驱动发布的头文件，不能取自文档转述。**

## 6. 被排除的（连排除理由一起记）

| 机制族 | 排除理由 |
|---|---|
| 一次性机制（ARP 预热／首包排队／单次重试／路由抖动） | `2.00×` 排除：它们抬高 1，不抬高 20 |
| H2「每接口一次」在 **NETWORK 层**的形态 | `B=0` 直接反证（若成立 B 应为 20 或 40） |
| H3「request＋reply 都匹配」 | 已由 EvalFilter 九条对照行实测为 `False`；且 ICMP 差错报文的外层目的地址也是主机地址 |
| 分片／重组 | 本轮载荷 60 B，无分片（且 `fragment` 字段可另验） |
| 去碰 360／关防护来试 | **不可逆且扩大攻击面**，而 `impostor` 只读即可回答同一问题 |

⚠ **本节不是「已排除全部其他机制」**：46 条里只有上表这几族被排除理由覆盖；
**其余大多未被判定**（见 §0 的面板失败）。**「完备」这个词本份不使用。**
