## 0. 三条贯穿全份的纪律（v1 已立，保留）

## 1. 仪器：五道门，任一不过整轮作废

### 1.1 收尾状态必须**具名**（裁定 blocking #1）

v1 写「`error != 0` 一律 `NOT_EXECUTED`」＋「S0 需 `error == 0`」，而 `rx()` 的
`while WinDivertRecv(...)` 只能因 FALSE 退出、正常收尾路径**就是**主线程 `Shutdown`
⇒ **干净退出时错误码必然非零**，两条**联立无解**；而 `error == 0` 唯一对应「线程仍阻塞」，
那个状态 v1 也判 `NOT_EXECUTED`。**⇒ v1 的第一格就会把整轮判作废。**

**规定**：

1. 主线程置 `shutting_down = True` **之后**再 `Shutdown`；
2. 读线程在 `Recv` 失败处**同线程立刻**取错误码（`use_last_error=True` ＋ `get_last_error()`），
   与 `shutting_down` 一起返回；
3. 每格印 `count=n shutting_down=X term_err=Y`；
4. **S0 期望**＝`count == 0` **且** `shutting_down == True` **且线程已退出**。
   🔴 **`term_err` 只印不判**（裁定 v2 第 9 条）：那三个码（232／995／6）是**推断值**，
   **本机本驱动上从未观测过**（v1 的 `rx()` 根本不取 `GetLastError`）。
   而 `shutting_down` 已经分开了「开跑就死」与「收尾时退出」
   ⇒ 白名单**几乎不增加检出力，却提供全额的整轮作废力**。
   集合外的码记 `OBSERVED_NEW_CODE`、**如实印、不作废**；**本轮据实测把集合钉死**。
   ⚠ 更要紧：`995`／`6` 恰恰是「读线程还阻塞时句柄被关」的产物
   ⇒ 把它们列进「干净收尾」会让下一条要防的竞态**被判成干净、计数照用**。
5. `is_alive()` 为真时**不要 Close 句柄**，记 `NOT_EXECUTED`，交 `finally` 的服务级清理。
   🔴 **与 §6-1 的联立**：`finally` 保 `Shutdown`，但 **`Close` 仅当 `is_alive()` 为假**才做
   ——v2 原写「`finally` 无条件 Shutdown+Close」与本条直接打架。

### 1.2 身份字段必须含 `ip.SrcAddr`（裁定 blocking #2）

v1 的 `(recvLen, ip.ID, icmp.seq)` **恰好回避了唯一能分开 NAT 前后的字段**：NAT 改的是**源地址**，
`recvLen`／`seq`／`ID` 都不变 ⇒ 三元组相同 ⇒ v1 判「同一批包被呈现两次」
——**而这与「同一点 clone＋reinject」对整形器的含义完全相反**（后者在 divert 模式下会再延迟一次
⇒ **延迟翻倍而看起来像整形生效了**，正是页首那个失败模式）。

**规定**：每包记录 **8 个字段**，全部 layout-free、只读包缓冲：

| 字段 | 偏移 |
|---|---|
| `ip.SrcAddr` | `12..15` |
| `ip.DstAddr` | `16..19` |
| `ip.ID` | `4..5` |
| `ip.TTL` | `8` |
| `icmp.Type` | `IHL+0` |
| `icmp.Id` | `IHL+4..5` |
| `icmp.Seq` | `IHL+6..7` |
| `recvLen` | `Recv` 的出参 |

**逐行进 stdout 逐字副本**（不只印汇总），供事后查询。

### 1.3 身份解析器的正对照，与 S0 同级（裁定 blocking #3）

**规定**：跑前把解析器喂三组**合成包**，定为与 S0 **同级**的门（不过即整轮作废），
做成 `scripts/tests/` 下的 pytest（零设备、零提权、不加载驱动）：

1. 20 个 `(ID, seq)` 互不相同 ⇒ 去重 20、重数全 1；

   第 2 组任何确定性解析器都给 1）。

合成包须**同时覆盖 Windows 侧 60 B 与 Android 侧 84 B 两种形态**，IHL **一律由首字节低四位算出**。

✅ **已实现并入库**：`scripts/diag/pkt_identity.py` ＋ `scripts/tests/test_pkt_identity.py`
（提交 `bed0d9cf`），**7 条全绿；突变审计 4/4**——W1 键含 `icmp_id`、W2 `seq` 读成 `id`、
W3 键含 `src` 各有两条用例转红，基线零红。⇒ **「8 字段偏移在两种包长上读对了」已是实测。**

🔴 **去重键在此定死**：`(recvLen, ip.ID, icmp.Seq)`；
`SrcAddr`／`DstAddr`／`TTL`／`Type`／`Id` **只记录、不入键**（裁定 v2 第 2 条）。

### 1.6 S3：两个 SNIFF 句柄能否看见同一个包（仪器自证，与 S0 同级）

🔴 **§4.3 的配对法建立在一个推断上**：「`SNIFF` 复制不摘走 ⇒ 同一个包可被每个匹配的句柄各看见
一次」。**这条本方从未测过**，它来自文档语义——正是今天反复栽的那一类。⇒ 它自带自证。

**S3-a**：同一格、同一批流量上并开**两个 filter 完全相同**的 SNIFF 句柄，打一轮。
**S3-b**：句柄 B 换成**恒真但写法不同**的 filter（`… and (icmp or not icmp)`），其余不变。

**判据**：两支均须 `|H_A − H_B| ≤ 2`。

⚠ **这个 `2` 的来历（自核，不是照搬）**：两个句柄的 open 与 shutdown **不在同一瞬间**
⇒ 开头与结尾各可能差一个包 ⇒ 上界 2。**它不是统计容差**，与 §4.1 那个 `±2`（丢包／收尾截断）
**来历不同，不得混用同一个理由**。

🔴 **不满足 ⇒ 配对法本身不成立 ⇒ §4.3 本轮 `VOID`**，**不是**「impostor 为 0」。
**这一条必须写死，否则自证失败会被读成阴性结果。**

⚠ **为什么 S3-b 不是冗余**：S3-a 只答「两个句柄能否同时看见同一个包」；
**S3-b 答的是「差异来自 filter 内容，还是来自开了两个句柄」**——没有它，
`impostor` 那一对读数不一致时，这两种成因**歧义**。

**编译性已自量（零提权、不加载驱动，带正负对照）**：

```
filter                                          NETWORK  FORWARD
true                                            True     True     <= 正对照
nonsense_field == 1                             False    False    <= 负对照(量法有区分力)
ip.DstAddr == 223.5.5.5 and icmp                True     True
  ... and impostor                              True     True
  ... and (icmp or not icmp)                    True     True     <= S3-b 可用
ip.DstAddr == 223.5.5.5 and ifIdx == 9 / == 13  True     True
  ... and outbound                              True     False    <= 层区分是真的
  ... and ip.SrcAddr == <设备 src>              True     True
```

⚠ **编译得过 ≠ 语义是我以为的那个**（D-879）——本表只排除「写法不合法」，不证语义。

## 2. 常量：现场推导 ＋ 双侧交叉核对

`ifIdx` 与 `ip.SrcAddr` 都不稳（热点腿是移动热点**动态创建**的虚拟卡，名中 `*10` 是重建计数器）。
🔴 **失败形态完全静默**：四格安静读成 0，而**仪器没坏、filter 语法对、收尾码正常**
——**§1 那几道门查的是「仪器有没有工作」，查不出「它匹配的对象不存在了」。**

**实测样本（19:0x，本条不是推演）**：PC 侧热点腿在、邻居 `192.168.137.129` `state=Permanent`，
而设备侧 `ip route get` 是 `via 10.10.0.1 src 10.10.7.37`（**不在热点上**）。
⚠ **ICS 把邻居项钉成 `Permanent`，它不会因为设备离开而消失** ⇒ **「邻居项仍在」单独用就是假绿。**

**规定（每个 FORWARD 格前后各做）**：

1. `ip.SrcAddr` **取自 P2 那一行的 `src` token**——同一次读数的两个用途，**不可能不一致**；
2. `ifIdx` 现场推导＝持有 `192.168.137.1` 的**唯一一块**接口；`count != 1` ⇒ `NOT_EXECUTED`；
3. 🔴 **双侧必须同意**：PC 侧邻居 IP **等于**设备侧 `src` 才放行；不等 ⇒ `NOT_EXECUTED`；
4. 建好的 `ifIdx == <n>` 送 `WinDivertHelperCompileFilter` **编译自证**后才用；
5. 多播排除按 **`224.0.0.0/4`** 判（实测漏过 `239.255.255.250`，**原写 `224.*` 是拿实例当了那一类**）；
6. 前后两次不一致 ⇒ 该格 `VOID`。

⚠ **`常量此刻正确 ≠ 常量在跑的时候正确`**——与「源码存在 ≠ 源码对应那个二进制」
是同一句话换到**时间轴**上。
（订正 v1 一处：安卓是**按网络持久随机化** MAC，同 SSID 每次同一个 ⇒ 地址比我先前暗示的**稳**；
本节仍成立，**触发概率低于我原先的说法**。）

## 4. 判定（**跑前写死**）

### 4.1 身份（区间，不用「约」；裁定 blocking #4）

| 读数 | 判定 |
|---|---|
| 去重 ∈ `[T−2, T]` **且**重数恰为 2 的占比 ≥ **90%** | **同一数据报被呈现两次** |
| 去重 ∈ `[2T−4, 2T]` **且**重数 1 的占比 ≥ **90%** | **是不同的包**，不是倍增 |
| 去重 **< T−2** | **丢包或收尾截断过多** ⇒ 该格 `NOT_EXECUTED` 重跑；**不得当成「倍增」** |
| 去重 **> 2T** | **有第三方群体混入** ⇒ 查 `A2 − A1` 与 S1/S2 底噪后重判 |
| 其余 | **不可单判**：按去重数与重数分布如实记，**不取整到近的一端** |

🔴 **第一行必须再按 `SrcAddr` 拆两支**（裁定 blocking #2）：

- 三元组相同 **且 `SrcAddr` 相同** ⇒ **同一点被呈现两次**；
- 三元组相同 **而 `SrcAddr` 不同** ⇒ **同一数据报在两点各一次**（H1 形态）。

**两者对整形器含义相反，不得并成一行。**

⚠ **构成与身份判定解耦**（裁定 blocking #4）：v1 写「构成仅在身份判为呈现两次时才有意义」
⇒ 一次平常读数落进中间行就让六格同时失去解释，**而 §5 那个要 PO 亲手关热点的干预已经花掉**。
**改为：构成一律按 §1.2 的每包日志事后查询**，不与身份判定共命运。

### 4.2 H2（守恒式为首要判别器；裁定 blocking #6）

**`F1 + F2 == C1`** 为首要判别器（精确、与 n 无关、误分即可检测）。
🔴 **跑前写死**：`F1 == C1` **且** `F2 == 0` ⇒ **不可判**
——在「H2 不成立」与「**转发层只暴露一个接口索引**」之间歧义，本轮答不了。
⚠ **转发层暴露的接口语义未经本方实测**：sweep 只证了 `ifIdx == …` **能编译**，
**编译得过 ≠ 该字段语义是我以为的那个**（D-879 的形状）；且 sweep 自己把热点腿标为 C 格的**入口**，
而 F2 要的是**到达接口**。
⚠ **不用合成 `WINDIVERT_ADDRESS` 喂 EvalFilter 去补这个对照**：那会把 §0-1 刚设计掉的
版本假设请回来，且 `False` 会在「字段语义」与「布局猜错」之间歧义。

### 4.3 impostor：**同格两句柄**配对（裁定 v2；`[0.4,0.6]` 已删）

⚠ **先说两个被删掉的数的来历**：
- v2 的 `≥5` 是**上一轮的活性门槛**（原文自述「给方向不给精度」）被搬来判**构成命题**；
- v2 的 `[0.4,0.6]` 是**我把上游的举例数字原样搬来、无推导**——**与上游把期望值写反是同一形状，
  只是方向相反：一边给出未经检验的数值，一边把它当推导用。** 两个数**全部删除**。

🔴 **两格配对不成立**：`A1′` 若是矩阵里独立一行 ⇒ 两次独立打流量、**两个窗口**，
**跨窗比值不是比值**——那正是 v1 被逮的那条换了个位置。
⇒ **改为同一格、同一批流量上并开两个句柄**（`A1`／`A1′` 与 `C1`／`C1′` 各是一格里的两个句柄）：
分子与分母**来自同一批包**，比值成立，**且不新增任何一格、不多花 PO 一秒**。

**前提**：§1.6 的 **S3 必须先过**。🔴 **S3 不过 ⇒ 本节整节 `VOID`**，

⇒ `MECHANISM_SWEEP.md` §6「不碰 360」那一行的**理由须改成只剩前半句**：

——**把一条正确的处置挂在未测语义上，等于给它配一个会塌的理由，而理由会被单独抄走。**

### 4.4 H4：那个干预的判词（v2 把格与判词一起删了，此处补回并给区间）

v1 写过「A 掉到约 20 ⇒ 同因；仍约 40 ⇒ 不同因」，裁定要的是**把「约」换成区间**，
而 v2 **把判词连同「约」一起删了** ⇒ **唯一需要 PO 亲手干预的那件事既没有格也没有判词**。补回：

| `A-off` 读数（`T` ＝该格实印发包数） | 判定 |
|---|---|
| 去重 ∈ `[T−2, T]` **且**重数 1 占比 ≥ 90% | **A 的 2× 由 ICS 造成** ⇒ 两格**同因**，H4 为假 |
| 去重 ∈ `[T−2, T]` **且**重数 2 占比 ≥ 90% | **A 的 2× 与热点无关** ⇒ 确为**不同因**，H4 成立 |
| 其余 | **不可单判**，按去重数与重数分布如实记 |

⚠ **判词读的是「重数」不是「总计数」**：v1 拿「40 掉到 20」当判据，
而**总计数同时受丢包与背景流量影响**；重数分布对这两者都更稳，
且它与 §4.1 用同一把尺（同一个 `summarize()` 的返回字段）。

## 5. 那个干预：判决性读数搬到 PC 侧（裁定 blocking #5）

🔴 **v1 把整个价值压在一个 PC 侧状态（热点已关）上，却拿设备侧检查反过来用当前提，两处都不成立**：
(a)「设备出口不在热点上」在设备连了**任何别的 WiFi** 时都满足——**今天真的发生过两次**——
而 PC 的热点可以完全照开；
(b) `judge_egress` 对读不到的输入一律 `ok=False`（空串／空白／`device offline`／有 via 无 dev
四种都被钉成拒绝，理由正是「缺席不等于通过」）⇒ **一旦取 `not ok` 作前提，这四种全部变成通过**。
⇒ 合起来：PO 以为关了而实际没关 ＋ 设备息屏或 adb 抖一下 ⇒ 反向前提「通过」
⇒ A 在热点仍开着时跑出约 40 ⇒ 逐字判「**确**为不同因」。
**那个比特是仪器没跑出来的，而输出里没有任何一行能暴露它。**

**规定**：

1. **判决性读数在 PC 侧，由脚本在该格前后各印一次**进逐字副本：热点腿是否存在／Down、
   `Get-NetIPAddress -IPAddress 192.168.137.1`、**ICS（SharedAccess）服务状态**，
   外加 PC 自身到目标的路由仍在上游腿；
2. **PC 侧读数不是「热点已关」⇒ 该格 `NOT_EXECUTED`**；
3. 设备侧只作**旁证**且必须**三态化**（`ON_HOTSPOT`／`OFF_HOTSPOT`／`UNREADABLE`），
   🔴 **`UNREADABLE` 在两个方向上都判 `NOT_EXECUTED`**，**绝不能满足前提**；
4. 该格必须排在**所有 FORWARD 格之后**；其后**任何 FORWARD 格都不得再跑**，
   除非按 §2 重读全部常量并重新通过其六条（**不依赖 P2**）。

## 6. 收尾与归属（裁定 blocking #8a/#8c）

1. **`cell()` 用 `try/finally` 保 `Shutdown`＋`Close`；`__main__` 整段
   `try/except BaseException/finally`（含 Ctrl+C），`finally` 无条件调 `teardown()`。**
   本轮 12 格、其中 8 格打 adb（`timeout=180`，挂死即上抛）⇒ **中止机会比上一轮翻四倍**，
   而上一轮已实证**句柄关闭不会触发 stop**。

   ⇒ 不区分「我装的」与「我搭了别人的车」。**仅当 `pre_state == 1060`（本轮自己装的）
   才允许 `stop`／`delete`；`pre_state == 0` 一律不碰、如实报人。**
   ⚠ 单名字黑名单（`BeanNetworkTester`）覆盖不了盘上**另一份同服务名的 2.2 构建**
   （`E:\tools\aneb-shaper\bin\` 与 `\clumsy\`）。
3. 收尾仍按「`sc stop` 是实质、`delete` 仅在 stop 后服务仍在时跑、其 `1060` 判**已自删不是失败**」。

## 7. 边界（**不得外推**）

- 🔴 **`SNIFF` 与 divert 不是同一件事**：`SNIFF` 是「复制并转发」，**只因原包继续下行才存在的副本，
  在 divert 模式下可能根本不存在** ⇒ **本份会高估**；且 divert 的**自我再捕获**是 `SNIFF`
  永远看不到的。⇒ **本份不能完全回答它所前置的那个问题。**
- **转发层暴露的接口语义未经本方实测**（§4.2）。
- 本份**不判**可整形性、**不判**档位语义、**不点名**任何驱动、**不写整形器**。
- 单次、单机、单 ICS 配置、单目标 IP；`MECHANISM_SWEEP.md` 里未被判定的机制**仍未被判定**；
  裁定 §7 那条被安全策略拦下的复核，按「**那一片没扫过**」对待。
