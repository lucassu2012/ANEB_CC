# 2× 分解：判据（**跑前写死**，2026-09-12）

> **被测对象**：`c_forward_layer_probe_20260912` 里那 **A=40／C=40**（每格只发 20 个 ping）
> 究竟由什么构成。**这是「可整」检验的前置**：若每包被看见两次而重注入两次，
> 要么延迟翻倍（**而那看起来像整形生效了**），要么在线路上真的多一个包（**污染被测对象**）。
>
> 🔴 **§0 必读**：本份的机制空间、排除理由、以及**哪一片没被扫过**，
> 全部记在同目录 `MECHANISM_SWEEP.md`。**本份不使用「完备」这个词**——
> 那份文件里 46 条机制中大多未被判定，且对抗面板因我的编排错而**零区分力**（该文件 §0）。

## 0. 本份相对我第一版（H1–H4）改了什么，以及为什么

| 改动 | 理由（均出自 `MECHANISM_SWEEP.md`，非事后补的） |
|---|---|
| **删 H3** | 已由 EvalFilter 九条对照行实测为 `False` |
| **删 H2 的 NETWORK 层形态** | `B=0` 直接反证；**我先前把 B=0 只用来支撑结论，没反过来用在假设上** |
| **H4 换测法** | 原测法（A 格加 `outbound`）测的是**方向**不是「不同因」；判决性实验是**关掉热点再跑 A** |
| **新增「干预」类实验** | 🔴 原四条**全是划分**：收窄 filter 永远说不出「为什么栈走两遍」 |
| **新增「身份」类实验** | 🔴 原设计**分不开「一个包被看见两次」与「两个不同的包」**——两个世界读数相同 |
| **主 filter 加 `and icmp`** | 原为纯地址 ⇒ 任何进程发往该 IP 的包都计入；**实测当时有一条到 `223.5.5.5:443` 的 TCP 流** |
| **新增空闲对照** | 句柄开着、无人 ping，期望 0 —— 原设计一格都没有 |
| **仪器修三处** | 见 §1；其中 `B=0` 的歧义是**承重缺陷** |

## 1. 🔴 仪器必须先修，否则任何读数都不可判

1. **`Recv` 失败即退出且从不读 `GetLastError`** ⇒ 每个计数实为「首次出错前的成功数」
   ⇒ **`B=0` 在「无匹配流量」与「第一次 Recv 就失败」之间歧义**。
   修：失败时记录 `GetLastError()` 与「已成功计数」，**两者一起印**；
   **`error != 0` 的格一律判 `NOT_EXECUTED`，不判 0。**
2. **`t.join(timeout=5)` 返回值从不检查** ⇒ 读线程没退出的格照样印正常数字。
   修：`join` 后检查 `is_alive()`，**仍活即该格 `NOT_EXECUTED`**。
3. **从不读 `pRecvLen`、从不碰包缓冲** ⇒ 无法确立身份。
   修：每次 `Recv` 记录 `(recvLen, ip.ID, icmp.seq)`（按偏移从缓冲里取，**只读不改**）。

🔴 **本份不读 `WINDIVERT_ADDRESS`，一个字节都不读——这是刻意的，不是省事。** 实测核过：
- 身份三元组全部来自**包缓冲**的**标准 IPv4/ICMP 布局**：`ip.ID` 在偏移 `4..5`；
  IHL 由首字节低四位算出（实测 20）；`icmp.seq` 在 `IHL+6..7`。**与 WinDivert 无关。**
- `impostor`／`ifIdx` 是 **filter 增量**（`… and impostor`），**经 filter 语言取得，不读结构**。

⇒ **本份不需要任何 WinDivert 头文件** ⇒ 「地址结构多少字节」这个数在本份里**不承重**，
**也就不存在「拿某个版本的布局套另一个版本的驱动」的机会**。
⚠ 这条写出来是因为树里曾躺着一个会诱人违反它的东西：`windivert.c` 被抓进过仓库根目录，
而它与上游 **`v2.2.2` 不同（228,309 B）**、**与 `master` 今日状态逐字节相同（233,146 B）**
——**真品但版本错**，差约 4.8 KB。已移出仓库树并另记来源与 sha256。
⚠ 且「与 master 相同」**本身是会过期的断言**（master 是移动引用）⇒ 只可写
「**等于 master 在 2026-09-12 的状态**」，不可写「等于官方源码」。
🔴 **同族**：`源码存在 ≠ 源码对应那个二进制`，与 `枚举存在 ≠ ABI 兼容`
（pydivert 2.1.0 的 12 字节 vs 2.x 的 64 字节）是同一句话换个位置——
**上次错在库版本，这次错在源码版本。修法是让它不被需要，而不是规定去哪儿取。**

⚠ **三条修完须先跑「仪器自证」**：filter 设为 `false`，期望计数 0 **且** `error == 0`
——**证明「0」能与「出错」区分开**。这一格不过，整轮作废。

## 2. 实验矩阵（**跑前写死**；每格 20 个 ICMP，`SNIFF|RECV_ONLY`，只数不改）

**共用主 filter**：`ip.DstAddr == 223.5.5.5 and icmp`（加 `and icmp` 是为把背景 TCP 挡在外面）

| # | 层 | filter 增量 | 谁打流量 | 它回答什么 |
|---|---|---|---|---|
| S0 | NETWORK | `false` | 无 | **仪器自证**：0 与「出错」可区分 |
| S1 | NETWORK | 无 | **无人** | **空闲对照**：A 的底噪（期望 0） |
| S2 | FORWARD | 无 | **无人** | **空闲对照**：C 的底噪（期望 0） |
| A1 | NETWORK | 无 | PC | 复现 A（期望约 40） |
| A2 | NETWORK | 去掉 `and icmp`（回纯地址） | PC | **A2 − A1 ＝ 背景非 ICMP 的贡献** |
| C1 | FORWARD | 无 | P40 | 复现 C（期望约 40） |
| **I1** | NETWORK | ＋`impostor` | PC | 🔴 A 的目击里有多少是**别的驱动注入的** |
| **I2** | FORWARD | ＋`impostor` | P40 | 🔴 同上，C 侧 |
| **F1** | FORWARD | ＋`ifIdx == 9`（以太） | P40 | H2 在转发层的判定（`ifIdx` 在该层可编译，实测） |
| **F2** | FORWARD | ＋`ifIdx == 13`（热点） | P40 | 同上，另一腿 |
| **N1** | FORWARD | ＋`ip.SrcAddr == 192.168.137.129` | P40 | NAT 前 |
| **N2** | FORWARD | ＋`ip.SrcAddr != 192.168.137.129` | P40 | NAT 后 |

**身份读数（每格都取，不单列一格）**：`(recvLen, ip.ID, icmp.seq)` 的**去重个数**与重数分布。

## 3. 判定（**跑前写死**）

🔴 **先判身份，再判构成**——顺序反了就会把两个群体读成一个包的两次目击：

| 身份读数 | 判定 |
|---|---|
| 去重三元组约 **20**，每个出现 **2** 次 | **同一批包被呈现两次**（真正的「2×」） |
| 去重三元组约 **40** | **是 40 个不同的包**，根本不是倍增 ⇒ 原问题本身提错了 |
| 介于两者之间 | **不可单判**：按去重数与重数分布如实记，**不取整到近的一端** |

**构成**（仅在身份判为「呈现两次」时才有意义）：

- `I1`／`I2` ≥ 5 ⇒ 第二次目击**来自其他驱动的重注入**（`impostor`）；**不点名是哪个驱动**
  ——本份无此能力，且**不得因此去碰任何安全软件**（不可逆、扩大攻击面，见 sweep §3-1）。
- `F1`／`F2` 各约 20 ⇒ **每条腿各一次**（H2 在转发层成立）；集中在一条腿 ⇒ 不成立。
- `N1`／`N2` 各约 20 ⇒ NAT 前后各一次；但 🔴 **该读数同时也是「两个不同源地址的包」的读数**
  ⇒ **必须与身份读数联合判，单独出现不作结论**。
- `S1`／`S2` 非 0 ⇒ 底噪不为零，**所有格先减底噪再判**；
  `A2 − A1` 非 0 ⇒ **原 A=40 里含非 ping 流量**，须在证据里改写那个数的含义。

## 4. 需要 PO 的那一个干预（**我做不了，也不代做**）

🔴 **H4 的判决性实验＝把移动热点关掉，再跑一次 A 格**：A 掉到约 20 ⇒ 两格同因（ICS 造成）；
仍约 40 ⇒ 确为不同因。**一次运行、一个比特。**
⚠ 它需要 PO 关一次热点（系统网络配置，非我的动作），且**关热点会使 C 格不可跑**
⇒ **必须排在所有 FORWARD 格之后**；关之后 P2 守卫会当场拦下 C 格，**那是设计不是故障**。

## 5. 前提与收尾（承前一份判据）

- **P2 前后各查**：`ip route get` 须 `dev wlan0` 且 `via 192.168.137.1`（仅 FORWARD 与 P40 相关格）；
  不满足即 `NOT_EXECUTED`。**「关热点」那一格例外，其前提反过来：出口必须不在热点上。**
- **驱动**：从 `1060` 起跑；收尾按前一份 §5b／§5c。
- 🔴 **退出码不得充当读数的载体**（这条比前一份 §5c 更宽，成因是实测出的第四条通道）：
  同一次 `sc query WinDivert`（服务不存在）——`bash $?` ＝ **36**、python `returncode` ＝ 1060、
  PowerShell `$LASTEXITCODE` ＝ 1060，而**工具外壳对那次 PowerShell 调用的报告又是 "Exit code 36"**。
  ⇒ 问题**不是「bash 不好」**，是**任何「外层读内层退出码」的地方都可能是 8 位视角**；
  同一个进程，内层读 1060、外层读 36，**两边都言之成理**。
  ⇒ **规定**：凡 `sc`／`schtasks`／`net`／`reg` 这类 Windows 原生工具的退出码，
  **由取到它的那一层自己印成文本**（脚本印 `rc=1060` 并进逐字副本），
  **外层只读那行文本，不读退出码**。⚠ 判据里写「应回 1060」而不指定载体，
  等于**允许两个人对同一次运行得出相反结论**。
- **stdout 逐字副本**由脚本自己写进本目录，**PO 的粘贴只作旁证**（实测两者曾差一个字）。

## 6. 边界（**不得外推**）

- 🔴 **`SNIFF` 与 divert 不是同一件事**：`SNIFF` 是「复制并转发」，
  **只因原包继续下行才存在的副本，在 divert 模式下可能根本不存在** ⇒ **本份会高估**；
  且 divert 的**自我再捕获**是 `SNIFF` 永远看不到的。
  ⇒ **本份不能完全回答它所前置的那个问题**——这句写在判据里，不是事后补的脚注。
- 本份**不判**可整形性、**不判**档位语义、**不点名**任何驱动、**不写整形器**。
- 单次、单机、单 ICS 配置、单目标 IP；`MECHANISM_SWEEP.md` 里未被判定的机制**仍未被判定**。
