## 0. 一页结论——与续派消息给出的框架有一处**关键分歧**，先摆出来

续派消息转述的归因是：「时序修正后通道 B 检出翻转成功；framestats 的 No process
在刺激全程活跃下仍复现，最终破案=EMUI 按包名查询失效、按 pid 可用」。

**逐字核对 run2 的原始文件后，前半句与本目录的数据不符**：

| 续派消息的框架 | run2 原始文件实际显示的 |
|---|---|
| 「时序修正后」 | `tools/e234/e234_collect.py` 的观测窗排序**在 run2 采集时仍是旧版本**——screencap 观测窗与两段刺激翻转窗**依旧零重叠**（见 §2），与 run1（D-408）**同一个根因、同一种失效形状**，只是刺激时长从 4s 拉长到 ~2 分钟 |
| 「通道 B 检出翻转成功」 | 40 个样本里 3 个不同值，但这 3 个值构成的是**一次孤立的 ~8 秒瞬变**（158.1→133.898→68.0→158.1），发生在 16:41:49–16:41:57——**离最近的翻转事件（stim_pre 末次 16:40:19，stim_post 首次 16:42:34）分别有 87 秒和 37 秒**。这不是刺激源翻转被检出，是观测窗内一次**来源不明的环境变化**，时间上够不到任何一次真实翻转 |
| 「刺激全程活跃下仍复现」 | `collect_notes.json` 显示 `layer:null`、`sf_status:NOT_EXECUTED`——查图层这一步与 run1 逻辑相同，**仍然发生在 `_pin("pre")` 已 force-stop 刺激源之后**（见 §2 时序表），不能证明"刺激全程活跃" |
| 「EMUI 按包名查询失效、按 pid 可用」 | **本目录没有任何一处按 pid 查询的记录**。若这个诊断来自另一次独立的手动验证，本判读**查无实据**，请给出证据路径；本判读只能对 `evidence/e1_realdevice_20260802_run2/` 里实际存在的文件下结论 |

**本文件的结论**：run2 是 run1 那个根因（D-408：观测窗排在两次 `_pin` 之间而非期间）在

## 2. 时序核验：D-408 的根因在 run2 里原样复现

```
stim_pre  翻转窗（pid 14215）  16:38:18.402 → 16:40:19.943   （~2 分钟）
screencap/通道C 观测窗          16:40:25.180 → 16:42:24.409   （~2 分钟）
stim_post 翻转窗（pid 14959→15230） 16:42:34.522 → 16:44:18.719  （~1.7 分钟）
```

三段依旧**互不相交**：观测窗在 stim_pre 结束后 5.2 秒才开始，在 stim_post 开始前
10.1 秒就已结束。刺激时长从 run1 的 ~4 秒拉长到 ~2 分钟，**没有改变问题的形状**——
只要观测窗仍被安排在两次 `_pin()` 之间，无论每次 `_pin` 跑多久，两者都不会重叠。

**顺带证据**：工作区此刻 `tools/e234/e234_collect.py` 与
`tools/e234/tests/test_e234_collect.py` 均为 v3 在办的未提交改动——与 D-408 报告的
时间线吻合：run2 数据采集于旧版本收尾之时，v3 随后开始按 D-408 的建议修复。
**本判读不碰这两个文件**，只如实报告 run2 数据本身采自旧版本。

## 3. 通道 B 的 3 个 ROI 值：不是检出，是一次孤立瞬变——逐帧时刻表

```
16:40:25.180 … 16:41:44.501   共 34 个样本，全部 = 158.1（恒定基线）
16:41:49.654                  = 133.898   ← 唯一一次偏离
16:41:54.064                  = 68.0      ← 唯一一次偏离
16:41:57.489 … 16:42:24.409   共  4 个样本，全部 = 158.1（回到基线）
```

这段瞬变发生在 **16:41:49–16:41:57**，前后各只挨着基线值，持续约 8 秒。
对照 §2 的翻转窗：**离 stim_pre 末次翻转 87 秒，离 stim_post 首次翻转 37 秒**——
两侧都够不着。刺激源在这 8 秒内没有任何 FLIP/COMMIT 记录。

**结论**：这不是"通道 B 检出了刺激源的翻转"。它是观测窗内一次时间上与刺激源
无关的环境变化（可能是系统 UI、通知、或诊断过程中的其他操作——本判读**不猜测**
具体成因，只如实报告"与已知真值刺激源的翻转事件无时间关联"这一可判定事实）。

**若强行拿这次瞬变去配对最近的真值翻转、算出一个"分布"，那个数字的量级会是
「十几秒到一分半」**，这不是"通道 B 量化误差大"，是拿噪声冒充信号。本判读**拒绝**
在零重叠前提下产出一版"首份真机分布"，即便带上误差棒——误差棒描述的应是测量
方法本身的量化极限，不能用来给一个跟事件对不上时刻的数字披上"可信"的外衣。

### 4.1 一处需要留痕的报告面小瑕疵（非严重，但值得记）

`e1_report_post.md` 的表头显示 `interval_ms=800, count=6`——这是**最后一次 CFG**
（pid 15230）的值。但该文件真正的 48 个可用翻转里，只有约 5 个来自这个 800ms/6-count
的配置，其余约 43 个来自更早的 2000ms/60-count 配置（pid 14959，被中断在 49/60）。
`duplicate_seq=6` 如实记了"被覆盖了几条"，但**没有提示"表头这一行 cfg 描述的是
少数派"**。这次不影响我关心的量（E_transport/E_quant 是逐帧算的，不依赖表头的
`interval_ms`），但如果有人拿表头的 `interval_ms` 去算"期望节奏"再跟 48 个翻转比对，
会算错。记录在案，不在本次范围内修。

### 4.2 E_clock 二次确认（本轮唯一正面结论）

两次判读都确认 BOOTTIME↔MONOTONIC 偏移跨度在**个位数微秒以下**（4168ns / 5729ns），
样本量从 run1 的 n=5 提升到 n=59/n=48——同一条链路上更大样本的复现，spec §3.2
「E_clock 已有界」在真机上进一步坐实。
