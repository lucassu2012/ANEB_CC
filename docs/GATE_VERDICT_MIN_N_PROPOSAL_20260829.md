## 1. 现状（实读，非转述）

`tools/e1/e1_analyze.py:546-553` —— 判据全文只有四步：分布缺失或缺实测刷新率
⇒ `NOT_EXECUTED`；无 p99 ⇒ `NOT_EXECUTED`；`p99 <= frame_ms` ⇒ `PASS`；否则 `FAIL`。
**既不看样本量 n，也不看 dropped。**

**四个调用点**（`gate_verdict` 是通用判据，改它会同时动这四处）：

| 调用点 | 喂进去的量 |
|---|---|
| `e1_analyze.py:642` | 逐段分布 |
| `e1_analyze.py:691` | 通道 C（`t_commit→t_present` 实测总量） |
| `e1_analyze.py:699` | 通道 C-framestats |
| `e234/e2_analyze.py:113` | 通道 A vs C |

**已实测到的病例**：`n=1 / dropped=9` 的一份数据判出 **PASS**（`e2_analyze.py:115` 注释在案）
——一个样本的 p99 就是那个样本本身，「p99 ≤ 1 帧」于是退化成「这一次没超」。
现状的处置是**把两个数印在判定旁边**（`gate_caveat`），即：如实说，但不拦。

## 2. 两行提案

### A 行：最小 n —— `n < N_MIN` ⇒ `NOT_EXECUTED`（fail-closed，D-511 同构）

**理由**：D-511 的形状是「信息不足不许当结论」。本函数 docstring 自己写着
「信息不足一律 NOT_EXECUTED —— 没测过不能判 FAIL」，而 **n 恰恰是它没查的那种
信息不足**：n=1 时它照样给 PASS。这是判据与自述之间的一处缺口，不是新增严格度。

**代价与风险**：
- `NOT_EXECUTED` 在 `verify_all -Strict`（现为默认，D-566）下**计败**——若某条采集
  路径常态 n 偏小，这一改会把它从「绿」变成「红」。**这正是要裁的点**：是想让它红，
  还是想让它继续绿着而只在旁边写字？
- `N_MIN` 取值需一个**依据**，不能拍脑袋。本仓现成可复用的有两条：
  `campaign_common.DEFAULT_MIN_SAMPLES = 5`（战役层低置信地板），或 n 表（D-474）
  分 KPI×RAT 的需求。**但两者都不是为「p99 是否 ≤ 1 帧」这个判据推的**——
  直接借用会犯 D-473 那个毛病（把一个 KPI 的算术依据套到另一个上）。
  **建议**：若批 A 行，`N_MIN` 先记 **PROVISIONAL**（如 5），并在 docstring 写明
  「此值未经本判据的敏感性分析，待 E2 数据到位后复核」——像 D-469 三常量那样。

### B 行：dropped 进判读 —— 两种强度，请择一

- **B1（弱，只报不拦）**：把 dropped 计入判定理由串，`PASS` 变成
  `PASS（n=12，另有 9 条被丢弃）`。**不改任何 PASS/FAIL**，只让判词自带分母。
- **B2（强，比例门）**：`dropped / (n + dropped) > X` ⇒ `NOT_EXECUTED`。
  **风险**：X 同样缺依据；且丢弃原因分很多种（`drop_reasons` 是个 Counter），
  「丢得多」不必然等于「剩下的不可信」——一刀切比例门可能**误拒**合理的高丢弃场景。

**我的倾向（供参考，不替裁）**：**A 行批，B 行取 B1**。理由：A 是补一处判据与自述
的缺口，方向明确；B2 的门限缺依据且有误拒风险，而 B1 已经能消灭「PASS 旁边没有分母」
这个真问题——分母一旦印在判词里，读者自己就能判断这个 PASS 值多少。
