## 2. 缝（**本文件的核心**）

**一份操作文档的分区本身就是它的盲区清单**：每份都把自己那段写得很细，
而**两段之间发生的事没有主**。下面逐条点名；**无主的显式标出，交回大脑裁**。

### G1 · S1 完成 → S2 自检之间：**谁做自检？——已裁 `D-742`：归 v4，在非提权窗**

⇒ **两个主体并列，没有写死一个。**

🔴 **而这不只是「派谁」的问题，它有一个没被验过的技术前提**：
§3 的脚本要 ① 写 `profiles\current.args`、② 跑 `schtasks /Run`。
§2 的 ACL 注释写的是「**bin 仅管理员可写；profiles 用户可写**」⇒ ①在非提权窗可行；
**而②「非提权用户能否触发一个 `/RL HIGHEST` 的任务」全项目没有任何实证**。
⇒ **「也可交给 v4」这半句目前是推断，不是结论。**

**已裁（`D-742`）：归 v4，在非提权窗。**

🔴 **裁定的理由否掉了我当时列的 (a)，这一条比结论本身更值得记。**
我原写「**(a) 写死 PO**：S1 与 S2 在同一个管理员窗一次做完……
**收益＝把一个未验前提整个绕开**」——**那个「收益」是错的**：
**整套设计存在的理由，就是让非提权会话也能起整形器**。
在管理员窗里跑 S2 **一定会过**，而**管理员窗本来就能起 clumsy、根本不需要计划任务**
⇒ **验的不是要验的那个东西**，**而通过的感觉和真通过一模一样**。
⇒ **在这里「绕开未验前提」不是省事，是把验收做空。**

⚠ **一般化（值得带走的那半）**：**当一份设计的全部价值在于「在受限环境下也能用」时，
它的验收必须跑在那个受限环境里**——否则通过率 100%、信息量 0。

⚠ 仍然成立的那半：**别写「PO 或 v4 都行」**——那是本条被裁前的状态，而它已经造成了这条缝。

### G6 · 时刻口径：**`stayon` 与设备复原谁验**

根 `CLAUDE.md` 收尾第 4 条要求「恢复 `stayon` 等临时设置」。
⚠ **本窗历史实测**：`stay_on_while_plugged_in = 7` **设着仍睡过**——

### G7 · 起／停整形那一步：**失败会被归到链条的错误一步**（`E2_SCHTASKS_SETUP` §4.1，起草期间新增）

**两条，都是「判据正面写」这条纪律的直接后果**：

1. **`schtasks /Run` 返回 0 只表示「任务已被拉起」**——不表示整形器在跑、更不表示整形生效。
   §4 已写死正面判据：`Get-Process clumsy` 有进程 ＋ `driverquery` 见 WinDivert ＋ **目标 RTT 抬到预期带**。
   ⇒ **S2／S4 的判据以这三条为准，不以 rc 为准。**
2. 🔴 **Git Bash 会把 `schtasks` 的 `/Run`／`/TN` 当 Unix 路径改写**，报错形如
   `错误: 无效参数/选项 - 'C:/Program Files/Git/Run'`，rc=1。
   **那条报错指向一个路径，不指向 shell** ⇒ **撞上的人最可能的误判是「任务没建成、PO 的 §2 没跑成」**，
   然后回头去动一个本来正常的东西。**正确式＝单斜杠 ＋ `MSYS_NO_PATHCONV=1`**（`//Run` 不管用）。

⚠ **这一条为什么算「缝」而不是「某一步内部的坑」**：
它的后果是**把失败归到链条的另一步**——现象出在 S2／S4，而人会去查 S1。
**一份分段写的文档天然防不住这个**：每份都只说自己那段怎么算过，
**没有一份说「这个症状其实来自别处」**。
⚠ **两句报错要分清**：「任务不存在」＝`系统找不到指定的文件`；
「参数被改写」＝`无效参数/选项 - 'C:/…'`。
**别拿一条本身就跑不通的命令的失败，当「任务不存在」的证据。**
