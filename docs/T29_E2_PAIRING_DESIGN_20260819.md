## 1. 【问①】对拍匹配规则

### 1.1 配对语义：从"每轮一个锚点差"升为"逐事件最近邻配对"

**为什么要换**：现规则每轮只产出 1 个 delta，于是
- **样本量天然稀缺**（一次会话 ~10 轮 → n≈10，且不足两簇的轮全丢）；
- **双峰形状根本看不出来**（D-417 说残余抖动是双峰、非连续噪声——1 轮 1 个点，形状被抹平）；
- 单点选择（`cl[1][0]`，第二簇首个）对**簇分割参数敏感**——而该参数 `cluster_gap_nanos()` **从生产侧 `ObsStats.kt` 读取**（当前 400ms，D-52/D-53；读不到即抛、无退路常量，D-392②）。
  即：**判读结果随生产侧一个常量而动，且那个常量改动时无人会想到 E2**。逐事件配对对它的敏感度显著更低（不再依赖"分成几簇"，只依赖"谁离谁近"）——这是换语义的第四条理由。

**建议规则（M7 预案同形：先定语义、再定判据、最后才定阈值）**：
```
对每个 A 侧事件 a（t_boot_ns → 经 clock_pin 换算到 mono）：
    c = nearest_after(a_mono, frames, key="actual_ns", max_gap_ns=W, used=used_set)
    命中  → 记 (a, c, Δ=c−a)，并把 c 标记为已用（一次物理事件只许配一次）
    未命中 → 按 why ∈ {none, gap, reused} 各自计数
```
- **方向固定为 `Δ = c − a`（C 在 A 之后）**：A 是"应用侧观测到内容变化"，C 是"该变化实际呈现到屏幕"。**因果方向决定了 Δ 恒 ≥ 0**；出现负值即是**证据本身出问题**（时钟钉桩偏、事件穿越边界），必须单列计数而非取绝对值吞掉。**这是与现规则最大的语义差别**：现规则对 signed 取 `abs()` 汇总，把"方向错了"和"抖动大"混成同一个数。
- `W`（最大配对间隔）**不由本预案发明数值**，见 §4 依赖：它必须大于 T27 落地后实测的 P99 Δ，否则会把长尾系统性判成 `gap`（"看起来更准"的假象）。

### 1.2 失败计数：四类，全部要出现在判定旁边

| 计数 | 含义 | 为什么必须单列 |
|---|---|---|
| `unmatched_none` | A 之后无任何帧 | 会话尾部截断，正常但要可见 |
| `unmatched_gap` | 最近帧超出 W | **W 设小了会伪装成"数据干净"**，必须和 W 一起读 |
| `unmatched_reused` | 最近帧已被前一个 A 占用 | A 侧事件密度 > 帧率时的真实拥挤，**不是错误** |
| `negative_delta` | Δ<0 | **证据故障信号**（时钟/边界），见 §1.1 |

**判定必须 fail-closed 于两条**（承 `gate_caveat` 的自曝，把 T14 待裁 C-2 在 E2 侧就地补上）：
- `n_matched < N_MIN` → `NOT_EXECUTED`（不是 PASS）；
- `matched / (matched + unmatched_*) < R_MIN` → 降级 + 点名主导失败类。
`N_MIN`/`R_MIN` 同样**不由本预案发明**，见 §2 与 §4。

## 2. 【问②】双峰判别的样本量门槛

**先说清判什么**：D-417 的判断是"残余抖动**是双峰、不是连续噪声**"，两峰间距 ≈1 帧（~12ms @83Hz 或 ~16.7ms @60Hz）。所以要回答的不是"分布长什么样"，而是**"数据够不够把两个峰分开、而不是把一个宽峰误读成两个"**。

**建议判据（三条同时满足才宣称"双峰已判别"，否则输出"未判别"而非"单峰"）**：
1. **总量**：`n_matched ≥ 60`。依据不是统计惯例，而是**每峰 ≥30**——两峰若均分即 30/30；这是"每峰能各自给出 p50 并算出峰间距"的下限。**n<60 时禁止宣称双峰或单峰**，只报直方图。
2. **弱峰占比**：`min(peak) / n ≥ 0.15`。低于此比例时，"第二个峰"与"长尾几个离群点"在本样本量下**不可区分**——此时应报"疑似长尾"而非"双峰"。
3. **峰间距**：两峰 p50 之差 ∈ `[0.5, 1.5] × frame_ms`。**这条不是自由参数**：它把"双峰"钉死在**物理上唯一合理的解释——差一帧**；若实测峰距落在此区间外，结论应是"存在多模态但与帧周期不符"，那是**新发现**，要报大脑而不是套用现有解释。

**为什么不用 KDE/GMM 之类**：本项目的判读要能被人手复核（§2 红线族"守卫本身要能被证伪"）。直方图 + 上述三条阈值可以用一张表复核；混合模型的拟合优度在 n≈100 量级不稳定，且会**把"选了几个分量"这个决定藏进算法**。

## 3. 【问③】候选 B「校正后误差」在双峰形状下算什么——**"扣基线"这个动词本来就错**

**结论先行：错。** 理由三条，按强度排：

1. **双峰下"基线"不是一个数**。"扣基线"预设了 `观测 = 真值 + 常量偏移`，于是减掉常量就还原真值。但双峰意味着系统有**两个离散状态**（差一帧：赶上了这一帧 / 错过要等下一帧）。此时"基线"要么取两峰加权均值（**一个两个峰都不落在的数**），要么取低峰（默认"总能赶上"，系统性乐观）。**减完之后的分布仍是双峰，只是整体平移**——误差结构一点没被消除，却因为数变小了而**看起来更准**。
2. **它把可解释的量换成不可解释的量**。原始 Δ 有物理含义（"内容变化到呈现到屏幕的时间"）；"校正后误差"是 Δ 减去一个我们自己选的数，**它不对应任何物理事件**，无法与别的批次、别的设备比较——除非那个基线也一模一样，而基线恰恰随设备/帧率变。
3. **它与 R-10 的精神冲突**。"扣基线"实质是**把一部分观测量当成已知误差抹掉**；而项目的一贯口径是"不确定就如实标不确定"（区间输出、`indeterminate`、缺失记 null）。抹掉之后**没有任何标记提示读者"这里减过一个假设值"**。

**建议替代（不发明新量，改报法）**：
- 主口径**报原始 Δ 的分布**（p50/p95/max + 直方图），不做任何减法；
- 若确实要表达"扣掉系统性部分之后还剩多少"，**报"峰内离散"**：各峰各自的 `p95 − p50`。它有明确含义（同一离散状态内的抖动），且**不需要选基线**；
- 峰间距单独作为一个量报（`peak_gap_ms`），并与 `frame_ms` 并列——读者一眼能看出"是不是差一帧"。
- 若大脑仍要"校正后误差"，**最低要求**：基线取值、取法、以及"减法已施加"必须三者同时出现在同一行输出上（同 §2.6 三面口径），且**不得进入任何门限判定**（只作展示）。
