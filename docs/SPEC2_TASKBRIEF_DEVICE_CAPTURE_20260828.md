## 1. 背景与目标

诊断结论：仪器完成度约八九成，真实语料只有 73 run（单点位/单运营商/73 全 low_confidence），对 1000+ 样本目标约 7%。本单的唯一使命是**把新数据采回来**：豆包首批、wave-1 外场、s4 真实路径、E1 实测结论、UI 视觉证据。**设计类产出不计为本单进展。**

## 2. 总前置（诚实声明）

**E-1（P40 物理解锁）是本单几乎所有子任务的总前置**——设备锁着，2.1–2.5 一个都动不了。E-1 属 PO 到场动作（决策请求一页清 #4）。E-1 未解前：把本单置 BLOCKED_EXTERNAL 如实记板，**不空跑设备窗（D-481 先例）**，可先做 2.4 的纸面准备（确认 probe 时戳一行是否已落）。

## 3. 范围与文件边界

- **可写**：`app/`（:probe 构建面，本 lane 属主）、`evidence/` 新战役目录、`docs/` 战役 README 与板面回执。

## 4. 任务分解

### 2.1 豆包战役先行批（前置：E-1）
按 `docs/DOUBAO_NETPERF_CAMPAIGN_PLAN_20260824.md` 的先行批设计执行：基线 + WiFi/蜂窝自然对照（先行批不依赖 E-2 提权与 E-3 热点硬件——那是 L3 整形批的前置）。测前/测后照 CLAUDE.md P40 实况流程五步。
**验收**：首批语料落库（独立 campaign_id）；`evidence/doubao_wave0_<日期>/` 含语料 + 流水 + README（含可复跑命令）；板面回执。**预计 1 设备日。**

### 2.2 wave-1 外场 2–3 点位（前置：E-1 + 点位真名 2–3 个 + 外场暂停令解除，一页清 #2/#8）
按 `docs/M3_EXPANSION_ROUND_RUNBOOK_ADDENDUM.md` 执行：预热轮（D-366）、3×3 拉丁方、radio+CGNAT 随采硬前置、取证 5 轮口径（D-379）。目标 ≥160 run 跨 2–3 点位。
**验收**：语料落库、契约门通过、`evidence/m3_wave1_<日期>/` 归档；点位/运营商/RAT 覆盖如实记录（第二张 SIM 未给则单运营商如实标注，不虚报覆盖）。**预计 0.85–1.28 外场日。**

### 2.3 s4_throughput 真机闭环（前置：Codex 完成 E-01 部署，一页清 #5）
部署后：`/api/v1/profiles` 确认 s4 在列 → 真机跑 s4 profile 首批真实路径样本 → 语料落库。客户端侧已全就绪（D-478，741/741 绿；常量已转正 D-499），本子任务只是验证与采集。
**验收**：首批 s4 真实样本入库 + 对拍服务端落盘一致；`evidence/s4_first_real_<日期>/`。**预计 0.5 设备日。**

### 2.4 E1 真机窗：M3 打点误差门出实测结论（前置：E-1）
- 先核对：`ADAPTER_EVT` 逐观察事件 emit `elapsedRealtimeNanos` 的"probe 补时戳一行"是否已落（板 T7/T11 记录为交接给 v2 的欠账；未落则本子任务先补上——:probe 构建面本就归本会话，注意 D-387 的顺序约束：先 DTO 带默认值、后 JSON+assets 同提交）。
- 上机跑 `tools/e1/`（README 有操作说明与设备红线）：通道 C framestats 实测（此前模拟器上 PROFILEDATA 恒空，即 BLOCKED_EXTERNAL 的那条）；通道 A 补时戳后复测。
**验收**：M3「打点误差 ≤1 帧」门从 NOT_EXECUTED 变为 PASS 或 FAIL 的**实测结论**（FAIL 也算收工——诚实结论优于悬置）；`evidence/e1/<日期>/`。**预计 0.5 设备日。**

### 2.5 UI 视觉证据链（前置：E-1；可与任一设备窗合并）
真机截图入库：LiveMetricStrip 四型渲染（三屏）、KPI 门限微刻度、三模式屏现状、ResultScreen 简洁/专业双视图。这是让 PO"看见"UI 进展的最低成本动作——仓内 UI 截图停在 07-14。
**验收**：`evidence/ui_20260829/`（或并入当日战役目录）≥10 张带文件名语义的截图 + 一页索引。**预计 0.5 小时，搭车任意设备窗。**
