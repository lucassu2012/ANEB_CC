# 致 MIW 云端运维：E-01 上 ANEB server 的 profile 目录下落（2026-09-07）

> 本文是给 `20260827_MIW云端运维接入` 的问询稿，由 PO 转发。**全部是只读查询，不要求任何变更。**

---

## 我们在查什么

ANEB 的语料里有 **89 个真实测量 run** 的溯源字段记着 profile 版本 **`s1_chat@0.2.1` / `s2_coding_agent@0.2.1`**，
而**这个版本号在我们的代码仓里从未存在过**（全历史搜索零命中，对照 `0.2.0` 有命中；`git log --all -S` 走遍每一次触碰这两个文件的提交，version 字段全是 `0.2.0`）。

已查明的成因：**那批 profile 确曾在运行时被真实加载**（版本串取自实际加载文件的 `version` 字段，不是拼接出来的），**但那批文件从未进入版本库**。
受影响的 run 跨 **2026-07-31 至 2026-08-20**，其中包含 08-20 那批验收数据。这些 run 的 `profile_source` 记的是 `server`。

⇒ **推断：当时 E-01 上的 server 从一个仓外目录（或未提交的本地副本）加载了 0.2.1 版 profile。**
我们想知道那批文件**还在不在**。

## 查到之后会发生什么（供你判断优先级）

- **文件还在** ⇒ 我们把它们补进版本库，那 89 个 run 的溯源就补全了，一个待做的回放分析能覆盖 88% 的语料。
- **文件没了** ⇒ 我们如实登记「该批 run 的 profile 定义已不可考」，并把那个回放分析的分母从「全部真实 run」改成「可解析版本的 run」（现测 12 比 101）。

**两种结果我们都能接受，但拖越久文件越可能真的消失。** 若这台机器有清理策略或将被回收，请优先看一眼。
