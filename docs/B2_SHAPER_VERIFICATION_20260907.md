## §2 出处：SBOM 与发布证明是真的，但**没有构建出处**

这是本次核验最大的**结构性**发现，也是选型单没有的。

- 随包的 `sigstore.json` **经端到端密码学验证通过**（DSSE 签名、Fulcio 证书链到 Sigstore 公共根、Rekor 默克尔包含证明、checkpoint 签名）。
- ⚠ **但它是一份 SBOM 证明，不是构建出处证明。** 对该摘要查 GitHub attestations 恰好返回两条：`spdx.dev/Document/v2.3`（SBOM）与 `in-toto.io/attestation/release/v0.2`（发布资产证明）。**没有 `slsa.dev/provenance/v1`。**
- **发布的那个 zip 是维护者用个人账号上传的**，不是 `github-actions[bot]`（SBOM 与 sigstore 两个文件才是 bot 传的）。
- CI **确实**为该 tag 跑过一次构建并对**另一个**归档出了证明。对抗复核者做了首轮没做的判决性检验：**把 CI 产物与已发布 zip 逐文件比对——107 对 107，仅缺失 0、仅多出 0，内容不同的恰好 1 个**（那个被签名的 `.exe`）。⇒ 差异**正是文档写明的代码签名步骤**，不是别的东西。
- **作者在自己的 workflow 头部注释里显名写明「本流程不做构建出处」**，没有藏。

⇒ **诚实的表述**：这些字节最终由一个人的工作站产出并上传，**没有任何证明说它由 runner 构建**。它可复核到「与 CI 产物只差一个签名过的 exe」，但那一步本身无人见证。**这是一个已知且被文档承认的信任缺口，不是隐瞒。**

## §3 无头：声明成立，但「任意参数」的说法过宽

这是换掉 clumsy 的**唯一**理由，所以单独核。

- 选型单引的那句 **在 v0.6.0 的 README 里逐字存在**，仍适用。
- 三档所需旗标 **13 个全部存在**，文档与冻结二进制里的选项串两侧都有。
- 🟢 **文档在四处独立位置明确回答了「杀死 clumsy 的那个问题」**：带设置类旗标启动即**立刻开始一次真实整形会话**，没有 GUI 表单、没有单独的 START 步骤。0.4.0 的变更日志甚至把「带参数再加 `--gui`」描述为曾经「在后台悄悄地劣化」。
- ⚠ **两条必须记的限定**：
  1. **「任意参数」过宽**：`--gui` 单独使用会开 GUI；`--gui` 与设置类旗标同用是**用法错误（退出码 2）**，不是静默无头跑。`--help`／`--version`／`--license` 同属例外。
  2. **计划任务用法零文档**：README 与 CHANGELOG 里 `scheduled task`／`schtasks`／`Task Scheduler`／`service` **零命中**，而同一次检索里 `administrator` 各命中 10 次——**量法证明有效，零是真的零**。

🔴 **§3 的关键一条，如实标未决：**

> **实际运行时是否真的开始整形，未验证，且在本次只读约束下无法验证。**
> 以上全部来自文档与静态二进制检查。**本仓规矩是：读源码与读文档不构成对运行时行为的断言**（D-789 正是这么栽的）。

## §4 三条会改变部署方式的发现（验收之前就要处理）

| # | 发现 | 后果 |
|---|---|---|
| **A** | **程序会自提权**：`beantester/winenv.py` 的 `elevate_self` 调用 `ShellExecuteW(None,'runas',…)` 触发 UAC 重启，受环境变量 `BEAN_NO_ELEVATE` 控制 | 直接影响选型单判据 2（**非提权会话经 schtasks 通道起停**）。schtasks 任务本身带 `/RL HIGHEST`，理论上不会弹交互式 UAC，**但这必须实测，不能假定** |
| **B** | 🔴 **它自提权之后从自己的目录加载 `WinDivert64.dll`，而该 DLL 完全没有签名**（PE 安全目录 offset=0 size=0；对照 `.sys` 是 offset 72704 size 21440） | ⇒ **解包到任何非管理员可写的位置，就造出一条「普通用户→管理员」的提权路径**。作者自己文档里警告了这一点。**部署位置必须选在非管理员不可写处**，这是硬要求 |
| **C** | **默认目标作用域是本机全部流量**，且具备 TCP RST 注入、彻底阻断、整类网络切断等破坏性能力 | 我们只要三档（延迟／丢包／限速）。**每次调用必须显式限定 `--filter`／`--target`**，别依赖默认值 |

## §5 其余需要知道但不阻塞的事实

- **`.sys` 的 EV 签名主体是一家中国公司**（成都密思听科技有限公司），证书 2023-05-26 已过期。
  ⚠ **但这是上游自己的签名**，存在于 basil00 亲自上传的官方发行版里，**不是本分发者重签或替换**；RFC3161 时间戳使签名仍然有效，Windows 报 `Signature verified / Valid`。另有嵌套的 Microsoft Windows Hardware Compatibility Publisher 签名，那才是内核加载的许可来源。
  ⚠ **提醒后来复核者**：只跑朴素的 `X509Chain.Build()` 会因为证书过期返回 False——**那个检查回答的是另一个问题**（它不看时间戳反签名）。
- **杀软会报**：Malwarebytes 的检出名 `RiskWare.WinDivert.VulnDriver`，Kaspersky 的 `not-a-virus:HEUR:RiskTool.Multi.WinDivert.gen`。**这是 WinDivert 这一类工具的属性，不是本工具的性质**，提前知道免得当成事故。
- **WinDivert 确实被 loldrivers 收录**（Category=malicious，MitreID=T1068）；**但它不在微软的易受攻击驱动阻止列表上**——首轮判 UNRESOLVED，对抗复核者跑了首轮自己说「能定案」却没跑的那个检查，定了案。
- **作者是真人**：`.exe` 的 Authenticode 签名主体为 `Open Source Developer Dominik Babiarz, Jelenia Gora, PL`；GitHub 账号建于 2017 年；355 次提交分布在 51 天里的 37 天、1067 次 CI 运行——是真实工作曲线，不是合成仓库。
- **独立审视很薄但非零**：46 星、约 446 次总下载、3 名外部贡献者、零安全评审。
  ⚠ 首轮判「不存在任何独立第三方评审」，**对抗复核者推翻了它**：`microsoft/winget-pkgs` PR #423538 由具名非作者审阅者 `Trenly` 批准并合入（2026-09-04）。**首轮的检索方法有盲区，而它把盲区当成了不存在。**

## §6 对抗复核推翻的 18 条，形状是什么

**绝大多数是「按所述被推翻，收窄后的内核仍成立」**——即结论方向对、**范围写宽了**。这正是这一层该抓的东西。几条实质的：

- SBOM 写 `zlib 1.3.1.zlib-ng`，而随包的 `zlib1.dll` **实为标准 zlib 1.3.2**（PE 资源与字符串双证）。
- 「无任何注册表写入」在所述范围上为假——**那次检索只扫了 Python 层**，而写注册表的动作在它按设计加载的原生 DLL 里。
- 「包内无 TLS 栈 ⇒ 无法发起 HTTPS」被推翻：`http.client` 与 `urllib.request` **确实在 PYZ 里**（从 exe 里解出 313 个模块逐一验证）。
- 「共三个第三方包」实为**十个**。
- 语言文件「不含任何主机或 URL」被推翻：`donislawdev.com/support` 三种语言里都有。

⚠ **这五条都不是安全问题，是核验本身的准确性问题**——而这恰恰说明对抗层在干活。**没有它，这份报告会带着五条听起来很确定的错话交出去。**

## §7 下一步（属主 v4）

**按选型单 §3 走验收程序，但先做 §4 三件，且第一步改成零风险的那个：**

0. **部署位置**：解包到**非管理员不可写**的目录（§4-B）。
1. **`--print-config` 打一次**——不加载驱动、不需要管理员，只确认旗标解析与合并。**这一步没有任何副作用，先做它。**
2. `--dry-run` 再打一次。
3. 经现有 schtasks 通道、**从非提权会话**起停，实测是否弹 UAC（§4-A）。
4. 真跑：**目标 IP 的 RTT 抬升到预期带才算过，同时打一个不该被影响的对照 IP**——没有对照，「目标没变」排不掉「量法不灵敏」。
5. `sc query` 确认驱动真的加载了。
6. 收尾：停、复验 RTT 回基线、`--cleanup-driver`、无残留。

**任一步不过就回来报，不试参数。**
