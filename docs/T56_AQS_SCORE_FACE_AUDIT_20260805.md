## 1. 摘要（先说最重要的四条）

- **①T46 报告有一处需要订正的数字错误**：`docs/T46_FULL_CORPUS_ANALYSIS_REPORT_20260804.md`
  称"AQS 总分 73/73 全部 excellent 档（84.8–91.7 分）"——两位独立核验员分别从
  Q1/Q2/Q3 三个不同角度各自复算，**一致得出实为 72 excellent + 1 good**（唯一例外
  `run_id=019fc86d-b295-7409-8ae8-ccd60d556d55`，score=84.823611，取整显示"84.8"
  与阈值 85 视觉接近导致误判）。Token 赛道更明显：**56 excellent + 17 good**
  （23.3% 低于 excellent 门槛），T46 报告未对 token 赛道下过判断，故无此矛盾但
  也未曾提及。
- **②权重最高的子分之一（T3）对总分方差贡献恰好为 0**：T3 在 73/73 run 上精确
  恒为 100.000（标准差=0），却在两条赛道里都是并列最高权重（主赛道 20%、
  token 赛道 15%），是"权重最高但信息量为零"的典型情况。
- **③"总分好看掩盖单项短板"不是个例，是全语料结构性现象**：100%（73/73）的
  good/excellent 档 run 至少含一个 fair/poor 场景级 KPI；排除已知的 s1_chat/U1
  测量伪影后仍 98.6%（72/73）；再排除结构性打不上 80 分的 N1 维度后仍
  35.6%（26/73）藏着其它真实短板。且这 73 个总分**全部**被打分器自己标记
  `low_confidence=True`——档位标签本身自带保留。
- **④M7 进分对总分的真实影响很小，且从未改变过任何一条 run 的档位**：语音首批
  5 条真实数据，M7 子分对总分的影响区间 −1.04~+0.30 分（等比归一化反事实），
  但按仓库真实发生过的 v0.1→v0.2 权重迁移计算，影响其实是 −0.74~+0.54、
  均值转为 **+0.07（近乎中性）**，与"等比归一化"反事实的方向相反——两个数
  必须并列报告，不能只取一个当头条。6 条数据无论有无 M7，总分档位都恒为
  excellent，最低分距下界还有 1.15 分余量。

## 4. Q2：SCORER_LOW_CONF 结构性成因量化

**范围前提**：489 场景中只有 306 个（62.6%）带 `kpi_quality` 诊断字段
（另 183 个缺失，疑似标注脚本版本/回填问题，按战役干净切分——非随机丢失）。
但 **run 级 `low_confidence` 字段在全部 73 个 run 上都存在且都是 True**，
这是直接实测，不依赖 `kpi_quality` 是否回填。

**sample_count 反推表**（306个已标注场景实测 + D1 代码级推定）：

| KPI | profile | 当前 sample_count | 门槛 | 缺口 | 结构成因 |
|---|---|---|---|---|---|
| T1 | s1_chat | 1（恒） | 3 | 差2 | 1 个 `token_stream` 相位 |
| T1 | s2/s3 | 2（恒） | 3 | 差1 | 2 个 `token_stream` 相位 |
| U1 | s1/s2 | 1（恒） | 3 | 差2 | 1 个 `upload_burst` 相位 |
| U1 | s3 | 2（恒） | 3 | 差1 | 2 个 `upload_burst` 相位 |
| **D1** | **s3** | **2（恒，代码级推定）** | **3** | **差1** | **2 个 `download_burst` 相位（语料无 D1 键可直接印证）** |

**核心结构性发现**：`sample_count` = 场景内某类相位**出现的次数**，与相位内
tokens 数/字节数/耗时**完全无关**——已用全部 306 个已标注场景逐一比对
`(T1,U1,U2) sample_count` 与 profile 相位数，**306/306 零不匹配**，是全语料
实证而非代码推理。**因此"测久一点"买不到置信度，唯一杠杆是相位数量这个
profile 设计参数**，是一次性结构改动。D1 走的是完全同构的映射（同一段
`ScenarioKpi.kt` 代码路径），当前 token 赛道 D1 也是 73/73 恒低置信的
同款成因，此前未被 T46 点名。

**两个旁支发现**：
- **U2 零裕度**：s2_coding_agent 的 `tool_loop rounds=8` 与门槛
  `MIN_TOOL_LOOP_SAMPLES=8` **精确相等**（判据严格 `<`，当前不算低置信），
  但零安全边际——只要 1 轮工具循环失败就会翻转为低置信。
- **"空集免罚"是全 KPI 通用设计，非个别 KPI 特例**：8 处判据全部要求
  `isNotEmpty()`，空集合（该 KPI 在该场景不适用）返回 `lowConfidence=false`，
  与"样本充足因而健康"共用同一个 False 值，无法从这个字段本身区分。

**与 D-474 明确区分**：D-474（`docs/N_SAMPLE_SIZE_BY_KPI_RAT_20260804.md`）
回答**战役级**问题（跨 run 重复多少次让均值/CV 稳定）；本节回答**场景内部**
问题（单次场景执行的原始样本数够不够打分器门槛）。两者正交、互不替代——
即便按 D-474 把重复 run 数跑够，只要 profile 相位数不变，每一次场景执行仍
各自独立触发 T1/U1/D1 低置信（forensic 模式的 3 次重复发生在**同一个 run
内**，`repeat_index` 是场景级字段非 run 级，实测三次重复各自独立触发，非
推断）。

## 5. Q3：总分 vs 短板

**核心统计**：good/excellent 档 run（分母）= 73（全部）；其中至少一个场景
至少一个 KPI 为 fair/poor（分子）= 73；**占比 = 100.0%**。**这 73 个总分
全部 `low_confidence=True`**——档位标签本身带保留，这是解读以下全部数字
的必读前提。

**驱动因素**（489 场景 `*_grade` 分布）：

| 字段 | excellent | good | fair | poor |
|---|---|---|---|---|
| t1/t2/t3/t4_grade | 489 | 0 | 0 | 0 |
| **n1_grade** | **0** | 112 | **376** | 1 |
| n2_grade | 192 | 285 | 10 | 2 |
| u1_grade | 3 | 282 | 41 | 163 |
| u2_grade | 81 | 82 | 0 | 0（326 null，s1/s3 不适用） |

**N1 是唯一一个 73/73 全部低于 80 分的子分**（56.49–73.55，均值 67.02），
376/489（76.9%）场景 `n1_grade=fair`，**0/489 达到 excellent**（RTT p50 门槛
<30ms，真机蜂窝实测 p10-p90=55.4-82.8ms，结构性不可达）。U1 的 163 个 poor
全部集中在 s1_chat（=D-366 已知测量伪影，评分侧从未计入 U1 子分）。

**敏感性分析**（同一占比，逐层剔除已知非"真实短板"因素）：
- 不排除任何字段：**73/73 = 100.0%**
- 排除 s1_chat/u1 伪影：**72/73 = 98.6%**
- 再整体剔除 N1（结构性打不上分的维度）：**26/73 = 35.6%**（由 41 条真实
  u1 fair + 12 条 n2 fair/poor 构成）

即使剔除所有已知的"非真短板"解释，仍有超过三分之一的 excellent/good 档 run
藏着其它真实短板未被总分反映。

**典型例子**：全语料最高分 run（91.68，excellent）的 9 个场景里 6 个
`n1_grade=fair`（RTT 62.6-69.6ms），无一 excellent；另有 run（86.13，
excellent）同一 profile 三次重复抖动从 15.6ms 飙到 95.4ms（poor）又回落到
11.9ms，总分档位纹丝不动。

**根因**：加权平均对短板不敏感——T1/T2/T3 三个子分恒高（T3 零方差恒 100），
T4 场景级 489/489 excellent 但**不进 AQS 加权**（`sub_scores` 只有 7 项，
无 T4），把总分整体拉高；N1 这个唯一"打不上去"的维度被稀释在权重里，拽不出
excellent 区间。**边界**：全部 73 run 同一采集点位（SZ-PILOT-01/ctcc），
本结论限于"该点位、该运营商、这套评分体系"，未跨点位验证。Token 赛道分档
分布不同（56 excellent/17 good，23.3% 低于 85），比主赛道的边界问题更明显。

## 7. 结论与建议（登记级，不擅自改评分体系）

**本报告只登记，不改锚/不改权重/不改门槛**——以下是发现的事实，改不改、
怎么改留给 PO/大脑决定：

1. **T46 报告的"73/73 excellent"需要一处订正**（→72 excellent + 1 good），
   两条独立路径（Q1/Q3）交叉确认。建议按 D-473 同款 append-only 纪律追加
   订正，不改原文数字本身（因为那批数字没错，错的是分档判断句）。
2. **T3 子分权重最高但零信息量**，是否该调整权重分配是评分体系设计问题，
   本报告只登记事实。
3. **D1 与 T1/U1 同款结构性低置信**，此前未被点名，若要修，成本与 T1/U1
   的相位数改造属于同一个量级（新增 profile 相位）。
4. **总分掩盖短板是结构性现象（100%→98.6%→35.6% 三层）**，评分体系是否
   需要额外的"短板旗标"机制（不改总分公式本身），是设计问题不在本次范围。
5. **U2 零裕度**是个需要关注但当前尚未触发的风险点，建议登记观察。
6. **语音 M7 进分影响很小、从未改变过档位**，暂无改锚必要性的证据（n 太小，
   且已有的两个反事实方向相反，本身就说明不该急于下结论）。
