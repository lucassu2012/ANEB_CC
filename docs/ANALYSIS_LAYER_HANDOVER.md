# 分析层交接：设计原则、测试策略、当前状态

> **给谁**：接手 `scripts/` 分析层的人（换人，或未来的自己）。
> **为什么需要**：这一层的设计原则散落在 `DECISION_LOG.md` 里（本层自 D-87 起的一长串），
> 逐条读要很久；而这些原则**不是风格偏好，是这层存在的理由**——违反其中任何一条，
> 报告就会开始说谎，而且是那种看起来很正常的谎。
> **配套**：`scripts/README.md`（逐工具口径）、`M2_CAMPAIGN_RUNBOOK.md`（外场操作）、
> `M2_REPORT_TEMPLATE.md`（交付物形态）。

---

## 1. 这一层是什么

把 ANEB 探针产出的 **result-run JSONL** 变成 M2 交付物《城市 AI 业务网络体验热力卡与归因
报告》。纯 Python 标准库、无第三方依赖、锁无关、设备无关——**任何人在任何机器上都能跑**。

21 个工具，接入 `verify_all.ps1` 的 `campaign-analysis-unit` 门。
（golden 条数以 `run_all.py` 的实际输出为准——**此处不写死数字**：写死的计数是本层反复
治理的那种文档漂移，两次提交就会过时。）

## 2. 不可违反的原则

这些是**红线**，不是建议。每一条都有 golden 守着，改动前请先确认自己不是在拆守卫。

### 2.1 不可计算 ≠ 零（R-10）
缺测量的量输出 `None`、渲染成 `—`，**绝不**以 0 或默认值顶替。一个 0 会被读成"测了，结果是 0"，
而真相是"没测到"。同理：空 buffering 块 = 未检测（不是"无批化"）、缺 `attribution` = `unknown`
（不是 `none`）、样本不足 = `low_confidence` 显式标注（不是悄悄呈现）。

### 2.2 "没法查" ≠ "查过了"
schema 不可读、无 `order_index` 证据、无 clock 标注——一律记 WARN / NOT_EXECUTED 并写明，
**绝不**记 PASS。`publish_check` 的 WARN 永不自动升格为 PASS；`coverage_matrix` 在 `--config`
未能给出**完整**目标网格（**任一维度为空**即算）时**硬错误退出**，而不是悄悄降级为描述模式
（D-119 是全空的情形，D-173 是只错一个键名的情形——后者更常见，也更难看出来）。

**"没法查"还得再分两种，而这一刀切在对象上、不切在证据上**：**有对象而缺证据**（有格但无
`server_tier_endpoint`、有块但字段全空）→ **WARN**，须由人解释；**连对象都没有**（单战役谈不上
前后效应量、无同格双介质可比谈不上介质差异）→ **N/A，未作判断**。**两者都绝不记 PASS。**
这条曾只在三个检查项上做到（D-163/D-198/D-170），其余 8 条分支把"没得核"印成绿勾，
最露骨的一条是「无同格双介质可比，**或**蜂窝不劣于 wifi」——**一条 PASS 兼表"核过了、干净"
与"从没核过"**，21 份语料里出现 15 次、其中 **12 次实为无可比对象**（D-229）。
配套要求：**N/A 行的字面与机器判定互为充要**（本层的实现是说明里一律含「未核算」，
并由守卫断言双条件），否则读者看到的和工具认定的会各走各的。

### 2.3 报告不可比性，绝不静默丢格
同格混 profile 版本 / 混直方图边界 / 混 quick-forensic → 标 `MIXED_*` 并**照常出数**；
缺层级 → 记 `TIER_MISSING` **不外推**；负增量 → 记 `inversion` **不归零**。
删掉一格比标注它更危险：读者不会追问看不见的东西。

### 2.4 绝不静默截断
显示上限必须**声明**省略了多少、去哪看全量（稳定性段就是这样）；且只折叠"无信号"的行——
超门与不可计算的行**永不省略**。为报告设的上限也不该套到独立 CLI 上（D-130）。

### 2.5 转义而非拒收
人工输入的标签含 `|`、换行、HTML——**转义后如实显示**。若某点位真叫 `SZ|CBD`，
报告应显示它，而不是丢弃或崩溃。（转义只属于渲染层；CSV 与分组键用原值。）

### 2.6 三个输出面必须同时改
报告有 **markdown / HTML / CSV** 三个输出面。同一个缺陷曾在三面**各犯一次**
（D-135→140→141：跨战役混池的中位数在 md 有标记、HTML 全缺、CSV 零标记且
`low_confidence=False` 暗示可信）。**CSV 是最要紧的一面**——分析员在它上面做计算，
而它只有列、没有横幅可看。加任何信息时：**核对三面，而不是只看自己刚编辑的那个**。
跨面共享的文字用单一事实源函数（如 `corpus_warnings()`），不要靠文本抽取搬运。

**「同时改」还要问「比的是什么」**：此层的跨面守卫长期只比**标记与段落在不在**，
**没有一条比过数字**（D-302）。三件事因此各自躲了很久：①页面与导出的数值从没被对过账
（实测热力卡 32 格、分 KPI 128 格两侧全等——诚实的否定，但此前无人核对；补上过账守卫后，
谁给一面加过滤都会被咬住）；②**合成数据警告只印在有横幅的两个面上**，13 张 CSV 里两张
一个字的证据都没有，其余各表的 `SYNTH-` 字样纯属点位/战役 id 恰好带前缀（D-303）；
③**一个模块渲染两张表、只导出一张**，而按「模块」计数的守卫照样答「有」——无线的忙闲
可比性判读与 validity 的按日趋势就这样只活在页面上（D-304）。**判据要落到「每一张表」
与「每一个数」，不是「每一个模块」。**

### 2.7 虚构数字必须不可混淆
彩排语料带**双重标记**（加性 `synthetic` 块 + `SYNTH-` 前缀），任缺其一仍可检出——
改标签洗不掉、删块也洗不掉；报告在标题正下方印红色警告，`publish_check` 直接 FAIL 阻断。
真实语料**零横幅**（狼来了会训练读者忽略警告）。

### 2.8 给出差值，就要给出"多大才算数"的尺度
只报 Δ 不报噪声量级，等于邀请读者把复测抖动当成效果（+3 分看起来像发现，而该格 CV 可能就有 5%）。
前后对比给指示性噪声尺度并标 `噪声内`；噪声不可估的格是**第三态**，既不是"噪声内"也不是
"真实变化"。同理，采集期要能反过来问"当前 n 能分辨多小的差异"（`stability --plan`）。

### 2.9 沉默的检查项等于没有检查项
新增检查时容易只想"触发时说什么"，忘了"不触发时是否还看得见"。`publish_check` 的每一项
在**任何语料形态下都必须出行**（不适用就写"不适用"），否则扫清单的人分不清"没问题"和
"工具漏了"。已有不变量测试钉住"各形态下检查项集合相同"。

### 2.10 "未检出异常" ≠ "证明相同"
筛查没报异常，只说明没有单元越过阈值，不代表各单元一致——满网格实测 MAD/典型 ≈ 29%。
判读措辞只能陈述**做过的检查**，并把离散度一并给出，让读者自己判断。

### 2.11 无歧义的替使用者清理，有歧义的连证据一起交回去
标签首尾空白无合法含义且在渲染中不可见 → 直接规范化；大小写/全角**可能**是有意区分 →
只检出并明写"**这不是自动合并的**"，给出两条出路。与 2.5「转义而非拒收」是同一原则的两面。

### 2.12 会说谎的守卫比没有守卫更危险
一次六透镜对抗审计的 8 条高危发现里，**6 条不是"缺检查"，而是检查给出了反向或虚假的结论**：
否决语义写反会把外场排查引向反方向；前后配对按字母序把改善印成回退；标签全塌成一格照样 PASS；
`started_at_epoch_ms` 写成秒仍照常排序，而结论栏还写着"按时间排的"。
**没有守卫时人会自己存疑；守卫说了话，人就不查了**——所以审查守卫要问的不是"有没有检查"，
而是**"这个检查在它失败的那一刻，会说出什么"**。

三个已反复出现的机械成因，值得逐一对照：

1. **守卫的判据与消费方的判据不是同一个**。`coverage_matrix` 的硬错误判「任一维度非空」，
   而 `analyze()` 要的是「每一维都非空」——网格是三维的积，少一维就是空的，于是**只写错一个
   键名**的配置穿过硬错误、落进描述模式，横幅还印「未声明目标网格」（D-173）。
   **判据要么共用一个函数，要么在两处都写明彼此的关系。**
2. **同一份文字在多处各维护一份**。D-155/157/158 的标记在 markdown 出现数十次、
   HTML 与 CSV **各 0 次**，因为三个渲染器各有一份标记清单（D-160）。
   修法是**单一事实源函数**（`incomparability_flags()` / `premise_notes()` / `heatcard_notes()`），
   不是逐处补——见 2.6。
3. **字段的取值范围从没被核对过**。可用不等于可信：一个数量级写错的时间戳照样排序，
   只是排出来的先后是错的（D-176）。**凡是参与排序、分档、差分的字段，都要问一句"什么样的
   取值是不可能的"。**
4. **一处横幅替所有下游作了承诺，而承诺从没逐个核对过**。语料横幅与发布自检都写着
   「不可能的取值已排除出中位数，受影响的格标 `IMPLAUSIBLE_VALUE`」——这句话此前只在
   **七个池化段落里的两个**成立（D-197）。代价不是漏了一句提醒，而是**那句提醒本身成了假话**：
   读者看到横幅就不会再怀疑下面的表。它与前三条的区别在于**看起来已经修好了**——
   守卫在、文字在、测试全绿，缺的只是"谁在兑现它"这一次点名。
   **凡是替别人作出的承诺，都要有一条逐消费方的核对**（`_POOLING_SECTIONS` 即为此而设）。
   同族的一个变体：`buffering_rollup` 算出了标记却没有任何渲染器读它——
   **输出到不了任何一个面的守卫，不是守卫**。
5. **被归档为"决定结论"的东西，本身没被核对过它是否真的决定结论**。溯源段印着
   「**生效门限**（改动其一即改变报告结论，复现须同值）」，而 `segment_outlier_k` 归档时
   **早已不可达**——它是我在 D-200 里为"让 manifest 保持一个稳定键名"专门留下的（D-204）。
   **一份掺了死条目的清单，会教读者把整张清单当摆设。** 两条配套规矩：
   **①凡归档为门限者必须活读**（写成默认参数会在 `def` 时绑定，归档值与实际用值可以分家）；
   **②每条归档门限都要有一次扰动证明它真的改变报告**——与「决定输出的门限必须全部归档」
   （D-198）互为对偶，两条合起来才是 `归档 ⇔ 决定输出`。
6. **读者做的第一个动作，恰好是报告最没准备好的那个**。他不会通读，他会**拿数字去对判据、
   拿清单去找最严重的、照着「见 X」去翻、把两列一减看对不对得上**——而这四件事各自都出过错：
   84.96 印成 `85` 却标 `good`（D-207）、「前三个」列出的是最轻的三个（D-208）、
   「见 `CV 不可计算` 一列」指向一个不存在的列（D-212）、before/after/Δ 三个数减不平（D-207）。
   共同形状是**同一件事由两套口径产生**：显示与判定、排序与严重度、指路与被指之物、
   各自舍入的三个数。**凡两个东西并排出现且读者会把它们对起来看，就必须由同一条线算出。**
   还有两条相关的：**「未知/无标签」桶一旦进入有序集合就会获得它没有的语义**
   （被当战役排进时序 D-210、被当地点排进最差榜 D-211）；
   **凡出现「X/Y」，都要能说清 Y 怎么来的、被排除的去了哪里**（D-209）。

7. **一处图例替下面每一行作了承诺，而其中一部分行根本没跑**。`publish_check` 的表头写着
   `PASS=该项无问题`，220 个 PASS 行里 29 个（13%）其实是"这项检查连对象都没有"——
   读者对这张表的第一个动作是扫图标，绿勾就是他读到的全部（D-229，详见 §2.2）。
   与第 5 条同源：**凡一句总述覆盖多行，就要逐行核对它对每一行都成立**。

**这一条的另一半**：本层曾在连续两轮里**自己引入**其中两条——快速迭代时最容易违反自己刚立的
规则。所以修法优先选**结构性消除**（让错误不可能被表达），而不是在出问题的地方各打一个补丁。

### 2.13 输出侧也是前门
前门加固做过五轮，**全在输入侧**（空语料、坏行、glob 不匹配、人手写的网格配置）。
输出侧一次都没做过，而外场收工最常见的手误恰恰是**输出路径打错**：四个输出旗标遇到
不存在的目录，四条**全部抛 Python 栈回溯**（D-306）。**它比输入侧的失败更难收拾**——
md 先于 html 先于 csv 写出，`--md ok.md --csv nope/c` 会**先落一份 markdown 再崩**，
操作者拿到半套交付物，而栈回溯里看不出磁盘上到底有什么。规矩：**能事先枚举的目的地问题，
在读语料之前就拒绝**（退出码与用法错误同档，且**一个文件都不产出**）；判定不了的
（目录在但写不进）如实留给写入时报错，不要拿探针文件去试。

另一半是**策略要被决定，而不是默认**（D-307）：命名**目录**的旗标（`--out-dir`）可以自建，
命名**文件或前缀**的旗标不可以——替一个打错的父目录建目录，等于把交付物撒到没人会去找的
地方。两种策略各有守卫钉住，免得日后有人「统一」成一种。

### 2.14 同一个东西写在几处，就必须有东西逼它们一致
本层有意保留了几份**独立实现**：`analyze_results.py` 与 `dashboard.py` 的 docstring 都明示
「stdlib only」，且**全仓无人 import 它们**——正因如此，它们各自带着一份 `fnum` 和
`load_records`。这个取舍**不改**（让它们依赖 `campaign_common` 会改掉它们被写进 docstring
的性质），但代价是真实的：**修复只落在被触发的那一份上**。

实测两次。`campaign_common.fnum` 在 D-148 学会拒绝 NaN/±Infinity，另两份**都没有**：一个
`nan` 让 per-run 摘要打印出 median=nan、n=20（20 个样本的中位数被其中一个毁掉，exit 0
无告警，D-314），并**印进了 dashboard 的交付页面**（D-315）。`cc.load_records` 按
`run.run_id` 去重是因为重复计数会「silently INFLATING apparent confidence」，另两份也都
没有：同一个文件在命令行**列两次**（重叠通配符、或 D-09 双写文件），20 条语料变
`records=40`，页面上每个 n 翻倍，两个面都不吭声（D-315）。

规矩：**副本可以留，分叉不可以**。每一组同名实现都要有一条守卫，拿**同一批输入**问它们
要**同一个答案**——比在旁边写句注释硬得多，下次只修一处会当场失败。两条落地要点：
①**按行为钉，不按实现钉**（三个 loader 只需在「首个 `run_id` 重复的语料」上返回同一个数，
各自怎么写不管）；②**比较方式本身别说谎**——`NaN != NaN`，用相等判断会让两个 NaN
悄悄通过，改用 `repr` 比对（承 §2.12）。

找副本的手法是**按名字分组，不要顺着 import 图找**：没有依赖边的副本正是漏网的那一种。
把 `scripts/*.py` 的顶层 `def` 按名分组，七组重名里三组是诚实的否定（签名不同的重名、
只转调的薄壳、逐字相同的 `html.escape` 包装），两组是真缺陷。

## 3. 测试策略：换一个维度，就抓到一个真 bug

**教训（本层最贵的一条）**：干净 fixture 与"已知输入→已知输出"的 golden 有**系统性盲区**——
它们只能验证你想到的情形。每换一个测试维度，都抓到过真 bug。

| 维度 | 手段 | 曾抓到的真 bug |
|---|---|---|
| 已知输入→已知输出 | 各工具 golden | 方法学不变量回归 |
| 整体形态 | 整报告快照冻结 | 段落被删 / 重排 / 措辞变 |
| 规模 | 12960 run 压测 | （无 O(n²)，确认线性） |
| 混乱语料 | `--chaos` 10 种外场病理 | 摘要标签歧义（丢 profile_id 维） |
| 随机语料 | 20 种子属性测试 | 竖线劈裂 markdown 表格 |
| 敌意输入 | 人工标签含 `\|` / 换行 / HTML | 每张表同时崩 |
| 编码 | 中文标签 + Excel | CSV 无 BOM → 乱码 |
| 流程 | 照字面走 runbook | 一天跨点位被打成同一点位 |
| 跨工具 | 报告级设定用到独立 CLI | 折叠上限误伤专门看稳定性的人 |
| 文档覆盖面 | 每个 `scripts/*.py` 必须在 README | 两个工具从未被记载 |
| 三面一致 | md / HTML / CSV 同一断言 | 同一缺陷每面各犯一次 |
| **输入顺序** | 打乱记录顺序重出报告 | **等级在 good / poor 间翻转**（并列按插入序裁决） |
| **非法数值** | 注入 NaN / Infinity | 一个 NaN 毁掉同格其余四个值的中位数 |
| **标签同名异写** | 尾随空格 / 大小写 / 全角 | 同一点位裂成 5 个 `low_conf` 格 |
| **单位 / 量级** | 时间戳写成秒 / 微秒 | 更好的一轮排到 1970 成了"before"，改善印成回退 |
| **对抗审计** | 多透镜并行找，再交怀疑者证伪 | 8 条高危里 6 条是"守卫在说谎"（见 2.12） |
| **验证装置自检** | 问"这套彩排/fixture 能不能演示阳性结论" | 彩排永远只会说"没超过噪声"，阴阳不分 |

**还有一类，且最难自查**：测试自身空转——**它通过了，但不是因为代码对**。已反复发生，
形状有三种，都值得在写断言时对照一遍：

- **fixture 撑不起被测分支**：语料没有 scenarios，用例走了"无数据"分支，
  "每行都带标记"在**零行**上真空通过。→ 加一条 `assert rows` 自守卫。
- **断言的字符串另有来源**：`"T4 严重卡顿率" in html` 看着在测卡片图例，
  实际摘要早就把这句话带进 HTML 了——**没有这次改动它也通过**。
  → 先数一下该串在产物里出现几次，再决定断言什么（计数，或换一个该处独有的串）。
- **断言用了太宽的词**：拿一个在**免责文字里也出现**的词当"标记未触发"的证据，
  或按朴素 `split("|")` 数列而把正确转义的 `\|` 当分隔符。→ 匹配行内形态，别匹配词。
- **装置本身只能产出一种结论**：彩排语料的设计效应（+3 分）小于它自己产生的噪声（±6），
  于是每次彩排都说"没有超过噪声的变化"——**"改善检测坏了"与"工具很诚实"输出一模一样**。
  → 验证装置必须能演示**阴阳两种**结论，且预期答案要**写下来**（`DESIGNED_EFFECTS`、
  `CHAOS_PATHOLOGIES`），否则彩排只是演示，不是核对。

**写守卫时务必负向验证**：把缺陷注入回去，确认它真的会失败。本层每一条重要守卫都这样验过，
D-173 那条正是**因为原测试从未负向验证，才把缺陷写成了期望行为**。

**审计"某条红线有没有守卫"时，同样只能靠负向验证。** 用 grep 找词汇会给出**错误的结论**，
而且两个方向都会错：搜得太宽，会把免责文字里**提到**标记名的地方当成"标记出现了"（D-181）；
搜得太窄，会把**用另一套说法**写的守卫判成"这条红线没人守"——§2.5 就被我这样误判过一次，
是把 `md_cell` 的转义拆掉之后，才看见 `test_report_properties` 里那条一直都在的守卫（D-185）。
**要知道谁在守某条红线，就把它弄坏，看谁喊。**

**§2 的十二条已按此法整体验过一遍**（D-186）：对每条红线施加一处最小突变、跑全套、
在 `finally` 中还原、最后以 `git hash-object --no-filters` 比对确认工作区与 HEAD 逐字节一致
（**`--no-filters` 不可省，理由见下文**）。
**17 条突变，17 条被咬住，零漏网**——所以本文开头那句"每一条都有 golden 守着"
是**实测结论，不是断言**。两点值得接手人知道：多数突变会同时打断 3~24 条测试
（红线之间的守卫是**交叉**的），而 **§2.10 只有报告快照加一条专门测试咬住，是最薄的一处**。
改动那一带时请格外小心。

**D-197 的十条守卫按同法验过**（五个取值守卫、CV 符号、批化标记渲染、CSV 的列/宽/序）：
**10 条突变，10 条被咬住**，收尾同样以 `git hash-object --no-filters` 确认逐字节复原。这一轮的形状与
D-186 不同：**多数突变只打断 1~3 条测试**，因为这些守卫是新的、彼此不交叉——
其中 `order_effect` 的取值守卫与 `buffering` 的标记渲染**各只有 `_POOLING_SECTIONS`
那一条在守**（该测试的文档字符串已按下述规矩自报家门）。

**为什么 `--no-filters` 不可省（D-213，实测）**：不带该参数时，`git hash-object` 会先跑一遍
**clean 过滤器**再算哈希；本仓库 `core.autocrlf=true`，过滤器做的正是 CRLF→LF 归一化。
后果是**同一份内容的 LF 版与 CRLF 版会算出同一个哈希**——2026-07-28 在工作区实地量到：
`publish_check.py` 是 LF、`coverage_matrix.py` 是 CRLF，原始字节不同，过滤后哈希却都等于 HEAD。
也就是说，一个把文件按另一种换行写回的还原脚本，**能干干净净地通过"逐字节一致"这项检查**，
而 `git diff` 同样看不见它（diff 也走归一化）。这一条的形状与 §2.12 是同一个：
**检查嘴上给的保证，比它实际够得着的范围大**。所以还原验证必须落在原始字节上——
`git hash-object --no-filters`，或 `cmp <(git cat-file blob HEAD:<path>) <path>`。
BOM 不在此列：它不经 EOL 过滤器，所以 D-199 那次剥掉 BOM 是能被普通 hash-object 咬住的。

**「测试失败了」不等于「守卫咬住了」（D-220）**：审计 D-220 时，第一次突变删掉了 `reconciled`
的赋值却留下了引用它的那两行，测试确实失败——**但失败信息是 `NameError`，是模块崩了，
不是守卫发现数字不对**。只看退出码，这一条会被记成「CAUGHT」，而实际上什么也没验到。
所以**每一次突变都要读失败信息，确认它死在你想验的那一步上**；本层的审计脚本一律把首行
错误打出来，就是为了这一步不能省。这与 D-204 的无效探针、D-210 的空转逃生口是同一个家族：
**验证动作本身也需要被验证**。
**推论：突变的锚点必须唯一。** 给两条测试加计数下限时，我用的那行锚点
在同一文件里**一字不差地出现两次**，按首次匹配替换改的是排在前面的另一条测试——
于是审计报了个 **MISSED**，而那既不是下限失效、也不是守卫不咬，**只是我改错了地方**。
锚点要么取到被测函数独有的一段，要么先数一遍它在文件里出现几次。

**这套审计不做成常设工具**：一个会就地改写源文件的脚本是把双刃刀。17 处突变点逐条记在
`DECISION_LOG.md` D-186，D-197 的十处记在同文件 D-197，需要复验时照图施工即可。

**薄厚地图**（同一审计的副产品，统计每条红线被**几条针对性测试**咬住；报告快照不计，
