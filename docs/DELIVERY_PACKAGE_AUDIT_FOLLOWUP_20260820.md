## 2. 一处自纠：**我 D-523 的 H-2 写死了"18"，它现在也过期了**

- D-523 原文：「verify_all 15 门…**实为 18**」。
- **今日实测**：最新运行（`evidence/phase0/verify_all_20260820-160525.log`）是 **19 门**
  ——D-518（T69）新增了 `app-unit-tests-full`。
- **也就是说**：我在 H-3 里刚建议属主"别再写死数字，它每天都在动"，
  **而我自己在 H-2 里写死了一个数，两天不到就过期了**。如实登记，同族红线自己也踩。

### 2.1 顺带查明："15"其实**有出处**，H-2 的性质要重述

- `scripts/verify_all.ps1` 里 `Add-Result '<名>'` 的**字面量恰好 15 个**：
  adapters-spec / adapters-spec-unit / app-parity-tests / app-release-signing /
  app-unit-tests-full / campaign-analysis-unit / portraits-redline /
  portraits-redline-unit / portraits-schema / portraits-schema-unit /
  profiles-deep / profiles-valid / results-contract-unit / spec-scoring-unit /
  voice-plan-parity
- 而**实际运行 19 门**，多出的 4 个（`app-assemble` / `server-build` / `server-test` /
  `server-vet`）不是字面量产出的。
- **所以 H-2 的准确性质不是"数字写错了"，而是「两个口径」**：
  15 = 脚本里硬编码的 check 名个数；19 = 一次运行实际产出的行数。
- **但 `verify_all 15/15` 这个写法仍应改**：`X/Y` 是"全过"的断言形式，
  而 **PO 复跑时屏幕上会出现 19 行**，与 Y=15 对不上。
- **修法建议（替代 D-523 里"应改 18"的说法）**：
  ① 最稳妥——**不写死数字**，写「verify_all 全绿（门数以当次运行输出为准）」；
  ② 若要给数，写明口径并标日期，如「19 门（08-20 实测；D-518 新增 app-unit-tests-full 后）」。
- **同源处**：`docs/BRAIN_TASKBOARD.md` 亦写「verify_all 15/15 全绿」，同样适用。
