## O-5 全体会话 · 共享工作树里「索引不是私有的」

实测：一次提交把**另一会话并发暂存在共享 index 里的** `evidence/nr_timeline_20260802/`（723 行）一并卷入；
已 `reset --soft` 精确还原。另一次实测：两次 `git status` 之间 HEAD 已被别的会话推进。

并在提交后以 `git show --stat` 复核只含自己的文件。

## O-7 O-5 通则的两个边角（实测撞到，建议补进 CLAUDE.md）

大脑已把 O-5 立为通则（`git commit <pathspec>` 绕过共享索引 + 提交后 `git show --stat` 复核）。
实践中撞到**两个该通则挡不住的边角**，均为实测：

**边角 A · pathspec 对未跟踪文件无效。**
新建文件无法直接 `git commit <path>`（报 `did not match any file(s) known to git`），
**必须先 `git add` 那一个路径**——也就是说新建文件**绕不开索引**。
可行的收敛做法：`git add <单个新文件>` 后**立刻**用 pathspec 提交，把窗口压到最小。
实证：提交 `11e11fb`（本文件自身的首次提交）。

**边角 B · pathspec 防得住别人的「文件」，防不住别人对「你正在提交的那个文件」的未提交编辑。**
实证：F-1 的提交 `16b866d` **卷入了另一会话对 `docs/DECISION_LOG.md` 的未提交编辑**
（在历史 D-38 行上新增的 D-395 条款）。未改写历史——内容正确，且落库比悬在工作区更安全——
但 **该编辑的属主应被告知它落在了 v3 的提交名下**。

**建议补进通则**：提交**高共享度文件**（`DECISION_LOG.md`、`BRAIN_TASKBOARD.md`）之前，
先 `git diff --cached -- <file>` **逐行确认只有自己的改动**；
`git show --stat` 只能看到「哪些文件」，看不到「文件里混了谁的行」。
