## 2. 待裁项的「改框架/改实现/保留」多选（每项列全第三路）

### 2.1 F-b：语音族要不要 C1/C2 权重 —— **产品级决定，归 PO/大脑**

**这不是措辞问题，是「语音稳定性（会话中断率/切换恢复）该不该进评分」的产品决定**——`C1/C2 + 类 E-model 时延-中断联合惩罚`
是 ITU-T G.107 E-model 的有意质量设计，删它等于删一个质量维度。M1–M7 是单点指标（口到耳/帧抖动/…/最长静默），
**无一等价于 C1/C2 的联合惩罚**；故「M 组是否已覆盖稳定性」本身就是待判问题，本提案不预设答案。三条路：

- **(i) 改框架**：框架 §4.1 删除/降级 C1/C2 + 联合惩罚要求。**代价**：改上位权威框架，且承认放弃一个质量维度。
- **(ii) 改实现**：给语音族加 C1/C2 + 联合惩罚（add-only 不原地改，D-404 纪律）。
  **〔v2 实证更正 `264060e`——范围比原述大一倍〕**：§7.6 台账与本提案初稿都写「现**两表**均无 C1/C2」，
  但 v2 按基线纪律 8 逐表枚举 `weights.yaml`——**四张语音表全无**：`WEIGHTS_VOICE`(M1/M2/M3/N1/N2)、
  `WEIGHTS_VOICE_SIM`(M1–M6/N1/N2)、`WEIGHTS_VOICE_V02`(M1/M2/M3/M7)、`WEIGHTS_VOICE_SIM_V02`(M1–M7/N1/N2)
  **全部无 C1/C2、无联合惩罚**。故 (ii) 要动的是**现役的 v0.2 两张**（`_V02`/`_SIM_V02`，按 add-only 新建 v0.3），
  不是 v0.1 两张——**工作量与版本纪律代价按四表/新建 v0.3 重估，比「两表」大一倍**。
  **代价**：需 C 组会话数据接进语音链路 + 真实语料标定权重（全仓零真实语音语料）+ 新建 v0.3 两表并保留 v0.2 历史。
  （这条更正本身又是「转述 vs 实证」的实例——初稿引 §7.6 台账的"两表"未自己逐表枚举。）
- **(iii) 保留待标定（PROVISIONAL）**：把 C1/C2 + 联合惩罚登记为「待真实语音语料标定的扩展项」，两者都不做但保留框架意图。**与 §2.4 的 target 处置同构**（都被"零真实语料/E-06 未落地"阻塞）。

**v4 倾向 (iii)**（不轻率放弃设计意图、不扩范围、与 target 同处置）——但**明确标注这是「无 PO 产品目标输入下的默认」**；若 PO 判定语音稳定性不需入评分，则 (i)。**裁定归 PO/大脑。**

### 2.2 F-c：64kbps vs 框架 24-40kbps 的对账 —— 三选一

- **(i) 规格写取值理由**：在 `PROFILE4_VOICE_LOOPBACK_SPEC.md` 写明「64kbps 是当前帧参数（160B/20ms）的自洽取向」。
- **(ii) 改框架数字**：把框架 §4.1 的 24-40kbps 改为含 64kbps 的区间。
- **(iii) 改实现收敛**：把帧参数收敛到框架的 24-40kbps。

**如实说明**：这一半是**真开着的实质问题**——是否接受实现相对上位框架 1.6-2.7× 的码率偏离，不是文档问题。
**〔v2 独立复算 `264060e`〕**：`FRAME_INTERVAL_MS=20`+`FRAME_BYTES=160` → 160×8÷0.02÷1000 = **64.0 kbps**（精确非约数）；
对框架 24-40 得 64÷40=1.6× 到 64÷24≈2.67×，「1.6-2.7 倍」逐位对得上；代码注释亦写「20ms×160B≈64kbps Opus 量级」。此数已进基线 §4.2 标为实证。
`validate_voice_plan.py` 只钉了「160B/20ms⇒64kbps 内部自洽」，没回答「64 该不该等于框架值」。v4 倾向 (i)（守卫已保证自洽、框架不宜为迁就实现改数字），但 (iii) 同样正当（让实现向权威看齐）——**PO/大脑裁，一条 D 号。**

### 2.3 F-d 的 VC-3 静音期心跳 —— 三选一

- **(i) 显式降范围**：登记「VC-3 暂不接入，降为扩展项」。
- **(ii) 接入**：实现静音期心跳（需 Codex 服务端心跳支持，跨 lane）。
- **(iii) 保留为待接入核心项**：不降格，接入 contingent on E-06/UDP 媒体端点落地（VC-3 静音心跳与 FRLOSS 同被真实媒体端点阻塞，同形）。

v4 倾向 (i) 或 (iii)（当前无外场/设备窗支撑接入）——PO 裁，一条 D 号。

### 2.4 F-e 的 target 残余微裁 —— 基线未登记的唯一真实新增

D-406 已消字面矛盾，但生产端 FRLOSS 条目「各取一半」：`measurability=NOT_MEASURABLE`/`scored=false` 跟 §5（TCP 现状），
而 `target={excellent:0, good:0.01, fair:0.03}` 仍跟 §4.1 的 <1%（`TestModeProfile.kt` FRLOSS 段 + `client_profiles.json` 镜像均在）。**基线 F-e 说"不再是待办"时未提这条残余。** 二选一：

- **(i) 保留 target 标 PROVISIONAL**：门限留作 E-06 UDP 端点落地后的质量目标，记回核义务（同 M7 末点锚形状），与「只增不改」一致。
- **(ii) 清空 target 待 E-06 再填**：更干净，但丢失已想清的质量目标。

**v4 推荐 (i)**；分钟级微裁，可自裁或大脑快裁。
