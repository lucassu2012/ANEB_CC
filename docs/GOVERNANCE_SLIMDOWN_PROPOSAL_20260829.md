## 4. 砍⑤｜审计降配

- **现行条文位置 = 无成文条文**：根 `CLAUDE.md` 对"审查/审计/多agent/对抗/镜头/抽样"零命中。多 agent 对抗审计目前是**按需的临场实践、非固定纪律**（举证=`BRAIN_TASKBOARD` 的 T46/T67/T79 回执、记忆库"七透镜/六透镜"复盘）。处于**无条文的自由裁量态**——既无"每次都跑"的强制，也无"按需"的授权。
- **修订后条文**（提议加进 CLAUDE.md 或本提案作独立纪律）：
  > 「**多 agent 对抗审计的配额（治理减负 §4，首次成文）**：对抗审计**不是每单必跑**——按下列触发：①交付给 PO 拍板的材料（决策请求/规格提案）；②改评分口径/契约/红线的变更；③交付包定稿前一次。
  > 其余日常任务用"方向性错误"单镜头（一个证伪者）即可，不铺多镜头。**降为按周抽样**：非上述触发的已交付物，每周抽一次做多镜头复核。」
- **预计节省**：把"凭会话判断施加"的重实践（T79 曾 49 agents）降为触发式 + 周抽样，可省大量 agent-token，且不丢关键把关（触发①②③覆盖高风险面）。
- **⚠ 自我指涉**：本会话 v4 对 4.2/4.3 都跑了三镜头对抗核验——按本条这**正是触发①（交 PO 材料）**，合规；但若对每个小件都跑就是过度，本条正是划这条线。**4.3 那次三镜头抓出我五处错（含第五次踩坑）——证明触发①的对抗审计不能砍**，故本条只砍"非触发场景"的冗余。
- **⚠ 判据升级：按「可机器化性」分流，不只按频率降（吸收 v2 实测洞察，08-29）**——审计降配的真正判据不是"多久跑一次"，是"这一类核查机器兜不兜得住"。v2 今晚实测了这条分界（并在我的 F-b 提案上当场抓到一处"两表实为四表"）：
  - **能机器化的**：跨文件节号引用是否指向真实存在的节、跨文件数字是否一致——这半应**转成常设守卫**（v2 已把"节号引用存在性"守卫提给 v3，是 `test_docs_commands.py` "命令引用的脚本是否存在"的自然延伸），从对抗审计里拿掉，机器每次跑、不耗 agent。
  - **不能机器化的**：**"这句事实断言有没有被实证过"——机器认不出哪句是事实断言、哪句是设计意图**，这半**只能靠触发式对抗审计 + 互相核（你核我、我核你、大脑核我们）**，**不能砍**。今晚三次被咬中（v2 的"疑为同批改名"当事实、我的"两表"未逐表枚举、我 4.3 把已订正基线当旧态）全是这半，全靠互相核接住。
  - **一句话**：砍⑤ = 把能机器化的转守卫（降 agent 用量）+ 保留不能机器化的走触发式审计（不降把关）。这比笼统"按周抽样"精确，也直接回答了"为什么触发①不能砍"——那正是机器兜不住的那半。
  - **⚠ 这条本身又是那句主线的实例**：「引用过教训 ≠ 不再犯它，只有机器守卫兜得住」——而**纪律 8「进裁定材料先实证」本身不是守卫、只是一个人的动作**（v2 原话），下一个人不记得时它一行字拦不住。故能机器化的必须真机器化，不能机器化的必须有互相核这个"人肉守卫网"，两者缺一，纪律就只是一句会被忘记的话。

## 8. 六刀优先级建议（据 v2 一夜五例频次证据 · 大脑 08-29 转接）

- **证据（v2 今夜自查收官的排序观察）**：v2 查到的跨文件问题**全部同一形状——「写对了但后来变了/没对齐」**（一夜五例：v1.0 行号被横幅顶偏、台账扩根后 110 没跟、总计划 7-3/7-5 状态漂移、我的 F-b「两表」实为四表、豆包 §10.3 工时假设与协议 §2 定案不一致）。**共享树多会话并行改互引文档，这形状是常态非例外。**
- **推论**：v3 的节号守卫只兜「引用指向不存在的节」一小类；**数字/假设/状态漂移仍靠人回头查**。若治理减负排优先级，「**跨文件一致性机器化**」的收益 > 再加一层审计——因为它治的是**每夜都发生**的常态形状，而多加审计层只是重复人肉核查。
- **六刀优先级排序（据此频次证据）**：
  1. **最高｜跨文件一致性机器化**＝砍④（数字徽章化，治「数字漂移」）＋ v3 节号守卫（治「引用漂移」）＋ **建议扩到状态/假设一致性**（五例里三例是数字/状态/假设漂移，节号守卫都兜不住）。这是唯一治「常态形状」的一刀。
  2. **高｜砍⑥ worktree 隔离（4.5）＝治漂移的根因**。v2 点明这形状是「共享树并行改」的直接后果；隔离让并行改走显式合并冲突，「行号被顶偏/台账没跟」在合并时对合并者可见，而非事后靠人翻。**4.4 与 4.5 在此汇合：一个治症（一致性守卫）、一个治根（隔离）。**
  3. **中｜砍①②（记账/决策门槛减负）**＝降流程摩擦，不涉一致性把关。
  4. **砍⑤ 审计降配 ＝ 不产新价值、是「降 agent 用量」**——能机器化的转守卫后审计量自然降；它是前三刀的**结果**、不是**手段**。
- **一句话**：**先机器化「每夜都漂的那类」（数字/状态/引用一致性），再谈降审计**——v2 的五例频次证据把「跨文件一致性机器化」从「六刀之一」抬成「优先级最高的一刀」。
- **⚠ 自我指涉（诚实标痕）**：五例里**有一例是我的**（F-b「两表」实为四表，v2 当场抓）——这条优先级建议又是「被自己的错误证明了必要性」的实例。**若我自己都在漂，机器化就不是可选项。** 而与砍⑤ 的关系：砍⑤ 说「按可机器化性分流」，本节回答「先机器化哪一类」——**数字/状态/引用一致性排第一，因为它出现频次最高（五例/夜）。**
