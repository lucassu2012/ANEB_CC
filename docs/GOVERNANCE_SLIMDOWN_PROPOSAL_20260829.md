- **⚠ 自反（v3 08-29 报 · 修在提案自身）**：本条**初稿复述**了 badges 键名格式（`gates=N tests_py=M tests_kt=K` 一行机读）——v3 落码实况（`cc41d50` 起）三处不符：①键名实为 `gate_count`/`reflex_tests`；②`tests_kt` 未实现（app 单测数不在链跑可解析行，v3 不写占位）；③非一行、每键两行带 `_source`（§2.17 数字可追源）。**这恰是砍④要治的「文档复述实况 → 实况一变复述就过期」出现在提案自身**——而修法用的正是砍⑤ 第②格的「下游改指针」：已把复述改成"以 `badges.txt` 实际产出为准"的指针，复述会过期、指针不会。**提案能在自己身上示范它要立的纪律，PO 读着更信。**

- **预计节省（量化 · v2 08-29 实测扫仓）**：一个关键数字改一次要同步的处数/文档数——这就是「不做徽章化」每次改数字的同步成本，也是漏同步的风险面：

  | 关键数字（含义） | 出现文档数 | 总处数 |

  | `489`（T46 场景数） | 12 份 | 70 处 |
  | `73 run`（T46 口径 run 数） | 12 份 | 31 处 |
  | `111`（台账 real run） | 11 份 | 45 处 |
  | `n=30`（语音回核级） | 11 份 | 27 处 |

## 4. 砍⑤｜审计降配

- **现行条文位置 = 无成文条文**：根 `CLAUDE.md` 对"审查/审计/多agent/对抗/镜头/抽样"零命中。多 agent 对抗审计目前是**按需的临场实践、非固定纪律**（举证=`BRAIN_TASKBOARD` 的 T46/T67/T79 回执、记忆库"七透镜/六透镜"复盘）。处于**无条文的自由裁量态**——既无"每次都跑"的强制，也无"按需"的授权。
- **修订后条文**（提议加进 CLAUDE.md 或本提案作独立纪律）：
  > 「**多 agent 对抗审计的配额（治理减负 §4，首次成文）**：对抗审计**不是每单必跑**——按下列触发：①交付给 PO 拍板的材料（决策请求/规格提案）；②改评分口径/契约/红线的变更；③交付包定稿前一次。
  > 其余日常任务用"方向性错误"单镜头（一个证伪者）即可，不铺多镜头。**降为按周抽样**：非上述触发的已交付物，每周抽一次做多镜头复核。」
- **预计节省**：把"凭会话判断施加"的重实践（T79 曾 49 agents）降为触发式 + 周抽样，可省大量 agent-token，且不丢关键把关（触发①②③覆盖高风险面）。
- **⚠ 自我指涉**：本会话 v4 对 4.2/4.3 都跑了三镜头对抗核验——按本条这**正是触发①（交 PO 材料）**，合规；但若对每个小件都跑就是过度，本条正是划这条线。**4.3 那次三镜头抓出我五处错（含第五次踩坑）——证明触发①的对抗审计不能砍**，故本条只砍"非触发场景"的冗余。
- **⚠ 判据升级：按「可机器化性」分流，不只按频率降（吸收 v2 实测洞察，08-29）**——审计降配的真正判据不是"多久跑一次"，是"这一类核查机器兜不兜得住"。v2 今晚实测了这条分界（并在我的 F-b 提案上当场抓到一处"两表实为四表"）：
  - **① 能机器化查（存在性类）**：跨文件节号引用/命令引用是否指向**真实存在**的节/脚本——这类**转成常设守卫**（v2 已把"节号引用存在性"守卫提给 v3，是 `test_docs_commands.py` "命令引用的脚本是否存在"的自然延伸），从对抗审计里拿掉，机器每次跑、不耗 agent。**⚠ 自纠**：本条原把"跨文件数字是否一致"也归此类——**错了，v2 08-29 实测推翻**：数字"一致性"查不了（见②），能查的只有"引用的目标存不存在"。
  - **② 查不了「一致性」、但能靠工程「消除需要查」（v2 08-29 补的第三格，我原二分缺这格）**：数字/引用值漂移——机器查不出"这两处该相等"（v2 实测"语义标签+紧邻数字"判据："外场日"标签下 31 个值**全部正当**、假阳性~100%，见 §3 注），但**能靠单一来源让不一致无法发生**：数字徽章化（=**砍④**）、下游改指针。v2 点透：**这不是"退而求其次"，是唯一有效那条**——因为"可查的前提（知道两处是同一个量）"恰恰只有建立单一来源之后才存在。故砍④ 不只是"一刀"，是**这一格的落地实例**。
  - **③ 既查不了、也消除不了**：**"这句事实断言有没有被实证过"——机器认不出哪句是事实断言、哪句是设计意图**，这半**只能靠触发式对抗审计 + 互相核（你核我、我核你、大脑核我们）**，**不能砍**。今晚三次被咬中（v2 的"疑为同批改名"当事实、我的"两表"未逐表枚举、我 4.3 把已订正基线当旧态）全是这半，全靠互相核接住。
  - **一句话（三分）**：①能机器化查（存在性）→转守卫（降 agent）；②查不了一致性但能工程消除→单一来源/徽章化（=砍④，让不一致无法发生）；③既查不了又消除不了（事实有没有实证）→触发式审计+互相核（不降把关）。这比笼统"按周抽样"精确，也回答了"为什么触发①不能砍"——那正是第③格、机器和工程都兜不住的那半。**而 §8 的优先级正是问"②里先做哪类"：数字/状态/引用一致性排第一，因为它漂得最频（五例/夜）。**
  - **⚠ 这条本身又是那句主线的实例**：「引用过教训 ≠ 不再犯它，只有机器守卫兜得住」——而**纪律 8「进裁定材料先实证」本身不是守卫、只是一个人的动作**（v2 原话），下一个人不记得时它一行字拦不住。故能机器化的必须真机器化，不能机器化的必须有互相核这个"人肉守卫网"，两者缺一，纪律就只是一句会被忘记的话。

## 8. 六刀优先级建议（据 v2 一夜五例频次证据 · 大脑 08-29 转接）

- **证据（v2 今夜自查收官的排序观察）**：v2 查到的跨文件问题**全部同一形状——「写对了但后来变了/没对齐」**（一夜五例：v1.0 行号被横幅顶偏、台账扩根后 110 没跟、总计划 7-3/7-5 状态漂移、我的 F-b「两表」实为四表、豆包 §10.3 工时假设与协议 §2 定案不一致）。**共享树多会话并行改互引文档，这形状是常态非例外。**
- **推论**：v3 的节号守卫只兜「引用指向不存在的节」一小类；**数字/假设/状态漂移仍靠人回头查**。若治理减负排优先级，「**跨文件一致性机器化**」的收益 > 再加一层审计——因为它治的是**每夜都发生**的常态形状，而多加审计层只是重复人肉核查。
- **⚠ 增维：按「危害×频次」排，不只频次（v2 第七例，08-29）**：v2 又抓到协议目录名 `doubao_pilot_` vs SPEC-2 判据 `doubao_wave0_` 不一致（`3927444` 已统一）——**频次=1、危害却是最高一级**：若 E-1 解锁后照协议跑，65 轮（豆包批 `e927eb2` 加锚格后定案）产物落进判据不认的目录，**执行完才发现不达标、返工一个设备窗**。由此两点补进优先级逻辑：
  - **漂移危害分两级**：「读者困惑」（读文档的人一时看错、可当场纠）＜「执行返工」（照错的跑完才发现，代价是一个设备窗/一批产物）。故排序应按**危害×频次**，不只频次——`doubao` 这例频次=1 却该排很前。
  - **「判据↔执行件」字面对齐 = ①里 grep 级最便宜的一格、却防最贵那级**：路径/文件名/命令，近乎 `grep` 就兜得住——**因为判据↔执行件本就是一对显式契约**（判据声明期望路径、执行件产出它），"该相等"的前提天生存在，不需先建单一来源。**这正是它与 v2 证过查不了的"数字语义一致性"的分界**：后者没有显式契约说"这俩该相等"，故落②（工程消除）；前者有契约、落①（能机器化查）。投入最小、防的恰是"执行返工"那级——**应排在机器化清单的最先。**
  - **「同文件内两处同一事实」= 比跨文件更低成本的浮现（v2 末条，08-29）**：交付包 L82/L88 那例（同文件两行说同一事实、矛盾七天）——**单文件 `grep` 同主题行即可浮现候选、无需跨文件解析**，成本比跨文件更低，危害同级（都让读者按过期信息行动）。**⚠ 但要诚实划界**：v2 今晚亲证一般"同一事实一致性"查不了（"语义标签+紧邻数字"判据 FP~100%）——精确说法是**单文件能便宜地"浮现候选"，"是否矛盾"的判词仍需配对句柄（共享 ID/字段名约定）或人读**。有句柄→落①的便宜守卫；无句柄→它只是喂给③（人读）的低成本候选浮现器、不是自动判词。**这条边界正是不重犯"给 v3 推假阳性守卫"的那一课。**
- **六刀优先级排序（据频次×危害证据）**：
  1. **最高｜跨文件一致性机器化**＝砍④（数字徽章化，治「数字漂移」）＋ v3 节号守卫（治「引用漂移」）＋ **建议扩到状态/假设一致性**（五例里三例是数字/状态/假设漂移，节号守卫都兜不住）。这是唯一治「常态形状」的一刀。
  2. **高｜砍⑥ worktree 隔离（4.5）＝治漂移的根因**。v2 点明这形状是「共享树并行改」的直接后果；隔离让并行改走显式合并冲突，「行号被顶偏/台账没跟」在合并时对合并者可见，而非事后靠人翻。**4.4 与 4.5 在此汇合：一个治症（一致性守卫）、一个治根（隔离）。**
  3. **中｜砍①②（记账/决策门槛减负）**＝降流程摩擦，不涉一致性把关。
  4. **砍⑤ 审计降配 ＝ 不产新价值、是「降 agent 用量」**——能机器化的转守卫后审计量自然降；它是前三刀的**结果**、不是**手段**。
- **一句话**：**先机器化「危害×频次最高的那类」，再谈降审计**——先做「判据↔执行件字面对齐」（grep 级最便宜、防执行返工那级），再做「每夜都漂的数字/状态/引用一致性」。v2 的五例频次 + 第七例危害证据，把「跨文件一致性机器化」从「六刀之一」抬成「优先级最高的一刀」。
- **⚠ 自我指涉（诚实标痕）**：v2 抓到的例子里**有一例是我的**（F-b「两表」实为四表，当场抓）——这条优先级建议又是「被自己的错误证明了必要性」的实例。**若我自己都在漂，机器化就不是可选项。** 而与砍⑤ 的关系：砍⑤ 说「按可机器化性分流（①能机器化查/②工程消除/③审计）」，本节回答「先机器化哪一类」——**按危害×频次：判据↔执行件字面对齐（①、grep 级、防返工）排最先，其次数字/状态/引用一致性（漂得最频，五例/夜）。**
