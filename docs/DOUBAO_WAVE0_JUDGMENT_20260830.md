## 3. 三条仪器性发现（本批最耐用的产出）

### 3.0 🔴 带内那一格跑起来了——**而 `|t_A − t_C|` 命题本身不成立**

`cell_f2`（蜂窝 F2，6 轮，固定答窗 75.2s）是本批**第一格让 `e2_analyze` 真正执行**的：
**`n=6 dropped=0`**。**判词是 `FAIL`**（我独立复跑复现）：

```
|t_A − t_C| p99 = 19805.8 ms      判据 = 1 帧 = 16.667 ms      差三个数量级
逐轮 t_A − t_C: −17913 / −19806 / −16841 / −16205 / −14330 / +3306 ms   ← 符号会翻
```

**这 20 秒不能推给时基**：`wall_to_boot` 残差 **p50 0.26ms / max 7.06ms**（n=2250）、
`clock_pin` 漂移 **1563ns**、`turn_method=operator-marks`。**钟是好的。**

⇒ **这是「A2 是语义事件」那条判断第一次被量出来**：**A 的第二簇落在思考静默之后，
C 的第二簇要等长流式结束才出现——两条通道各自指认了不同的事件，差 15–20 秒。**
**符号会翻尤其要紧**：**若是固定偏置（标定问题），符号不会翻**；翻了说明
**两侧各自锚在什么事件上是随轮变的**。

⇒ **本页结论就此升级一级**：**「适用带窄」讲的是能不能跑；带内这一格讲的是命题本身。**
**e2 的问题不止是常跑不起来——在跑起来的那一格，`|t_A − t_C|` 依然不成立，
量级是判据的三个数量级，符号还会翻。**
**⇒ 修门限、加轮数、换负载都不解决它**：那是**两个不同事件之差**，不是精度不足。

> **⚠ 2026-08-30 补正（`tools/e234/e2_precheck.py` 落地后）：上面这段的「两个不同事件」
> 是候选之一，不是已证；最后那句要撤回。**
>
> 本格 C 侧的 >400ms 间隔里，**12 个跨越确证丢帧的边界、只有 9 个可核**
> （`e2_precheck` 对本格判 `NOT_EXECUTED`：记录太碎）。原因是
> `SurfaceFlinger --latency` 的环缓冲**恒深 127 帧**、满帧率下只覆盖约 2.12s，
> 而采集器按 **20s** 周期 dump ⇒ **两次 dump 之间的帧永远丢了**。
>
> 于是有**第二个机制给出同一种形状**：「C 的次簇＝长流式结束」与
> 「C 的次簇＝**dump 停止观测的那一刻**」都产生一个大的负差。
> **「符号会翻」也分辨不了两者**——洞的位置逐轮不同，同样会翻符号。
> 我当时拿符号翻转排除了「固定偏置」，**那一步没错，错在把「非固定偏置」直接读成
> 「语义事件之差」**：被排除的候选之外还站着另一个，而它当时不在视野里。
>
> **⇒ `FAIL` 不撤**（p99 19805.8ms 是量出来的）；撤的是**因果断言**，以及
> 「修门限、加轮数、换负载都不解决它」——**改采集周期可能解决它**。
> **⇒ 判别实验（单变量）**：`--framestats-period-s` 由 20 改到 1 后复跑同一格。
> 仍是十几秒量级 ⇒ 语义事件说成立；塌到帧级 ⇒ 之前量的是**采集排期**。

### 3.1 `e2` 只在一条窄带里成立，两种失败模式方向相反

同一个 **400ms 间隙门限**同时服务两条节奏差一个量级的流：A 是 **~100ms 事件流**、
C 是 **~167ms 帧流**。于是——**短负载让 C 切不出第二簇，长负载让 A 切不出**。
而 `e2` 要求同一轮里两侧**都** ≥2 簇 ⇒ 它只在**中等长度且带停顿**的负载上成立。
本批 F1（短答）与 F2（长答）恰好落在这条窄带的两侧。

**这不是轮数、采样周期或提示词的问题** ⇒ **加轮数只对 C 侧失败有效**，**对 A 侧无效**。
⚠ **而落在哪一侧随「功能 × 条件」变，不是功能的固有属性**：同一个 F1，
**WiFi 下瓶颈在 C**（丢 2/6，A 从不失败）、**蜂窝下瓶颈在 A**（丢 5/8）。
⇒ **不得按功能下「可解/不可解」的断言**，逐格看 `drop_reasons` 落在哪侧（详见 §7-1）。

### 3.2 簇分割失效**不止杀掉 e2，还污染主量本身**

`ttft_cluster_ms` 与 `e2` 的 A 侧**用同一个 `CLUSTER_GAP_NANOS`、同一条事件流**
（`ec.cluster_gap_nanos()` 从设备端 `ObsStats.kt` 取值）。⇒ **A 侧切不出簇的轮次，
其 `ttft_cluster_ms` 量到的不是 TTFT。**

**实证**：`cell_f1` 宿主侧只有 **3/8 轮** `a_clusters ≥ 2`，而其 `ttft_cluster_ms`
呈 **4 个 ~15.6–15.8s ＋ 3 个 ~2.6–3.0s** 的两极分布。
**⚠ 本页初版把两者写成「一一对应」，那是过度断言，已订正**——**两侧口径无法逐轮配对**，
我当时是拿聚合形状去凑（4+3 个值 vs 3+5 轮，连数都对不上）。
**⚠ 订正之二（理由本身也错过一次）**：初版把不可配对的原因写成「设备侧是**会话累计快照**」，
**该说法对 `ttft_cluster_ms` 不成立**——`ObsStats.kt` v3.1/v3.2 明写「**输入框活动重置簇状态**」
（v3.2 收紧为仅 `textLen>0` 真实打字才重置）⇒ **它是逐次发送的**。
**正确原因是「两侧的轮界定义不同」**：设备侧按**输入活动**切、宿主侧按 `turn_method` 切
——**同名不同义**（D-326）。写成「会话累计」会让后来人以为该字段不能逐轮用，
而它其实逐发送可用，只是**与宿主侧的轮对不上**。
（`events`／`cadence_p50_ms` **确为会话累计**，实测单调 5→8→11→14→17→20；
**三个字段的重置语义不同，不可一并处理**。）
**另一条实测，它排除了一个候选成因**：四个高值是 **15.6／15.6／15.7／15.8**，
**跨度仅 0.2 秒**——网络造成的时延不会四次重复在 200ms 内，故更像某个固定量。
`ObsStats.kt` 注释记着一个同量级的脏值签名（`ttft_cluster=16145ms`，成因＝**簇窗未重置**），
**但实测不支持它**：`rule_matched/events` 在 `wifi_f1` 为 0.14、`cell_f1` 为 0.11，
**两者相当而只有后者出高值**。⇒ **该候选被排除，成因仍未判定。**
**⚠ 订正之三（本页最重要的一次收窄）**：初版写「一个都不能单独采信」——**过头了**。
**设备侧可以逐轮配对**：`AnebE4MARK` 与 `ADAPTER_OBS` **在同一条 logcat、同一个墙钟上**，
按 `turn_start` 切窗即可归轮。**我先前说「无法配对」，那不是数据的性质，
是我解析器的局限**——`parse_adapter_obs` **不投影时间戳**，而原始行自带墙钟前缀。
**正确表述：不能与宿主侧 `a_clusters` 配对**（那是另一句话）。

**🔴 归轮必须归事件，不能归播报**（本批实测，通用规则）：`ADAPTER_OBS` 是
**活动驱动 + 约 5s 节流**——第二簇形成后若该轮再无内容事件，**就不再发 OBS**，
直到下一轮打字才恢复。实测四个高值的播报偏移是 **+0.20 / +0.04 / +0.09 / +0.11 秒**
（正常值为 +5.0～5.4s）：**`turn_start` 后 40 毫秒时那一轮还没打字、更没发送**
⇒ **该值描述的是上一轮**。⇒ **高值归轮 2/3/6/7，不是播报所落的 3/4/7/8。**
**播报时刻与事件时刻可差 7 秒以上，差多少取决于之后有没有活动。**

**两个「工具伪影」候选均已被否证**（否证连同候选一起留在这里——**它们量级都对得上，
下一个人一定会重新捡起来**）：
1. **簇窗未重置**（`ObsStats.kt` 注释记的 `ttft_cluster=16145ms` 脏值签名）：
   若未重置，`first`/`second` 停在旧值 ⇒ **该值会重复**。而四个高值
   **互不相同**（15558.4/15636.6/15719.1/15754.8）⇒ **每一轮都重置过**。
   （我原用 `rule_matched/events` 比值否它——**那是拿会话级证据否一个逐轮假设，
   层级不匹配，即使结论对也是运气**；已换用「值是否重复」这条逐轮判据。）
2. **采集侧固定节拍**（驱动器答窗恒 ≈17.4s，高值恰低它 1.6–1.9s）：三条独立否证——
   ①`wifi_f1` **同一驱动器同一 17.4s 窗，零高值**；
   ②**离散度不能小于造它的那把尺的抖动**：答窗抖动 ≈600ms、轮期 ≈570ms，
   而四个高值跨度仅 **196ms**，**比造它的模具还稳三倍**；
   ③播报晚的形状在**没有高值的 `wifi_f1`** 上同样出现 ⇒ 那是播报机制、不是高值成因。

**🔴 判决性重测：阴性——双峰未复现；但成因仍未判定。**

`cell_f1b`：同功能、同条件、同提示词，**只把答窗 17.4s 改成 45s**，6 轮。
**ttft 全部出现（含重复）9 条，值域 3626.8–4161.1 ms，`>10000ms` 的 0 条。**
按 `cell_f1` 的 4/8 高值率，6 轮全不中的概率约 **1.6%**。
（**特意查了含重复的全量**：「取变化点」会滤掉重复的高值，不能只看不同值就宣布消失。）

**⚠ 但不能据此归因——该检验一次改了两个量**：答窗（17.4→45s）**与时段**
（两格相隔约一小时，射频未受控）。⇒ **两个候选仍并列**：
①高值与答窗有关；②高值是真实的、随时间变化的现象，这一格没赶上。

**✅ 被干净排除的是一个具体机制**：「**第二簇由答窗关闭那一刻触发**」。
若成立，45s 窗下的值应挪到 **≈43s**；**实际它回到了正常 TTFT（3.6–4.2s）**。
⚠ **本页前一版把「17.6 vs 17.4」当成窗因果的证据、并写「已判定为伪影」——那是错的**：
**这次检验恰恰排除了那个机制**，而我把一次阴性重测读成了对某个具体成因的证成。
**这正是本页两版前自己写下的那条——「否掉候选不等于证成第三个」——的反向重犯。**

**⚠ 「第二簇形成于 ≈17.6s」是个过度精确的数，真值是区间**（采集侧交出误差后订正）：
它由「重置时刻 + 15.636s」推得，而**重置时刻只有 5 秒分辨率**（OBS 5s 节流：
`+0.04s` 那条仍是旧值、`+5.17s` 那条才转 null ⇒ 重置 ∈ (0.04, 5.17]s）
⇒ **第二簇 ∈ (15.68, 20.81]s**。

在一个 ±2.5 秒的区间里不构成证据。**

#### 🔴 四订（v2 对抗核查 + 我方独立复核）：**成因已判定＝400ms 门限切在单峰连续量的正中**

**本节此前一直写「成因未判定」。现在判定了，而且它不是「双峰现象」，是阈值伪影。**

**① 触发量在 400ms 处没有断层——我独立复核，与采集侧数值逐个吻合。**
逐轮取 A 侧内容事件的**最大相邻间隔**（那正是决定该轮切不切得出次簇的量），全批排序：
`… 383.0 / 389.2 / 389.7 ‖ 400.6 / 403.8 / 411.4 …` —— **400ms 恰好落在一段连续分布的正中，两侧毫无断层。**
最刺眼的一对在**同一格内**：`cell_f1b` 轮5＝**381.3ms**、轮2＝**403.8ms**，
**相差 22.5ms，而读数差 45 秒。**
门限扫描同样是**单调迁移**（我复跑：`cell_f1` 能切出次簇的轮数 200ms→8/8、400ms→3/8、700ms→0/8）
——**单调连续迁移是阈值伪影的签名，不是双峰现象的签名。**

**⇒ 高模轮量的不是 TTFT，是「渲染流里第一次停顿超过 400ms 的时刻」；
在没有这种停顿的轮里，它退化成驱动器下一次点屏的时刻。**
这也解释了本页一直没解释的那件事——**为什么 `wifi_f1` 零高值**：它六轮的最大间隔最小值是
**483.9ms，全部在 400 之上** ⇒ 每轮都早早切出次簇 ⇒ 全落低模。
**「高模」标记的其实是渲染最顺、一次卡顿都没有的那些轮。**

**② 🔴 `null` 是个合并 token —— 本页多处「无高值」因此不成立。**
`ObsStats.kt` 里 **`TTFT_CEILING_MS = 30_000.0`**，私有函数 **`sane()`** 把 **>30s 的值转 `null`**，
且簇代理那一路（`secondClusterStartNanos - firstClusterStartNanos`）**经过它**。
（**锚在符号名上，不写行号**——本仓明令，且错行号不报错、只指向别的行。
复验：`grep -n "TTFT_CEILING_MS\|fun sane\|sane(" app/probe/src/main/java/com/aneb/probe/adapter/ObsStats.kt`。）⇒ 日志里的 `null` ＝「没形成次簇」**或**「形成了但 >30s 被删」
**或**「形成了但没播报」——**三者长得一模一样。**
**⇒ 上面那句「✅ 被干净排除的是『第二簇由答窗关闭那一刻触发』」必须撤回**：
它的论据是「45s 窗下 `>10000ms` 的 0 条」，而那是**一个被截断过的样本**——
**「没记到高值」与「没发生高值」在这份日志里不可区分。**
⚠ **撤回的是那个排除，不是反向证成**：我**没有**证明该机制成立。
（采集侧报 `cell_f1b` 轮1/轮5 的被删值为 **49470.3 / 49459.0**；
**我宿主侧重算得到的是 2172.6 / 1903.5，复不出那两个数**——
两侧本就在算不同的量（设备侧按输入活动重置、宿主侧按标记切轮，本节开头即记此事）。
⇒ **那两个数在有人交代其算法出处之前，别引。** 但**撤回不依赖它们**：
只要 `sane()` 存在，我那条排除的论据就已经不成立。）

**③ 我那条「比造它的模具还稳三倍」的论证，作废——而作废的理由不是算错。**
分母确实取错了：我拿 4 个高值的跨度（196.4ms）去比**全 8 轮**的答窗极差（604.0ms）。
**同 4 轮（2/3/6/7）的答窗极差实测 413.0ms ⇒ 比值 0.48**，仍比 1 小
（⚠ 采集侧报 201ms／0.98，**我复核为 413.0ms／0.48，两数不一致，量法待对齐**）。
**但真正让它作废的是另一件事**：我用的那条规矩「**被造物不可能比造它的模具更精确**」
**自带一个边界——边沿触发时不成立**，而我给它加的限定是「**先确认那个边沿有物理介质**」。
先前我据此驳回过一个候选（对方拿一条纯 logcat 写入当边沿，没有介质）。
**现在这个边沿有介质了**：渲染流里一次真实的 >400ms 停顿。**⇒ 边界条件成立，该论证不适用。**
**——我不是用错了场合，是用对了场合而漏验前提；而这正是我两版前给自己写下的那句话。**

**④ 仍未判定的：低值轮的语义。** 核查明确否掉了「整列都不是 TTFT」这个强断言。
⇒ **可写「高模轮的值不是 TTFT」，不可写「本批 ttft 全不可用」。**

**⇒ 当前状态：形状一，未复现一次，四个候选中三个排除，成因未判定。**

**限定用对了地方，却用在了不满足其前提的边沿上**——前提要单独验，不能因为
「机制看起来像边沿触发」就默认它成立。

**⇒ 既不能判成伪影，也不能判成真现象。**
**排除候选积累的是「不是什么」；一次阴性重测直接削的是「它在不在」——两者不可互相代替。**

**下批的正确设计（采集侧提，本页采纳入 §7）**：**同一格内交替两种答窗**
（奇数轮 17.4s、偶数轮 45s）⇒ **时段被摊平在两组之间**。
采集侧自评一句值得留下：**「我把两组放到了不同时段，于是省下的每一分钟
都换成了一个无法排除的混淆。」**

**代价（改变 `cell_f1` 的可用范围）**：高值那几轮回答在 ≈15.7s 才开始，
而驱动器 17.4s 切走 ⇒ **那几轮的回答在开口约 1.7 秒后被截断**。
⇒ **TTFT 可用**（事件发生在截断前），**但那几轮的流式/节奏/通道 C 数据是截断的**，
**不可用于任何「回答有多长/多稳」的判断**。**17.4s 固定窗对 WiFi 够、对蜂窝不够**
——这本身也是一条实测。
**若不看逐轮簇数，这组值会被读成「5G SA 下 TTFT 高达 15 秒」这个惊人而错误的结论。**
⚠ **凡引本批任何簇相关的数，必须写明它数自哪一侧**（设备侧 `ObsStats` / 宿主侧 `v3_anchors`）
——同名不同义（D-326），而两侧对 `cell_f1` 给出的簇成立轮数相差一倍以上。

### 3.3 通道 C 的**原始**帧数是饱和量，不可用

`wifi_f2` 与 `cell_f1` 的原始帧数**恰好都是 3717**——两次独立运行精确相等。
**机制比「顶到上界」更简单也更狠**（采集侧独立核出）：`dumpsys SurfaceFlinger --latency`
**每次固定返回 127 行帧**，采集器按 `--framestats-period-s`（默认 20s）周期 dump ⇒
**原始帧数 ＝ 127 × dump 次数**，逐格对得上（`wifi_f1` 21 次×127＝2667、
`wifi_f2`/`cell_f1` 各 30 次×127＝3810）。两格相等**不是巧合也不是饱和**，
**是同一个 session-seconds 给出同样的 dump 次数**。
⇒ **原始帧数恒为采集排期的常数，不含该场会话的任何信息，永远不能作为任何东西的证据。**
**去重后为 1730 与 1177**（重复 1987/2540）——**凡引通道 C 帧数，必须用去重后的数。**
（我数 3717、采集侧数 3810，差 93 ＝ `e2` 过滤掉的无效行；**两个数各自对，口径不同**。）
（这与采集侧那条「行数不等于帧数」是同一族**再深一层**：**去重前的帧数也不等于帧数**。）

## 4. 能给的数，与它们的口径

**只有 `wifi_f1` 的 A 侧簇分割全部成立**（A 簇/轮 ＝ 4,2,2,4,2,2），
其 `ttft_cluster_ms` 不同值为 **431.5 / 1977.7 / 2944.6 / 3291.6 / 3936.7 ms**。

**但它仍不能当作「F1 的 TTFT」**，两条限定缺一不可：

1. **⚠ 选择偏倚**：把别的格里「簇分割成立的轮」挑出来看似可比，但
   **簇分割成立与否与该轮回答自身的节奏相关**（有停顿才切得出）⇒ 成功轮**不是随机子样本**。
   **可以报「这些轮的值是多少」，不能报「该功能/该条件的 TTFT 是多少」。**
2. **⚠ 提示词口径**：F1 问的是 **「What is 5G in one sentence」**——**一句话**，
   实测流式仅 **7.9 秒**（战役计划 §10.2 估 30s，高估约 4 倍）。
   ⇒ 这些数刻画的是**「一句话回答」的诉求**，不是「文本对话」一般情形。
   **横向比较里含提示词这个我们自己定的变量**：F2 要深度思考、F1 只要一句话，
   **「F2 比 F1 吃网络」可能只是「F2 的提示词要求更长回答」**。

**故本页不给任何 TTFT 的功能级或条件级结论。**

## 4b. 一条跨格观察，与一条**因为窗长而作废**的对比

**⚠ 作废**：F2 的「次簇形成率」跨条件对比（`wifi_f2` 2/6 vs `cell_f2` 6/6）**不可用**
——两格轮期为 **45.4–49.1s vs 75.2–75.3s**，**观测窗长 53%**，而窗越长越容易出现
> 400ms 间隙。**这是我们自己调的参数进了结论**（答窗长度既是「防截断」的旋钮，
也是「次簇率」的分母）。要拿回该信号：同窗重跑，或改用**对窗长不敏感的密度口径**
（每分钟间隙次数），后者不必再烧一格。

**✅ 仍成立的一条，且理由在于混淆的方向**：**`cell_f2` 五个 ttft 值全在 2.9–3.9s，
无 ~15s 高模**。窗长只会让长 TTFT **更容易**被看见，**不可能把已存在的高模藏起来**
⇒ **「高模缺席」这条不受窗长影响**。⇒ **~15.7s 只在 F1 上出现，F2 上没有。**
**⚠ 但 F1 与 F2 两块相隔约一小时，时段与射频未受控**，该观察带此限定。
**（判断一个混淆是否致命，要看它的方向能否产生所观察到的效应——
这里它只能反向作用，故结论幸存。）**

**⏳ 待判决的直接检验**：采集侧正在跑 `cell_f1b`（F1／蜂窝／答窗 45s ≈ 15.7s 的三倍）。
判据：**高模仍落在 ~15.7s ⇒ 与答窗无关，坐实；跟着窗长跑到别处 ⇒ 是采集侧造的**。
**此前三条否证全是间接的，这一格是直接的**——出数后本页据实更新。

## 7. 给下一批的三条（按代价排序）

1. **按「功能 × 条件」排，不按功能排**（本页初版按功能，**错**——采集侧逐格 `drop_reasons`
   证明**失败侧随条件翻面**）：

   · **`F2/WiFi`：A 侧受限**（丢 4/6）⇒ 同上。
   **同一个功能在两个条件下的瓶颈不在同一侧**——我初版只看了 WiFi 那格就下了「F1 可解」。
2. **把 e2 的适用性做成开跑前可验的前置断言，而不是跑完才知道的「窄带」**（采集侧提）：
   判据＝**「该 App 在思考期，两条通道须同时静默」**。仓里已有反例——`ObsStats.kt` 注释记着
   **思考期播放生成动画的栈**（DeepSeek：持续 CONTENT、无 >400ms 静默 ⇒ `ttftClusterMs=null`）：
   **画面在动 ⇒ C 永不静默 ⇒ 门限取什么都没用，C 的次簇根本不是 A2**。
   ⇒ **同一把尺是必要不充分条件**；该断言**用现有 `sf_latency` 帧序列 + 通道 B `roi_mean`
   即可先验，不必先烧一格**。**边界描述要升级成判据才算产出。**
   **✅ 已交付（2026-08-30，大脑派 ②／D-595⑥）**：`tools/e234/e2_precheck.py`，
   用法见 `scripts/README.md` 速查表第 3a 步。**落地时发现判据要分两层**——
   在「App 静不静」之前还有「**这套装置看得见静默吗**」，而本批五格里三格卡在后者
   （见 §2 表后两列与 §3.0 补正）。**只写前一层的话，工具会把采集排期的洞判成 App 的停顿。**
3. **用单变量实验 settle 双峰**（采集侧提，本窗额度不足）：**发送后 60 秒内不做任何操作**，
   看第二簇是否仍在 ~15.7s 形成。**不导航就没有第二簇 ⇒ 导航是成因；照样有 ⇒ 是真的。**
   **它是单变量的，且不必等到网络变慢**——比「换答窗重测」干净（那次一改两个量）。
4. **先在 F5/F6 各跑一格定位窄带的正例**：F5 有检索往返（可能给 C 一个天然停顿）、
   F6 是长等待后出图（A 事件稀疏、C 末端突变）——**有正例的边界描述，比只有反例的强得多**。
5. **要 F1 的 TTFT 有代表性，得换一条不指定长度的提示词**——
   当前这条把「一句话」写死在了工作负载里，而结论会被读成整个功能的性质。
