## 3. `e1_analyze` **不能**离线补出 F1 的通道 A（实跑证伪，非推断）

采集协议 §723 写「F1 的价值在通道 A 的 TTFT／cadence 与通道 B」。核实结果分两半：

- **产物面**：三个豆包证据目录里**零个 e1 产物**（两种独立量法交叉，且同一条 `find` 命中 e2 产物八条＝量法自证可用）。跑器 `tools/e1/` 在仓里 ⇒ 是**没跑**，不是没工具。
- **实跑面**：`e1_analyze.py --run-dir …/cell_f1 --stim-file stim_pre.log` **rc=0**，但判词
  **`channel_a=NOT_EXECUTED channel_c=NOT_EXECUTED`（「无可用样本」）**。
  成因＝**判读器答的不是这个问题**：e1 是「**已知真值刺激**」实验的判读器，它把格里的
  `stim_pre.log`（采集前自检刺激，6 次翻转）当成刺激源，而通道 B 在真实会话里检出 25 次。

⇒ **「工具在、原始日志在」≠「结论能补出来」。** 正文不可承诺「F1 可离线补分析」。
（通道 B 那一列倒是 PASS：采样周期 p50 1500.3ms、n=400——但它按设计**不报时间误差**。）

## 4. **A 单元（TTFT）不是空的——是没人分析过**（本文最要紧的一条）

`ADAPTER_OBS` 里有三条 TTFT 代理。全批（wave0 290 行 ＋ DW-01/wave1 111 行）实测：

| 代理 | 非 null | 读法 |
|---|---|---|
| `ttft_send_ms`（发送锚定法） | **0 / 401** | 该法在豆包**全批失效** |
| `ttft_cluster_ms`（v3 簇分割法，D-52 原法） | **186 / 290**（wave0） | **有数据，可作正文 A 单元底数** |
| `ttft_density_ms`（密度谱法） | 9 / 290 | 样本太少，不入正文 |

**`ttft_send_ms` 全 null 的成因不是在册的那个。** 源码注释记着真机实证
「百度输入法把 `com.larus.nova` 观察切成两段／8-1-8 三段，`ttft_send_ms` 恒 null」，
但那两条豁免（IME 全事件豁免 `560f5a7`、systemui 豁免 `e0a9c12`）都落在 **2026-07-18**，
比 08-30 采集**早六周** ⇒ **切段解释已被修复堵掉，本批全 null 另有成因，未归因**。
佐证：`anchor_source` 全批 **220/220 = null**（一个发送锚都没建立）。

⚠ **一个键名差点骗到我**：`reason=throttle` 出现在 401/401 行上，读起来像「适配器被限流降级」。
去源码核（`AnebAccessibilityService.kt:213`）：它是**定时播报的触发原因**
（`if (now - lastEmitNanos >= EMIT_INTERVAL_NANOS) emit(now, reason = "throttle")`），
**不是降级信号**。正文引用 `confidence=LOW/INCONCLUSIVE` 时不可把它归因于 throttle。

## 5. cadence（播报节奏）分布：**F1 单峰，F2/F5/F6 多一个低峰**

`ADAPTER_OBS.cadence_p50_ms` 去重取值（wave0）：

| 功能 | 分布形状 |
|---|---|
| F1 | **单峰 ~100ms**（99.3–101.8，另有 48.5／92.5 各一） |
| F2 | **双峰**：100–112 ‖ **13–24** |
| F5 | **以 13–22 为主**，~100 仅 2–3 个 |
| F6 | 混合：~100 与 21–45 |

**~100ms 是实测不是配置回声**：取值在 99.3–101.8 连续抖动而非恒等于 100.0；
它与 D-52/D-54 写进 `doubao.yaml` 的 ⚓ 锚 `cadence_ui_ms=100` 一致，属**独立复核到同一值**。

⚠ **不可把低峰读成「该功能下行更快」**：`cadence_p50_ms` 量的是**无障碍事件间隔**，
不是 token 间隔。13–24ms ≈ 60 次/秒，更像**非流式的 UI 活动**（搜索结果卡片／图片渐进渲染）
产生的事件爆发。要区分这两种解释需要通道 D 的字节时序，而**通道 D 本批未采**。
