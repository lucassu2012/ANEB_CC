## §2 Blocking（落地前不开窗）

1. 【S0 的通过条件在实现上不可达，必须改成具名的收尾状态判据】§1-1 写「`error != 0` 一律 NOT_EXECUTED」，§1 末尾把 S0 定为「计数 0 **且** `error == 0`」且「这一格不过整轮作废」。但 `rx()` 的 `while d.WinDivertRecv(...)`（第 159 行）只能因 Recv 返回 FALSE 退出，而正常收尾路径就是主线程 `WinDivertShutdown(h, BOTH)`（第 166 行）⇒ **干净退出时错误码必然非零**；`error == 0` 唯一对应的是线程仍阻塞在 Recv 里，而 §1-2 把那个状态也判 NOT_EXECUTED。两条联立无解。改法（可逐条核对）：①主线程置 `shutting_down=True` 后再 Shutdown；②读线程在 Recv 失败处**同线程**立刻取错误码（下见第 8 条的 use_last_error），与 `shutting_down` 一起返回；③每格印 `count=n shutting_down=X term_err=Y`；④S0 期望改写为「`count==0` 且 `shutting_down==True` 且 `term_err` ∈ 收尾码集合」，其余一律 NOT_EXECUTED；⑤`is_alive()` 为真时**不要** Close 句柄，记 NOT_EXECUTED 交 finally 的服务级清理。不改这一条，第一格就会把整轮判作废，或者更坏——操作者当场即兴写一条例外，预登记当场失效。

2. 【身份三元组缺 `ip.SrcAddr`，§3 第 1 行因此把两个含义相反的世界并成一行】§1-3 定的身份是 `(recvLen, ip.ID, icmp.seq)`，**恰好回避了唯一能分开 NAT 前后的那个字段**。在 C1 上：若同一数据报在 NAT 前后各被呈现一次，recvLen 与 icmp.seq 不变、ip.ID 通常也不被 NAT 改写 ⇒ 三元组相同 ⇒ 去重 20、重数 2 ⇒ 触发第 1 行「同一批包被呈现两次（真正的 2×）」。但这与「同一点上 clone＋reinject」对整形器的含义完全相反：前者下 divert 句柄在第一点摘走并重注入，包会在第二点再被呈现一次、再延迟一次 ⇒ **延迟翻倍而看起来像整形生效了**，正是页首自己写的那个失败模式。改法（全部 layout-free，只读包缓冲，不碰 WINDIVERT_ADDRESS，与 §1 的刻意选择不冲突）：每包记录改为 `ip.SrcAddr(12..15) / ip.DstAddr(16..19) / ip.ID(4..5) / TTL(8) / icmp.Type(IHL+0) / icmp.Id(IHL+4..5) / icmp.Seq(IHL+6..7) / recvLen`，逐行进 stdout 逐字副本；§3 第 1 行拆成两行并跑前写死：`三元组相同且 SrcAddr 相同 ⇒ 同一点被呈现两次`、`三元组相同而 SrcAddr 不同 ⇒ 同一数据报在两点各一次（H1 形态）`。

3. 【身份解析器没有正对照，而 S0 的 `false` filter 保证它一次都不会被执行】§3 第一判就是身份，§1-3 的按偏移取字节是全新代码，S0 只验证了计数通道——`false` 永远不匹配 ⇒ 解析路径零次执行。偏移写错的两条具体后果都在判定表上：得到约 40 个互不相同的三元组 ⇒ 触发第 2 行「根本不是倍增 ⇒ 原问题本身提错了」，分解就此关闭；或读到 icmp.Id（同一 ping 进程内恒定）⇒ 去重 1 或 2，**表上没有小于 20 的任何一行**，只能现场即兴。改法（零设备、零提权、不加载驱动，纯字节解析，可做成 pytest 钉住）：跑前把解析器喂三组合成包并定为与 S0 同级的门（不过即整轮作废）——①20 个 `(ID, seq)` 互不相同 ⇒ 去重 20、重数全 1；②同一包复制 20 份 ⇒ 去重 1、重数 20；③只改 icmp.Id 其余字节不动的两个包 ⇒ 去重 2（证明 Id 确实**不在**键里，同时钉住第 2 条的新字段）。合成包须同时覆盖 Windows 侧 60 B 与 Android 侧 84 B 两种形态，IHL 一律由首字节低四位算出。另加一条跑中结构自检：观测到的 seq 多重集须落在 `1..N_PING` 内且覆盖 ≥18 个不同值，否则该格身份判 NOT_EXECUTED 而不是读数。

4. 【全部期望值是「约 20／约 40」，没有区间也没有样本量推理；而落进中间行会静默作废六格，此时 PO 的一次性干预已被花掉】这条直接撞项目已采纳的房规（「about 20 不是判据」）。更要紧的是 §3 第 123 行写明「构成**仅在身份判为「呈现两次」时才有意义**」——一次完全平常的读数（设备掉 1 个包＋一个背景 ICMP 混进来＋2 秒收尾宽限截掉最后一次目击 ⇒ 去重 21、重数 {2:19,1:2}）就落进「介于两者之间」，I1/I2/F1/F2/N1/N2 六格同时失去解释，而 §4 那个必须排在所有 FORWARD 格之后、要 PO 亲手关热点的干预已经消耗完。改法：按每格实印的发包数 T 跑前写死接受区间，风格照 D-851（n=200、精确二项带 [4,16]）——「呈现两次」⟺ 去重 ∈ [T−2, T] 且重数恰为 2 的占比 ≥90%；「不同的包」⟺ 去重 ∈ [2T−4, 2T] 且重数 1 占比 ≥90%；并补上现在完全没有的两支：去重 < T−2 怎么判、去重 > 2T 怎么判。同时把「构成只在第 1 行才有意义」这个耦合解开（改成对第 2 条那份每包日志的事后查询），让 §4 不与身份判定共命运。

5. 【§4 那个判决性干预，没有任何东西测量它是否真的发生，而被反用的 P2 守卫是 fail-open 且看的是另一台机器】§4 的整个价值压在一个 PC 侧状态（ICS／移动热点已关）上，§5 给它的前提却是把**设备侧**出口检查反过来用。两处都不成立：(a) 「手机出口不在热点上」在手机连了任何别的 WiFi 时都满足——D-880 记的正是这件事真的发生过——而 PC 的热点可以完全照开；(b) `judge_egress`（第 122-142 行）的安全性是**方向相关**的，它对读不到的输入一律 `ok=False`，`test_empty_or_garbage_is_rejected` 把空串／空白／`error: device offline`／有 via 无 dev 四种钉成拒绝，理由写的正是「缺席不等于通过」——一旦取 `not ok` 作前提，这四种输入**全部变成通过**。于是：PO 以为关了热点而实际没关（Windows 移动热点静默失败），同时手机息屏或 adb 抖一下 ⇒ 无输出 ⇒ 反向前提「通过」⇒ A 在热点仍开着的条件下跑出约 40 ⇒ 逐字判「仍约 40 ⇒ **确**为不同因」。一次运行、一个比特，而那个比特是仪器没跑出来的，输出里没有任何一行能暴露它。改法：判决性读数搬到 PC 侧、由脚本在该格**前后各印一次**进逐字副本——热点腿是否存在／Down、`Get-NetIPAddress -IPAddress 192.168.137.1`、ICS（SharedAccess）服务状态，外加 PC 自身到目标的路由仍在以太腿；预登记「PC 侧读数不是『热点已关』即该格 NOT_EXECUTED」。设备侧只作旁证且必须三态化（ON_HOTSPOT／OFF_HOTSPOT／UNREADABLE），**UNREADABLE 在两个方向上都判 NOT_EXECUTED**，绝不能满足前提。

6. 【F2 从未被证明能非零，而 §3 把它的 0 读成「H2 被反证」】F1/F2 是 H2 在转发层的唯一判据，但没有任何测量证明 `ifIdx == <热点腿>` 在 NETWORK_FORWARD 层**能**命中：sweep §3-2 记的是「`ifIdx == 9` 与 `ifIdx == 13` 在该层**都能编译**」——编译得过 ≠ 那个字段的语义是你以为的那个，正是 D-879 的形状；而 sweep §2 自己把热点腿标为「C 格的**入口**」，F2 要的恰是到达接口。§1b 已经把这个常量从写死改成现场推导并编译自证，那解决的是「打偏」，不是「这一层暴露的是哪个接口」。跑出 F1≈40／F2=0 时 §3 逐字判「集中在一条腿 ⇒ 不成立」，证据里于是多一条听起来很实的「H2 已在转发层被实测排除」，而这个读数在 H2 为真的世界里一模一样。⚠ 我不建议用合成 `WINDIVERT_ADDRESS` 喂 EvalFilter 去补这个对照：上一轮 README §3b 的方向语义那三行自述是「验证我对布局的猜测」，用它判 ifIdx 等于把你 §1 刚刚设计掉的那个版本假设请回来，而且 False 会在「字段语义」与「我的布局猜错」之间歧义。改法取零成本那一支：把守恒式 `F1 + F2 == C1` 定为首要判别器（它精确、与 n 无关、能把误分变成可检测的不一致），并跑前写死「`F1 == C1` 且 `F2 == 0` ⇒ **不可判**：在『H2 不成立』与『转发层只暴露一个接口索引』之间歧义，本轮答不了」，同时在 §2 写明转发层暴露的接口语义未经本方实测。

7. 【impostor：I=0 没有任何预登记判词，而 `≥5` 是上一轮的活性门槛被搬来判一个构成命题】两处独立的缺口。①§3 只写了 `I1／I2 ≥ 5` 一支，**I=0 完全没有判词**——跑出 0 时读者会退回 sweep §3-1 的措辞「它就是为这个问题造的」，在证据里记下「重注入已排除」，而 sweep §2 实测在包路径上 Running 的 360netmon／WFPLWFS／VfpExt／vwififlt 一个都没被这条读数排除；同时 sweep §6「不去碰 360」那一行的排除理由就悬挂在这个未被测量的字段语义上（**处置本身是对的，理由此刻不成立**）。②5 不是为这个问题推出来的：它来自上一轮判据「判『>0』的门槛取 ≥5……**5 个给出方向而不给出精度**」与脚本第 56 行 `HIT = 5`，一个自述不给精度的活性门槛；而「第二次目击**来自**其他驱动的重注入」要求的是约一半的目击（40 里的 20）。I1=6、A1=40 会原样触发那条规则，40 个目击里 34 个完全没被解释——正是 D-851 裁过的形状。改法：把 `≥5` 退役（并在判据里写明它的来历），改成对同窗计数的占比区间，例如「impostor 占比 ∈ [0.4,0.6] ⇒ 第二次目击由其他注入句柄产生」；补全三支——`I≈0 ⇒ 该位在本路径未观测到置位，**不等于**排除重注入，且不得据此认为『已排除去碰安全软件的必要』`、`0<I<下界 ⇒ 记数、判未定`、`I≈全部 ⇒ 包在 WinDivert 看见之前已是别人的注入`；并把 impostor 至多覆盖哪一类注入逐字写进 §3，与 sweep §6 那行的理由改成一致的措辞。

## §3 Recommended

1. 【把 N1/N2 换成 C1 自己的 group-by，省两格并换来精确守恒】`ip.SrcAddr` 在偏移 12..15，与第 2 条那份每包日志是同一笔改动、同样不碰地址结构。现在 N1 与 N2 是两次不同的 20-ping，逐包配对不可能、`N1 + N2 == C1` 不可执行；改成对 C1 一次捕获按 SrcAddr 分组后，守恒是恒等式而不是判断题，且「NAT 前后各一次」与「两个不同源地址的包」的区分直接落在同一批包上（§3 现在靠一句「必须与身份读数联合判」来兜，那句在跨窗时兜不住）。F1/F2 因为 ifIdx 只能经 filter 语言取得，没有这条便宜路，保留独立格。

2. 【三个空闲对照没有观测时长，按现有代码只有约 2 秒，是目标格的十分之一】S0/S1/S2 的「谁打流量」是「无」⇒ `traffic()` 空操作后只剩第 165 行的 `time.sleep(2)`；有流量的格前一轮实测 `time 19031ms`，约 21 秒。而 §3 规定「S1／S2 非 0 ⇒ 所有格先减底噪再判」。一个曝光只有十分之一的对照，它的零不是读数：背景里一个每 5–10 秒一次发往目标的 ICMP 在 2 秒窗里数到 0，却在每个 21 秒的格里贡献 2–4 个计数，而那几个落在最要命的地方（F1=22/F2=2 与 F1=20/F2=0 正是分界，身份侧则把去重推成 22 ⇒ 中间行）。改：在 §2 为三个空闲格写死与目标格等长的时长（取 19031 ms 向上取整，如 21 秒）并要求与对应目标格相邻执行；每格印实测 open→shutdown 秒数并与计数并印；底噪以**速率**表述并给上界（「21 秒内 0 次 ⇒ 95% 下 ≤3 次/格」），扣减按速率×时长算、不许整数相减；上界高于 1 次/格时 F/N 的划分判「未定」而不是「可扣减」。
