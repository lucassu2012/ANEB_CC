### §0.2 读法红线（**五条**，违反其一即本报告被误读）

1. **UI 呈现口径 ≠ 原文 API 口径**：本报告一切时延为设备 UI 呈现口径，**绝对值不可与原文互比**
   （原文 §3.5／§八-2 已自证 API 基线含多跳代理）。可比的是**形状与斜率**，不是数值。
2. **跨口径不可相减**：通道 D（传输层）的 A1 时戳**绝不与** A0′／A2／A3／A4（UI 呈现层）相减。
3. **四态只用四个词**（`PASS` / `FAIL` / `NOT_EXECUTED` / `BLOCKED_EXTERNAL`）；未测得的量写「**待实测**」，
   **不给占位数字**（R-10）。缺席必须是显式的。
   ⚠ **§1.4 的可答性标签（「可测」「弱化」「部分可答」）不是四态词**，两套词回答的是不同问题：
   四态说「这次测出什么」，可答性说「这条路本批走不走得通」。
4. **本批零整形档**：所有数字都是**自然网络下的登记值**，等级 **LOW／登记级**；每格 n≤6，**不给置信区间**。
5. **台账口径句：两个量分开写，勿混**（**D-723**，A-4 已落 `9356de7`）——
   **真机 wire `101`**（原 113 含 12 demo，已剔出真实面）；**带 AQS 分数的 run `99`**；
   **高置信 run 结构上不可能出现**（**D-743**），**故不作为质量指标呈现**——⚠ **这是结构性 artifact，
   不是数据质量信号**（每场景至多 2 个 `token_stream` ⇒ `T1.lowConfidence` **恒真**并经或运算上抛；
   实测真实侧 **99/99 零反例**、合成侧仅 5/572）。**加轮永远摘不掉帽**，只能改 profile 相位数或门限。
   **引用时不得当作数据质量证据。**
   ⚠ **「真实高置信 `0`」这个写法本身已弃用**：它读起来像一个**测量结果**，实际是**恒真命题的补集**
   ——**不是「一个都没达到」，是「结构上不可能达到」**。
   **`113` 不进正文**；**`99` 与 `101` 不是同一个量的两次测量**，任何一处并列出现都必须写明各自是什么。

### §0.3 一条独立纪律：**同一个标签服务两个不同的问题**

> 这条不是本报告的结论，是**读这份报告（以及本仓任何多方共写文档）时的一条纪律**。
> 它单独立节，因为它比任何一个数字活得久。

**形状**：一个词、一个字段名、一个任务号被**两个消费方**使用，而他们要的答案**不是同一个**。
两边各自都对、各自都不报错，**冲突只在有人把两边并排读时才现形**——而通常没人并排读。

**本报告成稿过程中实际撞到的五个实例**（都不是假想的）：

| 标签 | 甲方要的答案 | 乙方要的答案 | 后果 |
|---|---|---|---|
| `NOT_EXECUTED` | 起草者：**别信这个数** | `e2_analyze`：**样本不够，没算** | 「五格全 `NOT_EXECUTED`」读起来像「从没出过判词」，而其中一格出过 |
| `reason=throttle` | 读者：**适配器被限流降级了** | 源码：**定时播报的触发原因** | 差点把 401/401 行的正常播报读成全批降级 |
| 「可测」 | REVIEW §7.4-2(a)：**这条路走得通** | 读者：**本批有数** | 整形窗未开时，「A/B/E/G/I 可测」会让人以为报告里有曲线（D-724 原话：**能力词，不是本批有数**） |
| 「B-11」 | 派件：**P3 的簇阈并排复算** | §4.0／§8.2：**TTFT 数的交叉核** | 若照「B-11 已答」改，会**把一个还没做的检查提前注销** |
| `p99` | 统计名：**尾部** | n=6 时的实际值：**max 的别名** | 「p99 更差」这类论证一律不成立（本报告已全列改称 max） |
| 「**切错**」（§6 那句纪律） | 算术：**落在不同的相对位置**（任意两条不同节拍都成立） | 经验：**位置差足以翻转结论**（需证据） | 一句话缝着两个强度不同的断言，三次改措辞都在整句上调强度，**每次只对一半** |
| `ttft`（**grep 命中时**） | 提问者：**有人验过这个量吗** | 命中所在处：**为测试而编的同名常数** | 见下「第七实例」——**造数与提数在 grep 结果里长得一模一样** |
| 「低置信」／「高置信」 | 提问者搜的词 | 文档里写的**补集说法** | 见下「第八实例」——**搜出零命中，而真实答案是 2** |
| 「**核过**」 | 甲：**在册／有出处吗** | 乙：**从原始件能重算出来吗** | 见下「第九实例」——**两道关问同一个问题时，第二道只是抄了第一道的答案** |

🔴 **第七实例单独展开，因为它比前六个都锋利**（大脑 2026-09-06 核 `983e677` 时逮到）：
为回答「TTFT 有没有被第二方复算过」而 grep `ttft`，**命中了 2 处**——看起来像「有人碰过」。
但两处**全在会话模拟器里**（其 docstring 自述「生成与 `e234_collect.py` 逐字段同形的**合成语料**，供 dry-run」），
形态是零事件轮注入场景的夹具参数 —— **一个编出来的常数**（`ttft_ms` 取 1900）。
⇒ **那不是复算，是造数。** 加上 B-11 的零命中，结论收口：**至今无人从 `adapter.log` 独立提取过。**
**为什么它最锋利**：前六个实例里「命中」至少还指向一个真实的读者；这一个的命中**指向的是生产者**，
而 **grep 结果不区分生产者与消费者**——**造数与提数长得一模一样，且命中数不是零，更像「有人做过」**。
**检出手法**：**看那个命中所在的文件是生产者还是消费者**（模拟器／夹具／测试资源 ＝ 生产者，不算证据）。

🔴 **第八实例——我认为这一族里最该记住的一个，因为它在你以为已经查完的时候发作**：
为回答「报告里有几处把**低置信**当数据质量证据」，我 grep `低置信`，**得 0 命中**；
量法自证也过了（同一把 grep 搜 `ttft_cluster_ms` 得 5 命中）。**差点回一句「零处」。**
真实答案是 **2 处**——因为报告里写的是**补集说法**「**真实高置信 `0`**」。
**「低置信 99/99」与「高置信 0」是同一个量的两种说法，而我的搜索面只覆盖了一半。**

**为什么它最该记住**：前七个实例都要你**先怀疑某处**才会去查；这一个**在你以为已经查完时发作**，
而且给出的是**最令人安心的那个答案**。⇒ **零命中是唯一一种「看起来像做完了」的失败。**

**检出手法**：**报「零命中／没有任何一处」之前，先问这个量还有没有别的说法**——
**补集、同义、缩写、英文原字段名、或它的反面**。

⚠ **同一条的第三种形态：非零命中也要证「它命中的是不是那个对象」。**
（大脑 2026-09-06 实例：数版本号 `0.2.1` 的分布时用整行子串匹配，
**把 IP 地址 `10.0.2.16` 里的 `0.2.1` 算了进去**——多算 8 条、日期跨度多出 18 天，**已写进册子才被推翻**。）
⇒ **证量法有两半，各管一头**：**零命中要证「它能命中」，非零命中要证「它命中的是对的东西」。**
**只做前一半，正是我这次栽的那一半。**

🔴 **第九实例——它比第八个更根本，因为它让「两道关」失效**（D-756）：
「**核过**」这个词服务两个问题：「**在册／有出处吗**」与「**从原始件能重算出来吗**」。

**本报告的实证**：§6.1 那两个被证伪的数（「每轮 148–163 条事件」「三个数量级」），
**上游写下 → 大脑经 D-737 核收 → 我引用**，中间有**两道关**。两道都放过去了，
**因为两道问的是同一个问题**——「这个数在册吗」，**没有一道问「这个数算得出来吗」**。

🔴 **两道关不等于两重保险。当它们问的是同一个问题时，第二道只是把第一道的答案抄了一遍。**
**而两边都以为自己在做审查。**

**为什么难被发现**：**两道关都给出「通过」，而通过的感觉与真通过一模一样**——
这与本节前八个实例的共同点是同一个：**没有任何一步报错**。

**可挂动作的形态**：**设置第二道关时，先写下它要问的那个问题，再和第一道的问题比一比。**
**若两句话一样，那不是第二道关，是同一道关跑了两遍。**

⚠ **补一条成因，它解释了为什么恰好是这两个数漏掉**（大脑自述）：那两个数来自**上游的核收结论**，
**不是来自某份原始产物**。**从核收结论里取数，感觉上已经过了一道关，所以取数的人不会再问「它是怎么算出来的」。**
⇒ 本报告 §4.0 的撤标条件因此**把转述方也包含在内**：凡他方转述、未经第二方从原始日志复算的量，同一标准。

⚠ **这两个实例的编号本身撞过一次，正好是本节的现场演示**：两封交错的信里，
**「第八实例」分别指了补集盲区与「核过」两义**，两边都以为对方说的是同一个。
本报告按**先落笔者为八、后者为九**定序。

🔴 **检出手法（可直接执行，不靠想起来）**：
**给每一个标签逐个找出它的读者，然后问：这两个读者要的是不是同一个答案。**
—— 注意问的**不是**「这个词的定义是什么」（定义通常只有一个，且写得很对），
而是「**谁在读它、各自拿它去回答什么**」。**五个实例里没有一个的定义是错的。**

**近亲但不同的一种**：两个**不同的量碰巧同形或同值**——本报告撞到两次：
wave0 README 的「5 格」（当时已采格名单）与本报告的「5 格」（`FAIL` 判词数）**碰巧都等于 5**；
台账的 `99`（带 AQS 分数的 run）与 `101`（真机 wire run）**曾被一个箭头写成同一个量的进展**。
**第三例（大脑 2026-09-06 提供，我已实核）**：台账的「**12 条合成 demo**」与
`evidence/glm_e03_20260903/` 下的 **12 个 run 目录**（`smoke_a/b/c` ＋ `t60`／`t150`／`t800` 各三，
与 `app/probe/src/test/resources/glm_e03/` 的 12 个 `.sse` 一一对应）——**两个 12 没有共同分母，纯属数值相等**。

**第四例（D-756，本报告 §6.1 的两个被证伪的数）**：「每轮 148–163 条事件」与「0.1–0.2ms」
**不是两条独立的错，是一条**——`0.1–0.2ms` 的上界把 F6 两格（0.302／0.292）整个排除在外，
`148–163` 是单格极差写成全批，**都是「某一格的数被写成全批」**。
🔴 **并列写成两条，读者会去修两个数；写成一条，才会去改那个习惯。**

⇒ 判据：**两个数相等时先找共同分母**；**两个量并列时各自写明是什么，不用箭头**；
**见两个错先问它们是不是同一条**。

### §0.3a 怎么让纪律不依赖记性（**免疫式落地**）

本节列了九个实例、给了检出手法。但**检出手法有一个共同的弱点：它们都要求下一个人在正确的时刻想起它**。
本报告成稿过程中反复出现的正是这一点——**规矩记住了，却没在那一刻取用**（页头「锚打到款」那条即是：
我写下它之后，仍在同一天引了三个不存在的分项号）。

⇒ **凡一条纪律的执行依赖「下一个人在正确时刻想起它」，就去找一个把它焊进产物本身的形态。**
三个已落地的实例（**均在本仓实核，不是转述**）：

| 纪律 | 靠记性的形态 | **焊进产物的形态** |
|---|---|---|
| 报「零命中」前先想别名 | 「记得搜补集」 | **把补集的两种说法都写进文里**——本报告现同时含「低置信」与「高置信」，**下次搜任一词都会命中**（§0.3 第八实例的免疫） |
| 别删掉你不懂的守卫 | 「记得先弄清它为什么在」 | **把理由写进报错文案本身**——`scripts/tests/test_validate_profiles.py` 逐字：「只报『不许声明』而不给理由，**下一个人只会把它从清单里删掉**」 |
| 跨模块常量必须同步 | 「记得两边一起改」 | **写成独立用例钉死**——`tools/e234/tests/test_e2_precheck.py` 的 `assert ep.MIN_OBSERVED_GAPS == ec.ea.GATE_MIN_N`；同族＝`tools/e1_stimulus` 把「零权限、不联网、不落盘」焊进 KDoc |
| 版本号／计数改了要处处同步 | 「记得把每处都改一遍」 | **一个数只写一处，别处指向它**——本报告头部原写「本版 v0.1.1」，而 §9 已走到 v0.1.8，**锁死七版没人路过**；改为头部只说「以 §9 为准」后，**下次不可能再错**（本行即该缺陷的产物） |

🔴 **判据**：**焊进产物的形态，其生效不需要任何人记得它。** 靠记性的形态在**最忙、最像已经做完**的那一刻失效——
而那正是需要它的时刻。
