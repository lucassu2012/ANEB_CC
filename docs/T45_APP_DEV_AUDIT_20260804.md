### 3.2 把"仪表核心量可切换（AQS/TTFT/ITL）"接活——期1 最高价值的一项缺口

**根因**（用 `git log` 逐条核实，非猜测）：`eb9ff2a`（"期1: 底部3-tab壳+可切换
测试仪表"）当年**完整实现**了这个功能（`TestingScreen.kt` 的 `GaugeMetric`

动态化: 测量原地进行"）把手动测量的实际呈现搬到了首页原地仪表
（`HomeScreen.kt` 的 `RunningGauge`），**没有把已写好的切换器一起搬过去**——
`Screen.Testing` 从此再没有任何代码路径导航过去（`MainActivity.kt:680-681`
注释自己写着"本分支对手动 run 不再可达"），功能变成纯死代码，直到今天。

**实施**：把投影逻辑抽成纯函数（`GaugeMath.homeGaugeReadout`，遵循本仓已有
的 `GaugeMath.kt` 纯函数抽取惯例，spine-4 §4.1 先例），接到 `HomeScreen.kt`
当前真正在用的原地仪表上：
- 新增 `HomeGaugeMetric{Auto,Aqs,Ttft,Itl}`；默认 `Auto`——逐字保留改造前
  "上传相实时上行/流式相 token 速率"行为，用户不动它零变化。
- `Aqs` 用自身 0–100 量程直接驱动弧位（与表盘既有 0/25/50/75/100 刻度对齐，
  复用既有 `GaugeMath.gaugeFraction`）；`Ttft`/`Itl` 是无界延迟值，没有现成
  量程可套——弧位沿用 `autoFrac`（继续表达"传输活跃度"），只换中心文字，
  不为它们发明可能误导的新刻度。
- null 一律显"…"（R-10：缺失不驱动几何显示"满"，也不伪装成 0）——4 条新
  单测钉住这条，含"AQS 缺失时 fraction=0、文字=…，不是 autoFrac 的值"。

**测试**：`GaugeMathTest.kt` 新增 4 条（auto 透传、AQS 用自身量程非 autoFrac、
AQS null 语义、TTFT/ITL 借 autoFrac 换文字）；全量 `:probe` **685/681→685
（92 套件，重跑非缓存，XML 时间戳已核新鲜），零回归**。
