## 1. 主命题

### P1（主）生产解析器数出的 token 数 == 服务端 `usage.completion_tokens`

`OpenAiSseAdapter` 的计数规则写死在它自己的 docstring 里：**`choices[0].delta.content` 为非空字符串才记 token 到达**（首帧 role 帧的 `content:""` 与结束帧空 delta 不算），`data: [DONE]` 不算 token 不算错误。服务端尾帧给出 `usage.completion_tokens`。**两者应当相等。**

⚠ **为什么这条只能在真端点上做、在 mock 上做没有意义**：mock 的 `usage` 与它的 token 流**出自同一段代码**，一致是**构造保证**的——那正是本仓「**同一缺陷喂出两个假独立方法**」。真端点的 usage 来自独立实现，**才算互证**。

⚠ **不等时不预设哪边对**：至少两种解释——①我们的计数规则漏计/多计（量法缺陷）；②GLM 的 `completion_tokens` 口径与 delta 边界不同（分词口径差）。**报告须两种并列**；单次不等不足以定性。

### P2（主）真端点的 wire 形态不会让生产解析器**静默**产出错值

判据全部取自解析器自己的输出字段，不另立：
- `parseErrors == 0`；
- `protocolError == null`；
- **原始 SSE 字节全量留存**，任何判读事后可重解。

⚠ 危险的不是解析失败——那会计数。危险的是**解析成功而结果是错的**。故本条真正的判据是 P1；P2 只排除「连解析都没成」这一层。

### P3（次，**只描述不判定**）真端点的 TTFT 与瞬时 TPS 形态

模拟端点 `server/tokengen.go` 写着六条显式假设：TTFT 注入驻留／非平稳 `RateSchedule`（前快后慢）／SSE 帧合并 `TokensPerFrame`／每模型字节直方图／流内 think 停顿／burst。真端点能告诉我们**哪几条像、哪几条不像**。

⚠ 本批 n 小，**只出描述与区间，不出「模型该改成什么」的结论**。

冒烟三笔已使**同参重复失去信息量**（形态一致）。正式 9 笔改为**三档长度 × 三笔**，
用途从「重复」改为**判别差额机制：固定开销 vs 帧合并**。

**两套轴的映射（N-2）**：§2 的分流轴是「分词口径差／量法缺陷」，本节的轴是
「固定开销／帧合并」——**它们是同一个差额的两套说法**，对应关系写死：

| 本节（机制） | §2（归属） | 为什么 |
|---|---|---|
| **固定开销** | ⊂ **分词口径差** | 服务端**计入了它不下发**的 token；我们按帧数的那个数**作为帧数是对的** |
| **帧合并** | ⊂ **量法缺陷** | 一帧多 token 而我们按帧计 ⇒ 量法**没在量它自称在量的东西**（与已确立的「`arrivals` 实为内容帧到达」同源） |

⇒ **9 笔跑完必须回去合上 §2 的分流**，不能只答本节的分支就收工。

⚠ **一处对修正案措辞的事实订正（据冒烟数据）**：原案写「`max_tokens` 变」，
而冒烟三笔 `max_tokens=800`、实得 `completion_tokens` 仅 **246–269** 且
**`finish_reason` 全为 `stop`** ⇒ **上限根本没有生效**，模型是自然停的。
**照原样只调 `max_tokens` 到 800 以上，长度不会变。** 故三档取值必须**压到自然长度以下**：

| 档 | `max_tokens` | 预期 | `finish_reason` |
|---|---|---|---|
| 短 | **60** | 截断 | `length` |
| 中 | **150** | 截断 | `length` |
| 长 | **800** | 自然停（≈246–269） | `stop` |

**其余参数一律同冒烟笔 A（生产同构：无 `stream_options`、无 `temperature`）。**

⚠ **截断带来的副作用本身是判据，不是杂音**：截断轮**没有自然结束 token**。
若那 4–5 的固定开销来自 EOS/格式类不下发 token，**截断轮与自然停止轮的差额应当不同**；
若差额在两者间也恒定，则 EOS 解释被削弱。**这比原案更能分辨机制**，故保留而非规避。
⚠ 但按 §1c 既有规则，**`finish_reason` 非 `stop` 的轮不进 P3 形状池**——
它们**只用于 P1 的差额分析**，两个用途不混池。
