## 0. 怎么用（三步）

1. **定扫法**（§1，四种）：这一轮审的是**断言**、**设计**、**被执行**、还是**装置**？——四种视角互补，任一单用都有系统性盲区。
2. **定审计面**（§2，十一面）：在**哪一面**找？——扫法给「怎么看」，审计面给「看哪里」。
3. **套元规则 + 一级条目**（§3/§4）逐条问；命中即按 §5 分诊。**收敛判据不是「我想不出还有什么」，而是一次不依赖记忆的全量枚举**（换枚举单位比在同一单位里再想一遍有效得多）。

**⚠ 锚纪律（本册的自失效判据，v3 08-29 复审立）**：本册每条一级条目**都必须挂一手锚（commit 哈希或 D 号），且锚由「非作者方」解析过一次**。理由：本册收录的「转述会放大措辞强度」「零命中第二形状」两条，恰说明**作者自查挡不住转述误差**——v1.2 收录时就出过一次哈希转述错（发生在消息里、未进产物，由 v3 对 git log 核出）。这条把「本册是被互相核审出来的」从一句**自评**变成**会自己失效的纪律**（有人加了不解析的锚就红），且「谁核下一版」的答案是**判据本身（非作者解析过）**、不依赖具体某人。**v1.3 的 17 个哈希锚**已由非作者方（v3）逐个 `git cat-file -e` 解析、悬空 0；**本行绑版本与锚数——条目/锚数一变就得重跑下面的复核命令并更新本行**（读者见当前锚数 ≠ 17 即知本行已过期、须重解析）。⚠ 这里**计数即内容**（与「索引里别写计数」相反：那条防计数替代内容，这条要计数当**过期信号**）——否则这句凭据会成为全册唯一一条把自己漏在锚纪律之外、不自失效的断言（v3 08-29 末条自指缺口）。复核命令（几秒，任何非作者方可跑）：


## 1. 四种扫法（HOW —— 从哪个视角扫）

四种扫法作为一个集合的诞生锚：`D-580`（T78「F-1 未解期间以四种扫法逐面清账」）＋记忆 `aneb-v2-session-lessons-20260819`。**前三种只能发现文档内部不自洽；第四种（装置面）才验「文档说的与真实跑的是否同一个」。**

- **① 断言面**：把文档里每一句**事实断言**挑出来，逐句问「这句被实证过吗」。诞生锚：`D-578`（裁定把「应列入」写成「已列入」，清单上没有——裁定文里的机制存在性断言只许「先做再写」或「指令态＋点名跟进」）；`aneb-v2-session-lessons`（「UI 无测试／手写拼装」两次凭印象被实查推翻）。**砍⑤：机器认不出哪句是事实断言、哪句是设计意图 → 靠人（审计惯例 + 互相核）。**
- **② 设计面**：把文档**自己的结构**当盲区清单——「两个分区之间发生的事归谁」「这份产物有没有回答用户真正的问题」。诞生锚：`D-142`/`D-143`（报告叫《归因报告》而摘要六信号无一涉及归因）；`aneb-v2-session-lessons`（速查卡缺「格与格之间」＝执行顺序＋切换时间戳，按条件分组是操作者最自然、也正是要避开的混淆）。**砍⑤：部分可机检（段名映射存在性，见 D-134 `SECTION-MAP`），意图层靠人。**
- **③ 被执行面**：审**被执行的那一面**（摘要／速查卡／收工清单），不是只审详节——**审计习惯是读详节，而摘要才是被照着做的那面**。诞生锚：`D-300`（commit `f813854`，㊸：PO 最先读的头条那一行要单独找一遍）；`D-124`（`publish_check.py`，收工手工清单最易被跳过 → 一条命令）；`aneb-v2-session-lessons`（十几轮加固后最后几条真缺陷全在速查卡）。**砍⑤：清单齐不齐可机检（publish_check 已有守卫）；语义对不对靠人。**
- **④ 装置面**：**文档说的，拿真设备/线上跑一遍**——并常备一问「**我读的源码，是设备/线上跑的那份吗**」。诞生锚：`D-120`/`D-121`（文档命令全量实测＋`test_docs_commands.py` 守卫；跨 shell 差异是文档验证盲区，命令须在目标 shell 实测）；`D-581`（战役窗前重装会让「我读了代码所以知道它会怎样」的全部核查作废——任何这类结论都隐含「我读的＝设备跑的」这个几乎从不被说出的前提）。**砍⑤：命令存在性/flag 有效性已有守卫（D-121）；「装的是不是同一份」靠人（开窗前不要重装）。**

### 2.1 结构性无主项的五族（第⑪面展开）

同族形状：**天生没有属主的区间，因而每一方都以为别人管**。五族：
1. **lane 之间**——两条 lane 的接缝（如 spec 与实现、采集与分析）。
2. **设计与执行之间**——设计说了、执行没接（如 D-471 订正级联漏了 ADDENDUM 一份）。
3. **采集与结论之间**——采到的与印出的不是同一批（如跨战役池化未标注，`D-135`）。
4. **产物里有什么**——文件在、行在、列名对，判据却可能从没出去过（如 `D-296` 消费方复算）。
5. **红线谁来证明**——规则写着覆盖全体、对半个总体从未执行过（如 `GOVERNANCE §9.2` debt-1 sha256-manifest 只覆盖 phase0；治理债审计批次 `D-583` 咬出的一族）。

## 3. 组合规矩元规则（找什么 × 在哪找）

**单条规矩收益递减时，把两条相乘**——一条给「找什么」、一条给「在哪找」，单用任一条都扫不到，相乘才命中。诞生锚：`aneb-v2-session-lessons`（同晚两次兑现：速查卡不动作指令缺前提→整格通道 B 全零；操作者验收判据≠判读器可用判据→「5/5 全齐」而判读器一轮用不上）。

三条常用「乘法」：
- **「找什么」= 一级条目（§4）× 「在哪找」= 审计面（§2）**：如「旧判据残留（⑤）× 头条面（④）」＝去 PO 头条数它的旧名字。
- **「怎么看」= 扫法（§1）× 「看哪里」= 审计面（§2）**：如「装置面（④）× 消费方复算（①）」＝拿真设备产出的 CSV 复算头条。
- **元教训**：**记住规矩与在正确时刻想起它是两件事**——规矩要**挂在动作上**（「下『无 X』结论前先跑一次」），不是挂在记忆里。（`aneb-v2-session-lessons`，同晚写下后随即用同一坏判据又栽。）
