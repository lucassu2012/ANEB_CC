## 0. 怎么用（三步）

1. **定扫法**（§1，四种）：这一轮审的是**断言**、**设计**、**被执行**、还是**装置**？——四种视角互补，任一单用都有系统性盲区。
2. **定审计面**（§2，十一面）：在**哪一面**找？——扫法给「怎么看」，审计面给「看哪里」。
3. **套元规则 + 一级条目**（§3/§4）逐条问；命中即按 §5 分诊。**收敛判据不是「我想不出还有什么」，而是一次不依赖记忆的全量枚举**（换枚举单位比在同一单位里再想一遍有效得多）。

**⚠ 锚纪律（本册的自失效判据，v3 08-29 复审立）**：本册每条一级条目**都必须挂一手锚（commit 哈希或 D 号），且锚由「非作者方」解析过一次**。理由：本册收录的「转述会放大措辞强度」「零命中第二形状」两条，恰说明**作者自查挡不住转述误差**——v1.2 收录时就出过一次哈希转述错（发生在消息里、未进产物，由 v3 对 git log 核出）。这条把「本册是被互相核审出来的」从一句**自评**变成**会自己失效的纪律**（有人加了不解析的锚就红），且「谁核下一版」的答案是**判据本身（非作者解析过）**、不依赖具体某人。**v1.3 的 17 个哈希锚**已由非作者方（v3）逐个 `git cat-file -e` 解析、悬空 0。**v1.5（`D-598`…`D-603` 批补入十条一级条目＋一条自我适用注＋一条共享格首）后锚数 17→25**：新增八个（`2c2fca0`／`9a8f2a6`／`dbf6df6`／`760dcfa`／`ed02d88`／`e11caf8`／`252e880`／`dc052be`）由**本册作者（v4）**自跑复核命令——**25 个全部可解、悬空 0**。**作者自解不算数**（本纪律防的恰是作者自查，「**不给自己的锚盖章**」即它的操作形态），故转非作者方复核：**v3 已两轮跑完，按「比正文不比标题」判法核到 24/24 可解、悬空 0、二层全过**——**但第二轮跑完之后，(k) 条目入册又带来第 25 个锚 `dc052be`**，故当前状态是「**24/25 已由非作者解析**」，差 `dc052be` 一个。⭐ **现场拦截已发生三次（均 2026-08-30）**：①v3 按 22 个跑而册中已 23；②我自己用「还差一个」的旧措辞而实为两个；③**(k) 入册当场把刚报的「24/24 全解」变回 24/25**。**⚠ 第 ③ 次不是流程没跑好，正是 (k) 那条在本行上自我演示**：范围会在复核跑的时候变，而**陈旧的「全解」读起来与真全解一模一样**——**唯一让它现形的就是这个会对不上的数**。
>
> **本格一句话**：**中间层表示会造假阴性**（只看标题 → 误判锚错），**陈旧计数会造假阳性**（旧锚数 → 误判全解）——**中间层都不是对象本身**。下面两段是这两个方向各自的实例。
>
> **二层判据的正确写法（`231dc28`／`D-298`；v3 08-30 复核时实证订正，经本册作者独立核过；`252e880`／`D-601` 追认）**。**出处如实分层**：被订正的那个「只比提交标题」的判法**不是递条方派下的，是本册作者自己加的一层**（我当时把它描述为「比能解析强一层」，方向没错、**但不足以当判据**）——「**提交标题吻合**」**既不足以判对、也不足以判错**——`231dc28` 挂在「③注释/docstring 后果」那一行，其提交标题是 `a cell with data wearing the colour that means no data`，**光看标题与该行主题对不上**；而 `D-298` 正文首句写的正是「这句后果早就写在某条守卫的 docstring 里，**从没人断言它**」⇒ **锚是对的，对不上的是「标题」与「条目主题」**。故二层的正确判法＝**拿条目描述去比 D 条正文（或该提交的 diff），提交标题只作快速筛**；只比标题会造出**假的不吻合**，而这种假阳性会让人去改一个**本来正确**的锚。**同族形状：用一个中间层的表示去指认对象**——这次的中间层是「提交标题」。**本行绑版本与锚数——条目/锚数一变就得重跑下面的复核命令并更新本行**（读者见当前锚数 ≠ 25 即知本行已过期、须重解析）。⚠ 这里**计数即内容**（与「索引里别写计数」相反：那条防计数替代内容，这条要计数当**过期信号**）——否则这句凭据会成为全册唯一一条把自己漏在锚纪律之外、不自失效的断言（v3 08-29 末条自指缺口）。**⚠ 抽取器的一个已知假阳性（2026-08-30 被本行自己的检查逮到）**：下面这条命令按「反引号包裹的 7–40 位十六进制」抽锚，**它分不出 commit 哈希与恰好是十六进制的别的东西**——本册一度把一个会话 id（8 位十六进制，此处**刻意不加反引号**——加了这句警告自己就会被抽成锚，实测过）抽成锚并报 dangling。**这不是小概率**：`4.5` 迁移步骤单已规定分支名用 `sess/<会话 id 前 8 位>`，十六进制会话 id 会成批进入文档。**约定：文内引用会话一律写 `local_<id8>` 前缀形式**（含下划线与非十六进制字母，抽取器不会误收）。**同族形状：用一个中间层的表示（「看起来像十六进制」）去指认对象（「是一个 commit」）**——与本格上面两段同魂。复核命令（几秒，任何非作者方可跑）：

```
grep -oE '`[0-9a-f]{7,40}`' docs/AUDIT_PLAYBOOK_v1.md | tr -d '`' | sort -u | while read h; do git cat-file -e "$h^{commit}" || echo "dangling $h"; done
```

## 1. 四种扫法（HOW —— 从哪个视角扫）

四种扫法作为一个集合的诞生锚：`D-580`（T78「F-1 未解期间以四种扫法逐面清账」）＋记忆 `aneb-v2-session-lessons-20260819`。**前三种只能发现文档内部不自洽；第四种（装置面）才验「文档说的与真实跑的是否同一个」。**

- **① 断言面**：把文档里每一句**事实断言**挑出来，逐句问「这句被实证过吗」。诞生锚：`D-578`（裁定把「应列入」写成「已列入」，清单上没有——裁定文里的机制存在性断言只许「先做再写」或「指令态＋点名跟进」）；`aneb-v2-session-lessons`（「UI 无测试／手写拼装」两次凭印象被实查推翻）。**砍⑤：机器认不出哪句是事实断言、哪句是设计意图 → 靠人（审计惯例 + 互相核）。**
- **② 设计面**：把文档**自己的结构**当盲区清单——「两个分区之间发生的事归谁」「这份产物有没有回答用户真正的问题」。诞生锚：`D-142`/`D-143`（报告叫《归因报告》而摘要六信号无一涉及归因）；`aneb-v2-session-lessons`（速查卡缺「格与格之间」＝执行顺序＋切换时间戳，按条件分组是操作者最自然、也正是要避开的混淆）。**砍⑤：部分可机检（段名映射存在性，见 D-134 `SECTION-MAP`），意图层靠人。**

### 2.1 结构性无主项的五族（第⑪面展开）

同族形状：**天生没有属主的区间，因而每一方都以为别人管**。五族：
1. **lane 之间**——两条 lane 的接缝（如 spec 与实现、采集与分析）。
2. **设计与执行之间**——设计说了、执行没接（如 D-471 订正级联漏了 ADDENDUM 一份）。
3. **采集与结论之间**——采到的与印出的不是同一批（如跨战役池化未标注，`D-135`）。
4. **产物里有什么**——文件在、行在、列名对，判据却可能从没出去过（如 `D-296` 消费方复算）。
5. **红线谁来证明**——规则写着覆盖全体、对半个总体从未执行过（如 `GOVERNANCE §9.2` debt-1 sha256-manifest 只覆盖 phase0；治理债审计批次 `D-583` 咬出的一族）。

## 3. 组合规矩元规则（找什么 × 在哪找）

**单条规矩收益递减时，把两条相乘**——一条给「找什么」、一条给「在哪找」，单用任一条都扫不到，相乘才命中。诞生锚：`aneb-v2-session-lessons`（同晚两次兑现：速查卡不动作指令缺前提→整格通道 B 全零；操作者验收判据≠判读器可用判据→「5/5 全齐」而判读器一轮用不上）。

三条常用「乘法」：
- **「找什么」= 一级条目（§4）× 「在哪找」= 审计面（§2）**：如「旧判据残留（⑤）× 头条面（④）」＝去 PO 头条数它的旧名字。
- **「怎么看」= 扫法（§1）× 「看哪里」= 审计面（§2）**：如「装置面（④）× 消费方复算（①）」＝拿真设备产出的 CSV 复算头条。
- **元教训**：**记住规矩与在正确时刻想起它是两件事**——规矩要**挂在动作上**（「下『无 X』结论前先跑一次」），不是挂在记忆里。（`aneb-v2-session-lessons`，同晚写下后随即用同一坏判据又栽。）

> ② **空洞**：症状＝一句「丢弃 N 条」，你会读成「已处理」——**而没被丢的那些可能被同一原因污染**（见「报『丢弃 N 条』就问没被丢的」行）。
> ③ **漂亮的数值**：**没有症状**。空洞喂出的假比较会给你一个看起来完全正常的数，**看数值本身永远看不出来**——只能靠追溯它的产生路径抓到。

> **「前提与限定都会被读者简化成『那个数』或『那句话』——决定它们威力的不是写得对不对，而是它们旁边有没有一个同样显眼的作用域／口径。」**
