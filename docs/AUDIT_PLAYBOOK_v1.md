> **本格一句话**：**中间层表示会造假阴性**（只看标题 → 误判锚错），**陈旧计数会造假阳性**（旧锚数 → 误判全解）——**中间层都不是对象本身**。下面两段是这两个方向各自的实例。
>
> **二层判据的正确写法（`231dc28`／`D-298`；v3 08-30 复核时实证订正，经本册作者独立核过；`252e880`／`D-601` 追认）**。**出处如实分层**：被订正的那个「只比提交标题」的判法**不是递条方派下的，是本册作者自己加的一层**（我当时把它描述为「比能解析强一层」，方向没错、**但不足以当判据**）——「**提交标题吻合**」**既不足以判对、也不足以判错**——`231dc28` 挂在「③注释/docstring 后果」那一行，其提交标题是 `a cell with data wearing the colour that means no data`，**光看标题与该行主题对不上**；而 `D-298` 正文首句写的正是「这句后果早就写在某条守卫的 docstring 里，**从没人断言它**」⇒ **锚是对的，对不上的是「标题」与「条目主题」**。故二层的正确判法＝**拿条目描述去比 D 条正文（或该提交的 diff），提交标题只作快速筛**；只比标题会造出**假的不吻合**，而这种假阳性会让人去改一个**本来正确**的锚。**同族形状：用一个中间层的表示去指认对象**——这次的中间层是「提交标题」。**本行绑版本与锚数——条目/锚数一变就得重跑下面的复核命令并更新本行**（读者见当前锚数 ≠ 27 即知本行已过期、须重解析）。⚠ 这里**计数即内容**（与「索引里别写计数」相反：那条防计数替代内容，这条要计数当**过期信号**）——否则这句凭据会成为全册唯一一条把自己漏在锚纪律之外、不自失效的断言（v3 08-29 末条自指缺口）。**⚠ 抽取器的一个已知假阳性（2026-08-30 被本行自己的检查逮到）**：下面这条命令按「反引号包裹的 7–40 位十六进制」抽锚，**它分不出 commit 哈希与恰好是十六进制的别的东西**——本册一度把一个会话 id（8 位十六进制，此处**刻意不加反引号**——加了这句警告自己就会被抽成锚，实测过）抽成锚并报 dangling。**这不是小概率**：`4.5` 迁移步骤单已规定分支名用 `sess/<会话 id 前 8 位>`，十六进制会话 id 会成批进入文档。**约定：文内引用会话一律写 `local_<id8>` 前缀形式**（含下划线与非十六进制字母，抽取器不会误收）。**同族形状：用一个中间层的表示（「看起来像十六进制」）去指认对象（「是一个 commit」）**——与本格上面两段同魂。复核命令（几秒，任何非作者方可跑）：

```
grep -oE '`[0-9a-f]{7,40}`' docs/AUDIT_PLAYBOOK_v1.md | tr -d '`' | sort -u | while read h; do git cat-file -e "$h^{commit}" || echo "dangling $h"; done
```

### 2.1 结构性无主项的五族（第⑪面展开）

同族形状：**天生没有属主的区间，因而每一方都以为别人管**。五族：
1. **lane 之间**——两条 lane 的接缝（如 spec 与实现、采集与分析）。
2. **设计与执行之间**——设计说了、执行没接（如 D-471 订正级联漏了 ADDENDUM 一份）。
3. **采集与结论之间**——采到的与印出的不是同一批（如跨战役池化未标注，`D-135`）。
4. **产物里有什么**——文件在、行在、列名对，判据却可能从没出去过（如 `D-296` 消费方复算）。
5. **红线谁来证明**——规则写着覆盖全体、对半个总体从未执行过（如 `GOVERNANCE §9.2` debt-1 sha256-manifest 只覆盖 phase0；治理债审计批次 `D-583` 咬出的一族）。

## 3. 组合规矩元规则（找什么 × 在哪找）

**单条规矩收益递减时，把两条相乘**——一条给「找什么」、一条给「在哪找」，单用任一条都扫不到，相乘才命中。诞生锚：`aneb-v2-session-lessons`（同晚两次兑现：速查卡不动作指令缺前提→整格通道 B 全零；操作者验收判据≠判读器可用判据→「5/5 全齐」而判读器一轮用不上）。

三条常用「乘法」：
- **「找什么」= 一级条目（§4）× 「在哪找」= 审计面（§2）**：如「旧判据残留（⑤）× 头条面（④）」＝去 PO 头条数它的旧名字。
- **「怎么看」= 扫法（§1）× 「看哪里」= 审计面（§2）**：如「装置面（④）× 消费方复算（①）」＝拿真设备产出的 CSV 复算头条。
- **元教训**：**记住规矩与在正确时刻想起它是两件事**——规矩要**挂在动作上**（「下『无 X』结论前先跑一次」），不是挂在记忆里。（`aneb-v2-session-lessons`，同晚写下后随即用同一坏判据又栽。）

> **⚠ 三种「静默形态」并排**（`D-598`／`D-599` 批递入）：上面两个失败模式其实属于一个更大的族——**都不报错**，但**症状与修法各不同，且越靠后越难发现**：
> ① **零命中**：症状＝一个空结果，你会读成「没有」。**第三层**（`ed02d88`／`D-597 ④`）：零命中不但有两个成因，**两个成因的零命中长得一模一样**——我的突变锚串带 `\n` 而目标文件全 CRLF、且缩进猜错，两处锚各错一次、输出都是「0 命中」。故 ① 的复核不能只证「**量法能工作**」，还要证「**我这次用的锚正确**」——**工具无辜、输入有毒时，输出同样是 0**。
> ② **空洞**：症状＝一句「丢弃 N 条」，你会读成「已处理」——**而没被丢的那些可能被同一原因污染**（见「报『丢弃 N 条』就问没被丢的」行）。
> ③ **漂亮的数值**：**没有症状**。空洞喂出的假比较会给你一个看起来完全正常的数，**看数值本身永远看不出来**——只能靠追溯它的产生路径抓到。
>
> **判据顺序**：先问「**这个空／这个数是怎么来的**」，再问「**它和我要下的结论是同一个问题吗**」（后半句即「共用状态词」那条）。三者按发现难度排，**审计资源该倒着分配**。
>
> **「限定语要与证据量同句」(e) 与「具体数要带口径」(g) 的共享格首**（出处三层照 `D-602`：**发明＝采集侧会话 `local_61bd2401`，合成表述＝v3，转发＝大脑，录入＝v4**）：
> **「前提与限定都会被读者简化成『那个数』或『那句话』——决定它们威力的不是写得对不对，而是它们旁边有没有一个同样显眼的作用域／口径。」**
> 这句给出两条的**共同机制**：**读者的简化是必然发生的，防线只能建在「同样显眼」上**——(e) 让限定语带上它实际覆盖几个样本，(g) 让具体数带上它出自哪个口径，**都是往那个必然被读到的位置加一个同样显眼的东西，而不是指望读者转头去读旁边那句**。
>
> **⚠ §4 已经长到不该逐条过了（2026-08-31 批量落册后自陈）**：本表当初是「开审时逐条过一遍」的清单，
