## 0. 这份文件是什么、以及它现在**不是**什么

**载体选择（本文的决定）**：写成**独立草案**，不直接改
[`M2_CAMPAIGN_RUNBOOK.md`](M2_CAMPAIGN_RUNBOOK.md)。

理由是 D-311 那一课的**反面用法**：runbook 是**在现场被逐条执行**的那份文件，
把一套 PO 尚未批复的协议写进去，操作者就会照着执行。故：

> ⚠ **在 PO 批复之前，现场作业一律照 runbook §0.6 现行流程执行；本文不生效、不覆盖、不并行。**

同时，为了不重蹈 D-311 的**正面陷阱**（提案改了、runbook 没改，于是现场照着过期的那份跑），
§7 预先写死了**并入时要改 runbook 哪几处**——批复当天照 §7 机械执行即可，不必重读本文推导。

**本文对 D-366（预热轮）与 D-354（轮转正确性）只给指针，不复述其内容。**
理由：复述会漂。§3 里凡涉及这两条的地方，写的是「照 D-366 §0.6.1③ 现行口径执行」
「轮转正确性已由 D-354 实测确认，不在此重新论证」，**判据本身留在决策日志与 runbook 原文里，
只有一份**（§2.14 一处规则的同一条纪律）。本文因此**刻意不含**：预热轮的记账步骤细则、

## 2. s2 单列口径 · 标记名**定案** = `SCENARIO_INTRINSIC_JITTER`

提案 §2 把这个名字留给了「分析层属主」。**属主即本会话，现予定案。**

### 2.1 名字为什么长这样（先看仓里现有的怎么起名，再定）

清点了 `scripts/` 现役标记词汇：`MIXED_CAMPAIGN`、`MIXED_MODE`、`MIXED_PROFILE_VERSION`、
`MIXED_HIST_EDGES`、`TIER_ENDPOINT_CONFLICT`、`TIER_ENDPOINT_UNVERIFIED`、`TIER_MISSING`、
`CELL_CHANGED`、`CELL_CONFOUNDED`、`UNREPLICATED_POSITIONS`、`UNREPLICATED_ROUNDS`、
`SINGLE_ROUND`、`MEDIAN_NEAR_ZERO`、`IMPLAUSIBLE_VALUE`、`LOW_VALID_RATE`、
`UNKNOWN_VALIDITY`、`RULED_OUT`、`GRADE_TIE`、`ORDER_UNTRUSTWORTHY`、`NEED_2_POSITIONS`。

归纳出的三条成文规则，`SCENARIO_INTRINSIC_JITTER` 逐条对齐：

| 规则 | 现有实例 | 本标记 |
|---|---|---|
| 裸 `UPPER_SNAKE`，无命名空间前缀、无模块名 | 全部 20 个 | ✅ |
| 「**名词短语**说出**是什么情况**」，不是「该怎么办」 | `CELL_CHANGED`（不是 `RECHECK_CELL`） | ✅ 说的是「抖动是场景内生的」 |
| 首词是**被限定的对象**，其后是限定语 | `TIER_ENDPOINT_*`、`CELL_*`、`MIXED_*` | ✅ 首词 `SCENARIO_` = 抖动的**归属对象** |

**唯一一处需要如实说明的偏差**：长度 25 字符，比上表 20 个**渲染标记**中最长的
`TIER_ENDPOINT_UNVERIFIED`（24）多一个字符（比对时只数渲染标记；`DEFAULT_TARGET_EFFECT_PCT`
一类 Python 常量名不在此列，它们不出现在任何面上）。渲染面均为表格备注列，
25 字符不影响换行，**接受**。

（备选 `INTRINSIC_JITTER` 更短，**不取**：首词不是对象，读者无法从名字看出抖动归属于「场景」
而非「格」或「链路」，而**归属正是 D-372 全部的结论**。）

### 2.2 语义（判据结构，不预写门限数字）

标注对象 = **复测稳定性段的一行**，即 `(campaign_id, point_id, carrier, time_band, tier, profile_id) × KPI`。

触发结构：**同一格同一 profile 下，场景侧 KPI 的 CV 超门，而其网络侧 KPI 的 CV 未超门。**

- 场景侧 = `t1_ttft_ms` / `t2_itl_p95_ms` / `u2_tool_loop_p95_ms`；网络侧 = `n1_rtt_p50_ms` / `n2_jitter_ms`。
- 这正是 D-372 用来裁定 H3 的那对判别量（同批 RTT 平稳而 TTFT 独抖）。
- **门限值不在本文新设**：沿用 `stability.DEFAULT_CV_GATE`（M1 验收口径）。
- ⚠ **待定**：是否额外要求「网络侧 CV 低于场景侧若干倍」这一强化条件，**本文不擅定**
  （任何倍数都是新常量，需要自己的来源）。登记于 §8。

彩排实证（合成语料，数字虚构）：整形后的 quick 主体上，`t1_ttft_ms` 超 CV 门的格
**s2 占 27/32，s1 与 s3 各 4/32**，而同批 `n1_rtt_p50_ms` 三个 profile 的格中位 CV
分别为 2.66 / 2.59 / 2.49% ——**该形状可被这条判据干净地分出来**。

### 2.3 单列口径落地时的三面渲染契约（照 `RULED_OUT` 的先例，D-366）

D-337 的纪律：**标记在每个面用该面自己的词汇编码同一事实，不要求字面一致。**

| 面 | 形态 |
|---|---|
| **markdown** | 复测稳定性表**备注**列增 `SCENARIO_INTRINSIC_JITTER` 前缀标记；段首横幅一句：这些格的 `需 n≥` **不作为加测网络样本的理由**。 |
| **HTML** | 同段同行的中文短语（如 `场景内生抖动`），与 md 语义等价、措辞按 HTML 自己的惯例。 |
| **CSV** | `<prefix>_stability.csv` 增**独立列**（布尔），与 `unstable` / `low_confidence` 并列——CSV 没有横幅可看（D-141/D-303 的同一条理由）。 |

**并且**：s2 的 `需 n≥` 与 CV 门**单列呈现**，不与 s1/s3 的网络侧采样量核算并栏。

> 注：CV>门的格「无论 n 多大都应先查测量装置」是既有口径（D-170），单列口径与之相容——
> 单列口径只是把「查什么」从「测量装置」细化到「场景/服务端侧」。

## 3. 轮次协议

### 3.1 预热轮

**照 D-366 现行口径执行，即 runbook §0.6.1 第③步，逐字不变。**

本增补只加**扩展轮特有的两件事**（原文没有、也不该塞进原文的）：

1. **每格记账 = n_计入 + 1 预热丢弃**；取 n≥15 则每格 **16 次采集动作、15 条计入**（提案 §4.1）。
2. **取证格同样先跑一轮丢弃的预热**，口径同上——不是「丢弃取证第 1 轮」
   （那是 D-358 未被选中的选项②，改用它需另立决策）。

> ⚠ **彩排实证的硬提醒（F-3，诚实的否定）**：分析层**没有任何一个面**能指认哪条 run 是预热轮。
> 含预热轮与不含预热轮的两份语料，发布门**逐条同判**（FAIL 1 / WARN 8 / N/A 2），
> 差别**只出现在数字上**（网络侧 CV 由 ~5.7% 降到 ~2.6%），不出现在任何标记或判词上。
> 这与 D-366 的原话一致（台账是唯一能认出它的地方）。
> **推论：「预热轮排干净了没有」只能靠人对台账核，发布门永远不会替你发现漏排。**
> 收工清单因此有专门一项（§5）。

### 3.2 3×3 拉丁方轮转

- **缺陷来源**：D-353（quick 单一顺序，位次差与场景差不可分离）。
- **修法**：扩展轮以**取证模式**承载轮转；**轮转正确性已由 D-354 实测确认，不在此重新论证**。
- **方阵**见提案 §4.2（3 个场景位次的循环方；≥2 轮为**能不能算**的最低线，仍成立）。
  **每格轮数 = 5**（2026-08-01 裁定，见 §8 #3 落定段）——提案 §4.2 的「建议 4 轮」已作废。
- 语料形态：一条取证 run = 9 场景，`scenario_order` 为三个轮次以 `|` 连接
  （契约字段说明里给的就是这个写法）。
- 彩排实证：取证子集单独过门时，**序位效应 ✅ PASS**、**序位效应·单元混杂 ✅ PASS**、
  **预热效应 ✅ PASS**——D-353 的「拉丁方未轮转」在这一面上**已消失**。

> ⚠ **但必须单独过门**，理由见 §5 第 2 条。这是本次彩排最重要的一条发现。

### #3 落定：取证子集**每格 5 轮**（2026-08-01 裁定，D-379）

**判据**：一个数同时满足两条**互不相同**的判据，故不必在两者间取舍——

| 判据 | 数的是什么 | 5 轮为何满足 |
|---|---|---|
| 序位判据（提案 §4.2） | **每个执行位次**的样本数 | 一条取证 run 在每个 `order_index` 上各出一个场景，故每格 5 条 run ⇒ **每位次 n=5** |
| 样本充分性（`stability.DEFAULT_MIN_SAMPLES` = 5） | **每格的 run 数** | 每格 5 条 run ⇒ **n=5，不再 `low_conf`** |

**代价**：每格多一条 run ≈ **6.5 min**（彩排 F-5 口径），取证子集 8 格 ⇒ **约 +52 min**，
**不占额外外场日**（同一趟内完成）。

**明确不做的两件事**（写下来，免得下一个人以为漏了）：

1. **不动全局常量** `DEFAULT_MIN_SAMPLES`。它是热力卡/AQS 全局的样本门，为取证子集调低它
   会把**所有**格的置信门一起放松——用一个局部问题去改一个全局判据，正是 §2.2 那条红线。
2. **不加豁免逻辑**（例如「取证格跳过样本门」）。豁免要有人维护、要有守卫、还要有人记得
   它为什么在；把轮数从 4 提到 5 是**零代码改动**，两条判据当场同时成立。

**被这条作废的旧写法**（D-301 的纪律：判据换了，转述它的每一处都要跟着换）：

- 提案 §4.2「≥2 轮为最低、**建议 4 轮**」——建议值改 **5**；「≥2 轮为最低」仍成立（那是
  另一件事：能不能算，而不是算得准不准）。
- 本文 §3.2 对提案 §4.2 的转述（已改）。
- 本文 §8 #6 的「每位次 n≥4」（已改）。
- 彩排证据包 `README.md` 的 F-5 **不改**：证据包记的是**当时**的事实与当时的两条路，
  事后回填会让证据看起来早就知道答案。
