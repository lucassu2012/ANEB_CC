## 2. 测量口径与边界（**照抄，勿改写**）

本报告的测量口径为 **`application_end_to_end_to_probe_node`**——即**从客户端应用层到
本项目指定探针节点的路径**的端到端体验。具体含义与边界：

**本报告陈述的是**：
- 在**被测点位、被测时段、被测接入方式**下，本项目自研探针 App 与自建镜像服务端之间，
  应用层可观测的时延、抖动、吞吐、流式体验指标及其分段归因；
- 三级（同城/区域/中心）镜像端的**差分增量**，用于定位路径中哪一段贡献了时延。

**本报告不构成、也不得被表述为**：
- ❌ **MOS 或任何主观体验评分**——本项目未做主观打分实验；
- ❌ **无线层评级**（RSRP/SINR/覆盖质量）——探针不采集且无法推断无线层指标；
- ❌ **运营商全网 SLA 或网络质量结论**——测量样本仅覆盖上述有限点位与时段，
  且路径终点是本项目探针节点，**不是**运营商网络边界，更不是公众业务的真实服务端；
- ❌ **对任一 AI 业务 App 真实体验的测量**——本轮测的是探针与自建服务端，
  与商用 App 的服务端、协议栈、调度策略均不同。

**样本代表性声明**：本轮为**有限点位抽样**，不是全城普查；每格样本量见附录表格，
标注 `low_conf` 的格样本不足，其数值**不应单独作为结论依据**。

## 3. 方法学

### 3.1 测量对象
统一使用版本化 profile（【占位：本轮 profile 版本号，取自报告溯源段/记录 `profile_versions`】）
驱动三类业务场景：对话（`s1_chat`）、编码智能体（`s2_coding_agent`）、多模态（`s3_multimodal`）。
Profile 为**数据定义**而非代码分支，同一版本在所有点位完全一致，保证跨点位可比。

### 3.2 三级差分归因
同一客户端、同一接入、同一时段，对**同城 / 区域 / 中心**三级镜像服务端各测一轮：

```
接入分量      = median(RTT_同城)
区域骨干增量  = median(RTT_区域) − median(RTT_同城)
核心骨干增量  = median(RTT_中心) − median(RTT_区域)
```

三级共客户端、共接入、共时段，故**接入侧共模因素在差分中抵消**，增量项净化为骨干段贡献。
**约束**：任一层级缺测，该格增量记为不可计算（报告显示 `TIER_MISSING`），**不外推**；
出现负增量（区域快于同城）如实记为 `inversion`（可能源于路由/anycast/CDN 边缘），
**不静默归零**。

### 3.3 复测与反平衡
每格重复【占位：n，见「复测稳定性」段】次；同一格内场景顺序按拉丁方轮转以抵消执行位置偏倚，
报告「序位效应」段给出该抵消是否奏效的检验。复测变异系数 CV 超【占位：门限值，
取自溯源段「生效门限」】% 的格标为不稳定。

⚠ **写结论前必看「预热效应」段**（D-355/D-356）：**快测模式每场景只跑一遍**，
所以它测到的**永远是第一轮**，而实测首轮时延高 8–12%、吞吐低 10–16%。
若该段印的是「**只有一轮 → 无法校验**」，本报告的**每个绝对值都必须标明是冷启动口径**；
**跨格比较不受影响**（每格一样冷），但「TTFT 是 X ms」这类绝对表述必须带上这个前提。
取证语料下该段会给出逐 KPI 的「首轮劣势%」——**带疑似标记的 KPI，其绝对值以后续轮为准**。

### 3.4 数据处理
所有聚合取**中位数**（对离群稳健）；不可计算的量一律留空（报告中显示 `—`），
**绝不以 0 或默认值顶替**。失效场景不进入 KPI 聚合但计入分母，在「有效性」段可见。

### 5.2 分段归因

> ⚠ **深圳试点是单层级采集，本节的大部分写法用不上。** D-48 定为单实例 E-01 后，
> 归因矩阵里**没有骨干增量**——不是没测出来，是**数学上不存在**。报告会在该段开头
> 印一句 **本轮是单层级语料**；看到它，本节按下面这段写，**不要**照三层级的写法硬凑。
>
> **单层级下能写什么**：各点位**接入段绝对值**的横向比较（谁高谁低、忙闲差、运营商差）。
> **不能写什么**：任何带「骨干」二字的结论、任何「这一段比那一段大」的分解。
> **要连带写的**：接入段绝对值里**含无线与末端**，所以先看 §5.3 的「无线上下文」段——
> 若该点位被标 `CELL_CHANGED`，它的忙闲差里混着小区差；若该段印的是「采集缺口」，
> 就**明说本轮没有无线协变量**，接入段为何高只能存疑，不得归因于运营商。

【占位（**仅三层级采集适用**）：贴「三级差分归因矩阵」+ 说明各点位时延主要由哪一段贡献。
主导段的分布与最大单项已由摘要的「分段归因」信号给出，可直接引用。
注意区分"接入分量大"与"骨干增量大"——前者含无线/末端，后者才是骨干。

**写建议前必看「分段异常定位」段**：某一段的最大单项若**未越过筛查阈值**，它只是该段
分布里的最大值，**不构成"该点位这一段有问题"**——把它写成点位问题，就是派人去查一个
并不存在的故障。反过来，某段若在**所有单元**都同样大，那是本次测量路径的共性
（例如到中心镜像端的物理距离），应如实说明，**不得表述为运营商骨干缺陷**。
只有该段标出**存在单点异常**、且列出了具体单元，才谈得上写"该点位该段异常"。
另注意：`未见单点异常` ≠ 各单元相同，齐不齐看该段的 `离差/典型` 列。

**但「存在单点异常」本身也不是证明**（D-200）：该筛查按可比单元数标定到"干净网格误报 ≤5%"，
而那是**对称分布**下的口径；**时延右偏，实测误报率仍有 7%（4~5 单元）到 26%（48 单元）**，
该段 `判读` 列的判词后面就跟着本段实测值。所以正确读法是**"这一格值得去看一眼"**——
**先去核实**（回查该点位该轮的原始 run、层级端点、介质与时段是否真的同质），
核实站得住才写进结论；核实不了就写成"待复核项"，**不要直接落成"该点位该段异常"**。
反向同理：该筛查只抓得住很粗的异常（+5 稳健 σ 的真异常约一半会漏），
故 `未见单点异常` **更不能**写成"该点位这一段没问题"。】

### 5.3 忙闲与接入介质对比
【占位：贴忙闲差异与「接入介质对比」段的 Δ(cellular−wifi)。

**噪声尺度在这一节同样是红线**（与 §5.4 同口径，别只在那一节守）：介质 Δ 也是两个中位数
相减，段内每格都带 `±` 噪声量级与备注列。标 `噪声内` 的格**不得**写成"蜂窝劣于 wifi"——
那是复测抖动；标 `噪声不可估` 的格是"不知道"，同样不计入结论。摘要若说
**"未观察到超出测量噪声的介质差异"**，正文就照此写，**不要**挑符号为负的几个格来讲故事
（彩排语料实测：7 个 Δ 为负的格**无一**超出噪声）。忙闲差异同理。】

【占位：贴「无线上下文」段。**忙闲差在这一节要先过一道前置检查**——该段的
「忙闲可比性」表若把某点位标 `CELL_CHANGED`，说明它忙时与闲时挂的**不是同一小区**，
那么该点位的忙闲差里混着小区差，**不得**单独归因于时段；`CELL_PARTIAL` 同理折损可信度。
若该段印的是「采集缺口」而非表格，照抄那句话——**那不是「信号良好」**，
而是无线上下文尚未接进导出契约（见 `RADIO_CONTEXT_WIRING_SPEC.md`），
本轮的分段归因也因此只剩接入段绝对值一列。】

### 5.4 优化前后 / 纵向趋势
【占位：仅在有多轮战役时填写，贴「优化前后对比」或「纵向趋势」段。单轮测量删除本节，
**不要**用单轮数据讨论趋势。

**噪声尺度是本节的红线**：Δ 旁带 `±` 的是该格测量离散度推得的指示性噪声量级。标
`噪声内` 的格**不得**写成改善或回退——那是复测抖动，不是效果；标 `噪声不可估` 的格
（样本不足）同样不得计入结论，它是"不知道"，不是"没变化"。若全部格都落在噪声内，
本轮的诚实结论是**"未观察到超出测量噪声的变化"**，请照此写，不要挑一两个格来讲故事。
该尺度是正态近似下的量级指示，**不是显著性检验**，正文也不要把它表述成 p 值或置信区间。】
