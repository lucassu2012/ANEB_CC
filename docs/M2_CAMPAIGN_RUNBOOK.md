## 0.5 出发前彩排（强烈建议：外场前一天跑一次）

用合成全网格语料把整条链路预演一遍，确认工具、参数、阅读方式都就位——
**不要**在外场当天第一次见到规模化报告长什么样。

**分两趟，各练一件事**（合成一趟会两头都练不到，原因见下）：

**A. 补注演练**——练整条链路上最容易出错的那一步：

```
python synth_campaign.py -o rehearsal_raw.jsonl --unlabelled --points 2 --repeats 3
python annotate_campaign.py rehearsal_raw.jsonl -o rehearsal_labelled.jsonl --set campaign_id=drill --set point_id=DRILL-01 --set carrier=cmcc --set tier=metro --infer-time-band
```

`--unlabelled` 让语料与**今天 app 的实际输出一致**（标签接线未落地 = 无 `run.campaign`）。
注意这一趟会把**所有记录压成同一点位、同一层级、同一战役**——那正是 `--set` 的语义，
**不是**用来看报告的语料。

**B. 读报告演练**——用带标签的满网格语料，看报告真正的样子：

```
python synth_campaign.py -o rehearsal_full.jsonl
python campaign_report.py rehearsal_full.jsonl --md r.md --html r.html --csv rt
python campaign_report.py rehearsal_full.jsonl --campaign SYNTH-opt --md r_opt.md --csv ropt
python publish_check.py rehearsal_full.jsonl
```

**第二条报告命令不是多余的**：彩排语料含两个战役，而归因段的格键不含战役，
于是**全量报告里 192 行归因，192 行都带 `MIXED_CAMPAIGN`——一行干净的都没有**。
照手册只跑第一条，操作者在彩排里**永远看不到一行他外场真正要读的归因**。
限定战役后该标记归零，其中 58 行完全无标记（D-270 实测）。

（`publish_check` 必然报 FAIL：彩排语料本就是合成的，正是它该拦的。）

**C. 无线上下文演练**——A/B 两趟的语料都**不带无线数据**，所以「无线上下文」段
在它们身上只会印一句「采集缺口」。那正是**外场当前会看到的样子**（接线尚未落地，
见 [`RADIO_CONTEXT_WIRING_SPEC.md`](RADIO_CONTEXT_WIRING_SPEC.md)），但操作者还需要
认得该段**有数据时**长什么样——尤其是那条会让忙闲对比失效的标记：

```
python synth_campaign.py -o rehearsal_radio.jsonl --radio --tiers metro --campaigns SZ
```

```
python radio_rollup.py rehearsal_radio.jsonl
```

> **为什么必须分两趟**：A 趟的 `--set point_id=…` 把 8 个点位压成 1 个、三层级压成 1 层、
> 两个战役压成 1 个，于是热力卡只剩 2 格、归因矩阵只有同城一层、
> **「优化前后对比」整段根本不存在**——而那一段的噪声尺度恰是全报告最难读的部分。
> 从前的单趟彩排就是这样：手册叫人看热力卡颜色分布与层级增量，而彩排给不出来（D-182）。

### 彩排的正确答案（B 趟对着核，不是"看看而已"）

合成语料是**按已知答案设计**的（见 `synth_campaign.py` 的 `DESIGNED_EFFECTS`）。
对不上就是工具链坏了，不是数据没效果：

- [ ] 「优化前后对比」把 **`SYNTH-P05`** 的格判为**超出噪声**且方向为改善，摘要点名它。
      **若报告说全部格都在噪声内 → 改善检测路径已坏，不要带去外场。**
- [ ] 其余点位的 opt 改善判为 `噪声内`（设计上就小于噪声）——这是**正确**行为，不是工具迟钝。
- [ ] 「接入介质」信号说**未观察到超出测量噪声的介质差异**，**不**点名"蜂窝劣于 wifi"。
- [ ] 「无线上下文」段在 A/B 两趟里说的是**采集缺口**，**不是**「信号良好」——
      看到「信号良好」四个字就是判据坏了。
- [ ] **深圳试点的报告里，归因段不该出现 `TIER_ENDPOINT_UNVERIFIED`。**
      这一趟只有一台服务器（D-48），合法的 `tier` 只有一个值，该标记因此不会触发。
      **一旦看见它，就说明有人把标签标成了不止一层**——而那些层级没有对应的服务端，
      于是矩阵里的「区域骨干+ / 核心骨干+」是**编出来的数字**（D-292 实测：数值恰好单调时
      它们会以零标记、不低置信的样子印出来）。处置：回查该批 run 的层级标签，
      改回实际打的那一个，重出报告；**不要**保留那几列去讲骨干。
- [ ] C 趟里该段出得来**弱/中/良三档**，且 `SYNTH-P05` 被标 **`CELL_CHANGED`**：
      该点位忙时与闲时挂的不是同一小区，**它的忙闲差不可单独归因于时段**。
      外场遇到这个标记，要么补测、要么在报告里照标不解释。
- [ ] 热力卡有明显颜色梯度（末位点位最差），归因矩阵三层级增量齐全。
- [ ] 报告顶端有红色合成数据警告；CSV 能被你的表格工具正常打开（中文点位名不乱码）。
- [ ] **对比 `rt_attribution.csv` 与 `ropt_attribution.csv`**：前者 192 行**全部**带
      `MIXED_CAMPAIGN`（两个战役池化在同一格，增量既不是前也不是后），后者该标记**归零**、
      58 行完全无标记。**这才是外场要读的那种归因行**——只跑全量报告的话，你在彩排里
      一行都见不到。若限定战役后标记仍在 → 战役过滤已坏，别带去外场。

> ⛔ 彩排产物**数字全是虚构的**。见到红色合成数据警告的报告**一律不得**外发或作为任何
> 结论依据。彩排文件用完即删，**绝不可**与外场语料放同一目录。

另外重点看：摘要各条信号的读法、稳定性段的省略声明。

## 2. 补注战役标签（app 侧写入落地前的桥）

> ⛔ **最容易犯的错**：一天的语料跨**多个点位**，而 `--set point_id=X` 会把它们**全部**
> 打成同一个点位——标签看起来完全正常，热力卡却是错的，下游无人能发现。
> **按点位分目录**（推荐）或用 `--map` 按 run_id 精确打标。多文件配统一 `point_id` 时
> 工具会告警，但它无法替你判断这些文件是否真的同点位。

> ⛔ **本轮只有一个层级**——部署形态是**单实例 E-01**，三级（同城/区域/中心）差分已于
> **D-48 由 PO 拍板放弃**，2026-07-29「利旧现有服务器、不再增加新服务器、仅深圳试点」再次
> 确认。**不要照旧版流程去跑 regional / core**：那两个镜像端**不存在**，跑出来的只会是打错
> 标签的同城轮次，而报告会把它们当作真实的骨干增量呈现。合法的 `tier` 只有 `metro` 一个值。
>
> ⛔ **同一格内仍不得中途换条件**：不换运营商、不跨忙闲边界，**也不要在 wifi 与蜂窝之间切换**。
> 这条红线在单层级下**没有失效，只是理由变了**——不再是「层级间增量混进介质差」，而是
> **该格的绝对值不可混池**（同一格里一半 wifi 一半蜂窝，中位数两种都不代表）；报告标
> `MIXED_TRANSPORT` 并在归因段写明本轮含义（D-157）。
>
> 📌 **原三层级红线的去向**（留档，别当它凭空消失）：铁律 3 的共模抵消要求三层级条件相同，
> 报告为此核对层级间测量间隔并标 `TIER_TIME_SPREAD:Xh`。单层级下**层级间差分不存在**，
> 该核对项在报告里如实印为「**不适用**（本轮 N 个单元无一覆盖 ≥2 层级）」——**不是「已核对」**。
> 归因矩阵因此只有接入段绝对值，`PLAN_ALIGNMENT` §7.3 点名的替代协变量（无线上下文、
> 忙闲、双运营商）是本轮的主要对照维度。

采集时按**点位**分目录存放（`raw/SZ-CBD-01/`、`raw/SZ-CBD-02/`…），**逐点位**补注：

```
python annotate_campaign.py raw/SZ-CBD-01/*.jsonl --out-dir labeled \
    --set campaign_id=sz-2026Q3-baseline --set point_id=SZ-CBD-01 \
    --set carrier=cmcc --set tier=metro --infer-time-band
```

> ⛔ **`--set tier=metro` 要显式写上，别省**。省掉它标签就是**缺失**而不是**声明**：报告分不清
> 「这一轮就是同城」与「没人填这个字段」，单层级横幅与层级对账两处都会退回「无从核对」。
> 多文件配统一 `tier` 时工具仍会告警——**看见就停下**，确认这些文件确实来自同一层级（D-189）。
>
> 📌 若将来恢复多层级部署：**同一格内三层级必须连续测完**（同城→区域→中心一轮接一轮）、
> 按 `raw/<点位>/<层级>/` 分目录、每层各跑一条 `--set tier=…`；只跑一条会把整个点位打成同城，
> 另外两层被**标没**（报告报 `TIER_MISSING:regional,core` 说它们没测过，而你明明测了）。

若已混装在一个目录里，用 `--map map.json`（`{run_id: {point_id: …}}`）按台账精确打标。

`--out-dir` 输出同名文件、不动输入；若输出会覆盖输入或不同目录存在同名文件，工具**直接拒绝**
（分别提示用 `--inplace`、或先改名）。单文件仍可用 `-o`。

- 非破坏：只填 gap、原有标签永不覆盖、`label_source` 记溯源。
- `--infer-time-band` 按 `started_at_epoch_ms` 推忙闲（跨时区采集给 `--tz-offset`）。

## 3. 覆盖检查（外场期间每日收工跑）

```
python coverage_matrix.py labeled/*.jsonl --config ../docs/campaign_grid_shenzhen.json
```

未测/欠采格 = 明日路线；**计划外**格 = 疑似误标，回查台账。

⚠ **样本列是本工具能给的全部重复证据，它查不出「重跑凑数」**（D-344）：契约里没有
run 级重复编号——`scenario.repeat_index` 是取证模式内的遍数（快测恒 0），与战役重复
无关；所以「12 条是 12 次重复还是 3 次重复各跑四遍」工具**判不了**，崩溃重跑写的是
新 `run_id`，去重也看不到（D-340 曾按 `run.repeat_index` 设「不同重复」列，但该字段
无人生产，真实数据上恒为全体无编号，已撤）。**重复数的可信来源是现场台账**：每格每
完成一次重复画一道，画满 n=11 才算采满；收工时拿台账对样本列——**两边都到 11 这格
才从明日路线划掉**，对不上的按台账回去补。

**第一个点位测完当天，另跑一次采样量核算**（这时改采集计划还来得及）：

```
python stability.py labeled/day1/*.jsonl --plan
```

**每格复测数已定为 n=11**（提案 D3，2026-07-30；v1.0 的 5 是按 CV≈5% 推的 63% 把握，
11 才是「八成把握」的拐点，且单层级后总工时仍低于原计划）。若结论行说"X 个单元在当前 n 下**没有 80% 的把握**看见
5% 的差异"，按表里 **`需 n≥(80%)`** 那一列上调剩余点位的复测数；n 不够又照测下去，
最后拿到的是一堆标着 `噪声内` 的格——**那时已经补不了**。反之若实测离散度明显小于假设，
可据此收缩复测数省出外场工时。离散度不可估（n<2）的单元不计入核算，别把它当成"达标"。

⚠ **两列 `需 n≥` 不要看错**（D-201）：`需 n≥(平)` 是让目标差异**正好等于**噪声尺度的复测数，
在那个 n 上真实差异只有**约五成**会被判为「超出噪声」——**照它上调等于把把握定在抛硬币**。
规划一律看 `需 n≥(80%)`，它约是前者的 3.4 倍。若因工时上不去而维持较低的 n，
**那就要在报告结论里认账**：本轮只能给量级指示，**不得**写"本轮未见改善说明优化无效"
（把握不足时，「没看见」与「不存在」分不开）。

⚠ **两列 `可辨最小差异` 同理**（D-240）：`可辨最小差异(平)` 是恰好等于噪声尺度的差异——
真有那么大的差异，也只有**约五成**会被判为「超出噪声」；`可辨最小差异(80%)` 才是这一格
**有 80% 把握分辨出来**的差异，约为前者的 1.842 倍。右侧「达标?」按 80% 判定，
所以**要拿来回答"这一格能分辨多大的变化"的，是 `(80%)` 那一列**。

## 4. 出报告（入口自动跑契约门，坏语料拒绝出报告）

```
python campaign_report.py labeled/*.jsonl \
    --md report.md --html report.html --csv tables --provenance provenance.json
```

**语料里有多个战役时（优化轮之后必然如此）**：除「优化前后对比」/「纵向趋势」两段外，
**其余各段会把所有战役按格池化**——那个中位数**既不是前也不是后**（受影响的格标
`MIXED_CAMPAIGN`，报告顶部也会提示）。正确做法是**各出各的、再出一份对比**：

```
python campaign_report.py labeled/day1.jsonl --campaign sz-2026Q3-baseline --md report_base.md
python campaign_report.py labeled/day1.jsonl --campaign sz-2026Q3-opt --md report_opt.md
python campaign_report.py labeled/day1.jsonl --before sz-2026Q3-baseline --after sz-2026Q3-opt --md report_compare.md
```

**头条数字取自单战役报告**；混合那份只用来看对比段。战役名打错时工具 exit 2 并列出语料中
实际有哪些战役，不会给你一份空报告。

> 出表之后要**组装成交付物**（工具产出的是表格集合，不是报告）：
> 骨架见 [`M2_REPORT_TEMPLATE.md`](M2_REPORT_TEMPLATE.md)——口径边界/方法学/免责措辞
> 已预写（§2 为红线，照抄勿改），结论与数字留占位并注明从哪一段取。

产物：markdown 报告 + 自包含 HTML + **成套 CSV**（运行时逐个打印文件名，照单归档）+
溯源 sidecar（输入文件 sha256 / 去重与坏行计数 / 塑形参数——归档必带，
"进局点的弹药"须可复现）。优化前后对比给 `--before ID --after ID`；
≥3 个战役自动出纵向趋势段。

## 5. 发布前复核（先跑自检，再过人工项）

```
python publish_check.py labeled/*.jsonl
```

FAIL=客观错误**阻断发布**（混入合成语料 / 契约违规 / 全无标签），退出码 1；
WARN=**须由人解释**后才可发布（**具体项以 `publish_check` 的实际输出为准**，不在此复制清单——每加一项这里就会过期；含低有效率 / 失真热点 / 时钟可疑 / low_conf / 序位效应 /
效应量 / 战役池化 / 标签来源 / 否决封顶 / 层级同时性 / 同一接入 / 同一客户端）；
**N/A**（`➖`）=**本项无可核算对象，未作判断**——单战役谈不上前后效应量、无同格双介质可比谈不上介质差异；
**它不进退出码**（`exit 1` 只由 FAIL 决定），但**也绝不读作"没问题"**。
**"无法判断"分两种，一律不记 PASS**：**有对象而缺证据**（有格但无 `server_tier_endpoint`）→ **WARN**，须由人解释；
**连对象都没有** → **N/A**。PASS 的含义是**该项已在非空集合上核查且未见问题**（D-229/D-238）。
自检覆盖不了的人工项仍需逐条过：



- [ ] 契约门通过（无 `--skip-contract-check`；stderr 无"未经校验"告示）
- [ ] 「有效性」段：各格有效率 ≥80%，无 `LOW_VALID_RATE`（有则先解释失效原因直方图）
- [ ] 「覆盖盘点」无意外 `unlabeled` 桶（有 = 漏打标）
- [ ] `low_conf`（n<5）格已在正文标注、结论不依赖它们
- [ ] 「批化归因」段无未解释的 `失真热点`（有 = 先做失真核算再谈网络结论）
- [ ] 「序位效应」段无显著位置-KPI 相关（有 = 反平衡失效，样本重采）
- [ ] 多轮战役时，「优化前后对比」中标 `噪声内` / `噪声不可估` 的格**未被写成改善或回退**
      （自检的「效应量」项即此；全部落在噪声内 = 本轮**没有可宣称的效果**，如实写）
- [ ] **整轮战役全部由同一台设备采集**（⚠ 契约无设备标识字段，**工具无法核对**，只能靠
      采集方确认，D-156）。**本轮是单层级，所以别照旧版只问「三层级是不是同一台」**——那句话
      在一层的语料上**恒真、可以不假思索地打勾**，而真实风险是**跨点位/跨轮次中途换机**：
      机型差异会整个落进**该格的绝对值**（不再是骨干增量），照样一个标记都不会有
- [ ] 报告落款 claim_scope 原话在（`application_end_to_end_to_probe_node`，
      不表述为 MOS/无线层评级/运营商全网 SLA）
- [ ] **报告顶端无红色「合成数据警告」**（有 = 混入了彩排语料，立即停止外发）
- [ ] 归档四件套：report.md + report.html + tables_*.csv + provenance.json
