## §6 重写回归扫描（v1 没有而 v2 有的问题 ／ 被删掉的强项）

1. **去重键在 v2 里没有定义（v1 明写的那一句被删），而 判据 §1.2 把记录扩成 8 字段含 SrcAddr/TTL**（high）— v1 判据 §2 有一句显式定义：「身份读数（每格都取，不单列一格）：`(recvLen, ip.ID, icmp.seq)` 的**去重个数**与重数分布」。v2 删掉了这句，判据 §1.2 改成「每包记录 **8 个字段**」（含 `ip.SrcAddr`、`ip.TTL`），而 判据 §4.1 整张表仍然只说「去重 ∈ …」，全文再没有一处说去重用哪些字段做键。最自然的读法是「按 判据 §1.2 记下来的那条记录去重」——而 SrcAddr 正是 NAT 会改的字段、TTL 正是转发会减 1 的字段。 ⇒ C1 跑出 H1 形态（同一数据报在 NAT 前后各被呈现一次）。实现者按 判据 §1.2 的记录去重：两次目击的 SrcAddr 不同、TTL 差 1 ⇒ 40 条互异记录、重数全 1 ⇒ 精确落进 判据 §4.1 第二行「去重 ∈ [2T−4, 2T] 且重数 1 占比 ≥90% ⇒ **是不同的包，不是倍增**」。这正是裁定 blocking #2 要防的那个反向结论，v2 把它从「缺字段」搬成了「缺键定义」，且新表的区间让它落得更干脆。判据 §4.1 那两行子判词还在用「三元组相同」这个 v2 已不再定义的词，操作者只能现场即兴。

2. **判据 §5 那个最贵的干预：既没有格定义，也没有任何判词——H4 在 v2 全文消失**（high）— v1 判据 §4 写死了两件事：干预是「把移动热点关掉，**再跑一次 A 格**」，以及读数怎么判——「A 掉到约 20 ⇒ 两格同因（ICS 造成）；仍约 40 ⇒ 确为不同因」。v2 判据 §5 只保留了前提侧（PC 侧读数、三态化、排序），把这两件都删了且没有替代：全文 `grep H4` 零命中；判据 §3 的 12 格矩阵里没有这一格（没有层、没有 filter、没有谁打、没有 T）；判据 §5 四条规定里反复出现的「该格」在本节没有先行词，唯一的线索是 164 行一句附带的「判据 §5 那个要 PO 亲手关热点的干预」。 ⇒ PO 花掉那个受监督的提权设备窗把热点关掉，脚本按 判据 §5-1 印全 PC 侧读数、按 判据 §5-2 确认「热点已关」，然后跑那一格——跑的是哪一层、什么 filter、打多少个包由操作者现场决定，出来的计数再对照 判据 §4：判据 §4.1 只判身份（去重/重数），判据 §4.2 是 F1/F2/C1，判据 §4.3 是 impostor，**没有一条把这个计数映射到「同因/不同因」**。于是这一次性的一个比特要么现场即兴一条规则（预登记当场失效），要么白花。裁定 blocking #4 已裁过「干预被花掉」这个代价，v2 在修 #5 的前提时把 #4 关心的那个结论侧一起删了。

3. **判据 §4.1 新增的「去重 < T−2 ⇒ NOT_EXECUTED 重跑」与 判据 §4.2/判据 §4.3 新写的零读数判词互斥（联立无解）**（high）— v2 新加了两条针对**零/小读数**的判词：判据 §4.2「`F1 == C1` 且 `F2 == 0` ⇒ 不可判」、判据 §4.3「`I ≈ 0` ⇒ 该位在本路径未观测到置位」。同时 判据 §4.1 新加了第三行「去重 **< T−2** ⇒ 丢包或收尾截断过多 ⇒ **该格 `NOT_EXECUTED` 重跑**」，而这张表没有任何格别限定（行文是「该格」，判据 §3 说身份对每格都取）。F2=0、I=0 的去重都是 0 < T−2 ⇒ 同一读数同时命中两条互斥判词。判据 §1.3 新加的「跑中结构自检：seq 多重集须覆盖 ≥ T−2 个不同值，否则该格身份判 NOT_EXECUTED，**不产出读数**」是第二条独立通道，对 I1/I2/F2/N2/S1/S2 这些**合法就该小于 T−2** 的窄格同样恒不满足。另外 判据 §4.1 结尾刚写「构成一律按每包日志事后查询，**不与身份判定共命运**」，而第三行判的是「该格 NOT_EXECUTED」——整格作废正是共命运，同一小节自相矛盾。 ⇒ F1=40、F2=0 跑出来：按 判据 §4.2 应记「不可判」并写进证据；按 判据 §4.1 第三行应判该格 NOT_EXECUTED 并**重跑**——重跑要再占一次 FORWARD 窗，而 判据 §5 的顺序约束又要求所有 FORWARD 格跑在干预之前。操作者只能现场选一条，预登记失效；若选了「重跑」，一个稳定为 0 的读数会被反复重跑直到窗耗尽。I≈0 同理。

4. **判据 §1.3 第 ③ 组合成包用例：期望值与它自述的目的相反，且对它点名要防的失败模式零区分力（这是一道不过即整轮作废的门）**（high）— 判据 §1.3 ③ 写：「**只改 `icmp.Id`** 其余字节不动的两个包 ⇒ 去重 **2**（证明 `Id` 确实**不在**键里…）」。逻辑是反的：若 `Id` 不在键里、其余字节又完全相同，两条记录在键上就是同一条 ⇒ 去重必须是 **1**；得到 2 恰恰证明 Id **在**键里。更要命的是它同一段点名的失败模式——「或读成 `icmp.Id`（同进程恒定）」，即 seq 的偏移错指到 Id——在这个用例上给出的**也是 2**：正确解析器（键不含 Id）得 1、被点名的坏解析器得 2，判据写的是 2 ⇒ **正确实现挂、被点名的 bug 过**。若改成按 判据 §1.2 的 8 字段整条记录去重，则两者都得 2，区分力为零。v1 没有这道门，是 v2 新写的。 ⇒ 跑前 pytest 阶段：实现者按 判据 §1.2+判据 §4.1 用三元组键写出正确解析器 ⇒ 用例 ③ 得 1 ≠ 2 ⇒ 门不过 ⇒ 按字面「整轮作废」，设备窗还没开就废掉；或者实现者为了让门变绿把 `icmp.Id` 塞进键里，于是键里多了一个同进程恒定的字段，再叠上缺陷 1 的键歧义，H1 世界更稳地落进「不是倍增」。

5. **判据 §1.3 的「seq 落在 `1..T` 内」是从发包数推出来的取值域，没有测量支撑，且 判据 §1.2 没规定字节序**（high）— v2 新加的跑中结构自检写死「观测到的 `seq` 多重集须**落在 `1..T` 内**且覆盖 ≥ T−2 个不同值」。`T` 在 判据 §3 定义为「该格实际印出的**发包数**」——于是这条判据把「发了几个包」直接当成了「seq 的取值域」，正是房规「每个数必须溯到测量，不得从旁边的常量推出来」点名的形状；文件自己在 判据 §2 还立过「常量不许写死，现场推导」。两处配套缺口：①`icmp.Seq` 在 判据 §1.2 只给了偏移 `IHL+6..7`，**没有规定字节序**，而这条范围检查是全文唯一对 seq 取值敏感的地方；②Windows 侧 `ping.exe` 的 echo 序号是按启动累加的全局计数器（抓包里常见的大端读数是 256/512/768…，并不从 1 起、也不随每次调用归零），Android 侧 `ping -c` 才是 1..N。本份对此没有任何实测记录。 ⇒ A1/A2/I1 三个 PC 打的格：脚本按大端读 seq，得到 256、512、768…，既不在 `1..T` 内也覆盖不满 T−2 ⇒ 三格身份一律 `NOT_EXECUTED`、不产出读数；A 侧那个 40 的分解当场关闭，而门是绿的、仪器没坏、收尾码正常——与 判据 §2 描述的「静默失败」同形。反方向同样坏：若实现者为了让它过而现场放宽范围，这条自检就退化成没有判据。

6. **判据 §4.2 只写了排除支：H2 成立/不成立的判词被删，守恒式既非「精确」也没有容差区间**（high）— v1 判据 §3 有正面判词：「`F1`／`F2` 各约 20 ⇒ 每条腿各一次（H2 在转发层成立）；集中在一条腿 ⇒ 不成立」。v2 判据 §4.2 只留下一条 🔴 跑前写死的**排除支**（`F1 == C1` 且 `F2 == 0` ⇒ 不可判），全节再无一行说 F1/F2 怎样才算 H2 成立或不成立。同时它把 `F1 + F2 == C1` 定为「首要判别器（**精确**、与 n 无关、误分即可检测）」——但 F1、F2、C1 是 判据 §3 矩阵里**三个独立的格、三次独立的 20 个 ping**，不是同一次捕获内按 filter 的划分，所以这不是恒等式，而是三次运行的经验相等；而「不相等时怎么判」没有容差区间、没有样本量推理、也没有任何判词（房规：每个门限必须是跑前写死的确切区间）。 ⇒ 最可能的实际读数：C1=40、F1=38、F2=2（设备在三次 ping 里各丢 1–2 个、或 F 格被收尾宽限截掉最后一次目击）。`F1+F2=40 == C1` 偶然成立，但 F2=2 既不满足排除支（F2≠0）也没有任何判词说这算不算「集中在一条腿」；反过来 C1=40、F1=20、F2=19 时 `F1+F2=39 ≠ 40`，「首要判别器」判假，而文件没说这意味着 H2 被否、还是该格作废、还是重跑。两种情况都只能现场即兴，而 FORWARD 格在 判据 §5-4 之后不得再跑。

7. **N1/N2 两格在 v2 里没有任何判词，v1 那条「必须与身份读数联合判」的告诫一并丢失**（high）— 判据 §3 矩阵保留了 N1（`ip.SrcAddr == <设备 src>`，NAT 前）与 N2（`!=`，NAT 后）两格，但 判据 §4 三小节分别覆盖身份（判据 §4.1）、F1/F2/C1（判据 §4.2）、impostor（判据 §4.3），**没有一行提到 N1 或 N2**。v1 判据 §3 有：「`N1`／`N2` 各约 20 ⇒ NAT 前后各一次；但 🔴 **该读数同时也是「两个不同源地址的包」的读数** ⇒ **必须与身份读数联合判，单独出现不作结论**」——判词和那条歧义告诫在 v2 里都没有落脚点。 ⇒ N1=20、N2=20 跑出来。没有预登记判词，读者按最自然的读法记下「NAT 前后各一次 ⇒ 同一数据报被呈现两次」——而 v1 明确警告过：同样的读数在「两个不同源地址的、本来就不同的包」那个世界里一模一样。v2 把 SrcAddr 拆分支放进了 判据 §4.1 的第一行（只在去重 ∈ [T−2,T] 且重数 2 时才触发），N1/N2 的计数走的是另一条路径，于是这条告诫对它们不再生效，一个含义相反的世界被读成结论。

8. **判据 §4.3 的分母「同窗计数」在 判据 §3 矩阵里不存在；区间无样本量推理，且 (0.6, 全部) 之间无判词、I=1 同时落两行**（high）— v2 把 v1 的 `≥5` 退役，换成「impostor **占同窗计数** ∈ `[0.4, 0.6]`」。问题在分母：I1 与 A1、I2 与 C1 是 判据 §3 矩阵里**四个独立的格、四次独立的 ping**，I 格的 filter 带 `and impostor` ⇒ 该格内部量不到总数，「同窗」在本份里没有任何一格实现它；文件也没说 I1 该除以 A1 还是别的。区间本身也无样本量推理（房规要求，且 判据 §4.1 的区间是由 T 推出来的、判据 §4.3 的 0.4/0.6 从何而来没写）。四行判词还有两个洞：①`I ≈ 0` 与 `0 < I < 下界` 对 I=1 同时为真；②占比落在 (0.6, 全部) 之间——例如 0.8——**不属于任何一行**。 ⇒ I1=24 跑出来。分母取哪一个：A1 是上一格跑的 40（比值 0.6，压在上界上）、还是 I1 自己那次 ping 的 T=20（比值 1.2，超出全部行的定义域）？两种取法给出相反结论，而判据没写。再如 I1=32/A1=40=0.8：既不在 [0.4,0.6]、又不是 ≈0、又不是 0<I<下界、也不是 ≈全部 ⇒ 读数落不进任何判词，现场即兴。v2 在 判据 §4.1 刚立「区间，不用『约』」，判据 §4.3 又用回了「≈」。
