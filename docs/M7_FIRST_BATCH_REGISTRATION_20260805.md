## 3. 独立复核 D-487 的登记级判读——结论：数字判读正确，但发现一处转述误差

D-487 原文判读："五值全部落在锚点表前三段内，无一接近 400ms 强否决区，更无一接近

**独立复核（不是照抄，是重新分桶验算）**：按上表逐值分桶，**5/5 确实全部落在
<60ms / 60-150ms / 150-400ms 三个区间**，无一进入 400-1000ms 或 ≥1000ms——**D-487

≥400ms"才够格写"1000 末点缺乏真实分布支撑"，本批 n=5 远未达该门槛，**"不支持也不
否定"这个双重否定的克制措辞是恰当的**——没有借着一批小样本就倾向性地暗示 1000
该调或不该调，符合预案"诚实的确认与诚实的异议同样是产出"的原则。

**发现一处需要订正的转述误差（不影响 M7 判读，但既然是登记备忘就如实记）**：大脑

## 4. voiceNearZeroArrivalRatio 是否有信息量、要不要接消费方

**首批实测值（id 4-9，n=6）**：0.0062, 0.0, 0.0124, 0.0342, 0.0280, 0.0078——
数值**在 0%~3.4% 之间连续变化，不是恒定值/恒零**（区别于本项目已反复咬中的
"低置信恒为真"那类退化信号，如 T1/U1 的 `low_confidence` 在试点语料里 306/306
恒真——那种字段才是"有字段没信息"；这里的值本身在变，说明它确实在测量某种
逐会话不同的东西）。

**判断**：这个字段**有信息量**，不是死字段，但当前**完全没有消费方**——
`VoiceTestScreen.kt` 全文件零命中（T50 协议③已核实），是标准的 D-276 反模式
（"契约里要打分/落库了，wire/UI 上从未出现"）。**不建议在外场暂停期紧急补一个
消费方**——n=6 仍是登记级规模，现在急着接线不会比多攒几批数据更有信息量，且当前
项目纪律（呼应 D-475 对 TTFT 归因调查的处理）是"暂停期不为暂停中的用途预先做
额外工作"。**建议登记为条件触发项**：等 M7 累计到回核级规模（≥30 会话）、需要
正式写 §2 分布报告时，**顺带**给 `voiceNearZeroArrivalRatio` 补一个最简单的展示位
（比如 `VoiceConclusionCard` 子分行旁加一个百分比，不需要独立详情页），成本很低，
但不必现在单独立项去做。
