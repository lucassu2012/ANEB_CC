## 3. 主轴 B:UDP × contend:N 设计

### 3.1 核心设计缺口与方案
现仓 UDP 探针(SpeedRunner)与 contend:N(TestEngine)**分居两 runner,永不叠加**。要观测"UDP 未返回率/RTT 是否随自拥塞上升",需把二者合流。

- **方案 A(首选,口径最干净,改动最小)**:把 contend 伴流引入 `SpeedRunner.run()`,在 Ping/UDP 探针**之前**起 N 条背景下行大流,run 末取消 → 现有单次 UDP 探针天然落在拥塞窗内。
- 方案 B(备选):在 TestEngine token 模式加一趟 UDP 探针。缺点:token 模式已复杂,UDP 口径混入 token 流易被误读为进分。**不采**。

采方案 A,并把 contend 解析抽成共享纯函数供两处复用与单测。

### 3.3 预期观测(假设表,诚实标不确定项)`[被设备阻]`
关键口径:contend:N 压的是**接入链路共有队列**,UDP(无拥塞控制、无重传)与 TCP 背景流共排队,故与"服务端合成整形只碰 TCP、豁免 UDP"**本质不同**——contend **应当**影响 UDP。

| 观测量 | 基线(contend off) | contend:N 下 | 机理 | 方向置信 |
|---|---|---|---|---|
| UDP 回显 RTT 中位数 | 低(~echo RTT 量级) | **显著↑** | bufferbloat 排队时延暴涨(TCP RTT 已实证 24→60–66ms) | 高(应↑) |
| UDP 回显抖动 | 低 | **↑** | 队列深度波动 | 高(应↑) |
| **UDP 未返回率(unreturnedPct)** | 多为 0 或 null | **可能↑,也可能仍 0** | 仅当膨胀队列**尾丢**溢出时才丢包;17B×20 小包/1s 未必触发溢出 | **不确定**(honest) |
| reordered | 0/低 | 可能↑ | 队列重排/多路径 | 中 |

**必须诚实声明**:RTT/抖动上升方向明确;**未返回率方向不确定**——若队列不溢出,20 个小包可能全回显(unreturned=0),这本身是有价值的结论(拥塞先杀吞吐/时延、后杀丢包)。**绝不预设 unreturned 必升**;实测 null/0 就如实记 null/0(R-10)。若要逼出丢包,可叠加 §3.5 的整形网关做尾丢档对照。
