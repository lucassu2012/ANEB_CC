## 1. dump 周期：**用公式算，不要抄那个数**（D-599／D-600）

    界(ns) = 127 × 「该批 sf_latency.txt 首行的那个数」
    要求：dump 周期(换算成 ns) < 界(ns)

**照做三步，全程不需要你做任何判断**（口径由大脑 2026-08-30 夜裁定为此，**不换算赫兹、不舍入**）：

1. 打开该批 `sf_latency.txt`，**看第一行**——它是一个纯数字（刷新周期，单位 ns）；
2. **乘 127**，得到界（ns）；
3. 把你要用的 `--framestats-period-s` **乘 10 的 9 次方**换成 ns，**必须小于界**。

**本批实测的样子**（十格 ＋ 四个作废格，**十四个目录首行全是同一个数**，我逐个查过）：

    首行 16666666  →  界 = 127 × 16666666 = 2,116,666,582 ns ≈ 2.117 s
    period 1s = 1,000,000,000 ns  <  界   ✅ 通过，余量约一半

- **环深 ＝ 127 帧**（`dumpsys SurfaceFlinger --latency` 恒返回 127 行，实测十四个目录无例外）；
- **⚠ 不许拿设备铭牌率代入**——必须读该批实测首行（60Hz 与 90Hz 给出的界差 1.5 倍）；
- **⚠ fail-closed 守卫**：**若首行不是纯数字**（空文件／报错输出／换了设备），**停下，不要猜刷新率**。
  「读不到」与「读到了一个正常值」在下游长得一样，而这条公式整个吊在这一个数上。

**为什么这条值得占一整节**：周期 20s 时，相邻两次 dump **要么完全相同、要么完全不相交**，
几乎没有中间态（实测 `cell_f2` 30 对：相同 14／重叠 4／不相交 12；`wifi_f1`、`cell_f1` 的重叠**恰好为 0**）。
不相交那些之间的帧**永远丢了**，而**丢帧与思考静默在去重后的序列里长得一模一样**。
⇒ **周期 ≤ 界之后，环装得下、必然重叠，「环之间有洞」和「一轮只拿到一个环」同时消失**——
**它们是同一个溢出机制的两个症状，别当成两件事去修**。

## 2. 每一格的循环

| 步 | 动作 | **⚠ 这一步的静默失败长什么样** |
|---|---|---|
| 1 | **先把被测 App 切到前台并让它出一屏画面**，**再**起采集命令 | 顺序反了 ⇒ 通道 C 零帧。历史 9 跑有 7 次栽在这 |
| 2 | 起采集器 | — |
| 2a | **判 `frames`，不是判文件在不在** | `frames=0` ＝ 通道 C 已死，**立刻停掉重来**，别带着死掉的 C 跑满全格 |
| 2b | **绝对不要用行数判帧数** | 这些文件行尾是 **CR CR LF**，通用换行会把它译成两个换行 ⇒ 行数约两倍 |
| 3 | 每轮：新对话 → 输入（**该功能的固定提示词，逐字相同**）→ 发送 → **固定答窗** → 标记 → **静置期** | — |
| 4 | **逐轮把答窗与静置的「实际值」落盘**（不是意图值） | **常量写 17.4 而轮询粒度 1.0s ⇒ 实际跑出 18.2**。一个精确的常量被一个粗的循环悄悄改掉，**而锚格正靠它可比** |
| 5 | **收工 ＝ 采集器进程已退出**，不是「你跑完 N 轮」 | 采集器按 4096 字节块读管道，最后一条标记卡在里面。**误判会让你白白作废一个好格** |

**负载选型（§1b 实证）**：**自带长静默的功能天然更适合 e2**——只要那段静默 **> 单环覆盖（≈4.3s）**，
它就跨得过 dump 空洞。F6 的 8.9–9.7s 是约 2 倍余量，是全批 C 侧最干净的两格。

## 5. 验收项 → **下游读者**（本节是刻意存在的：**你让他检查的那个东西，是下游真正读的那个吗**）

| 你现场数的 | **下游真正读的** | 不一致时会发生什么 |

| `screencap_index.jsonl` 有行 | `e1` 的 `screencap_sampling_stats`（硬下限 `<2` 即 `NOT_EXECUTED`） | — |
| `ttft_cluster_ms` 有值 | **该轮最长内容事件间隔是否 > 门限** | **全程小于门限 ⇒ 簇窗不闭合 ⇒ 值兜底成驱动器下一次点屏**，再可能被 `TTFT_CEILING_MS=30_000` 静默转 `null` |
